# Qiskit Code Assistant {#qiskit-code-assistant}

Die Qiskit Code Assistant LLMs sollen Quantencomputing für neue Qiskit-Nutzer zugänglicher machen und das Programmiererlebnis für bestehende Nutzer verbessern. Er wurde mit Millionen von Text-Tokens aus dem Qiskit SDK, jahrelangen Qiskit-Code-Beispielen und IBM Quantum&reg;-Funktionen trainiert. Qiskit Code Assistant kann deinen Quantum-Entwicklungsworkflow unterstützen, indem er LLM-generierte Vorschläge auf Basis von [IBM Granite und anderen Open-Source-Modellen](https://huggingface.co/Qiskit) anbietet, die die neuesten Funktionen und Features von IBM&reg; beinhalten.

<Admonition type="note" title="Hinweise">
- **Möchtest du direkt zu den Installationsanweisungen springen? Gehe zum Abschnitt [Qiskit Code Assistant installieren](#install).**
- Wenn du Feedback hast oder das Entwicklerteam kontaktieren möchtest, nutze den [Qiskit Slack Workspace-Kanal](https://qiskit.enterprise.slack.com/archives/C07LYA6PL83) oder die zugehörigen öffentlichen GitHub-Repositories.
</Admonition>

## Das Large Language Model (LLM) hinter Qiskit Code Assistant {#the-large-language-model-llm-behind-qiskit-code-assistant}

Um Code-Vorschläge bereitzustellen, verwendet Qiskit Code Assistant ein Large Language Model (LLM). Konkret basiert Qiskit Code Assistant derzeit auf dem Modell `mistral-small-3.2-24b-qiskit`, das auf dem [Mistral-Small-3.2-24B-Qiskit-Modell](https://huggingface.co/Qiskit/mistral-small-3.2-24b-qiskit) aufbaut. Das Modell `mistral-small-3.2-24b-qiskit` verbessert die Code-Generierungsfähigkeiten des Modells `Mistral-Small-3.2-24B-Instruct-2506` für Qiskit durch erweitertes Pretraining und Fine-Tuning auf hochwertigen Qiskit-Daten sowie Python-Commits und Chat. Weitere Informationen zur Mistral-AI-Modellfamilie findest du in der [Mistral-AI-Dokumentation](https://docs.mistral.ai/getting-started/models). Weitere Details zu den `.*-qiskit`-Modellen findest du unter [Qiskit Code Assistant: Training LLMs for generating Quantum Computing Code](https://arxiv.org/abs/2405.19495).

Unsere auf Qiskit spezialisierten LLMs sind auch als Open-Source-Modelle verfügbar. Alle verfügbaren Modelle findest du unter https://huggingface.co/Qiskit.

## Die Qiskit HumanEval- und Qiskit HumanEval Hard-Benchmarks {#the-qiskit-humaneval-and-qiskit-humaneval-hard-benchmarks}

Um das Modell `mistral-small-3.2-24b-qiskit` und andere Modelle zu testen, haben wir mit Qiskit Advocates und Experten zusammengearbeitet, um ausführungsbasierte Benchmarks namens Qiskit HumanEval (QHE) und Qiskit HumanEval Hard (QHE Hard) zu entwickeln und auf den Modellen auszuführen. Diese Benchmarks ähneln [HumanEval](https://arxiv.org/abs/2107.03374) und enthalten mehrere anspruchsvolle Code-Aufgaben, die alle auf den offiziellen Qiskit-Bibliotheken basieren.

Die Benchmarks bestehen aus etwa 150 Tests, von denen jeder aus einer Funktionsdefinition besteht, gefolgt von einem Docstring, der die Aufgabe beschreibt, die das Modell lösen soll. Jedes Beispiel enthält außerdem eine Referenz-Musterlösung sowie Unit-Tests zur Überprüfung der Korrektheit der generierten Lösungen. Es gibt drei Schwierigkeitsstufen für Tests: einfach, mittel und schwierig. Der Qiskit HumanEval Hard-Benchmark ist eine Variante des Qiskit HumanEval-Benchmarks, entfernt jedoch Informationen zu Code-Imports, sodass das LLM die richtigen Methoden- oder Klassen-Imports selbst herausfinden muss. Diese Änderung macht den Datensatz laut unseren Tests und ersten Ergebnissen deutlich anspruchsvoller für LLMs.

Die Datensätze für Qiskit HumanEval und Qiskit HumanEval Hard sind auf diesen Websites verfügbar: [Qiskit HumanEval](https://huggingface.co/datasets/Qiskit/qiskit_humaneval) und [Qiskit HumanEval](https://huggingface.co/datasets/Qiskit/qiskit_humaneval_hard). Du kannst zur Weiterentwicklung dieser Benchmarks im [GitHub-Repository](https://github.com/qiskit-community/qiskit-human-eval) beitragen.

## Qiskit Code Assistant installieren {#install-qiskit-code-assistant}

Erfahre, wie du eines der Qiskit Code Assistant-Modelle auf deinem lokalen Rechner installieren, konfigurieren und verwenden kannst.

<Accordion>
<AccordionItem title="Von der Hugging Face-Website herunterladen">

Folge diesen Schritten, um ein beliebiges Qiskit Code Assistant-Modell von der Hugging Face-Website herunterzuladen:

1. Navigiere zur gewünschten Qiskit-Modellseite auf Hugging Face.

2. Gehe zum Tab **Files and Versions** und lade die Safetensors- oder GGUF-Modelldateien herunter.


</AccordionItem>

<AccordionItem title="Mit der Hugging Face CLI herunterladen">

Um eines der verfügbaren Qiskit Code Assistant-Modelle mit der Hugging Face CLI herunterzuladen, folge diesen Schritten:

1. Installiere die [Hugging Face CLI](https://huggingface.co/docs/huggingface_hub/main/en/guides/cli)

1. Melde dich bei deinem Hugging Face-Konto an


    ```
    huggingface-cli login
    ```

1. Lade das gewünschte Modell aus der obigen Liste herunter


    ```
    huggingface-cli download <HF REPO NAME> <MODEL PATH> --local-dir <LOCAL PATH>
    ```

</AccordionItem>

<AccordionItem title="Qiskit Code Assistant-Modelle lokal über Ollama manuell bereitstellen">

Es gibt mehrere Möglichkeiten, das heruntergeladene Qiskit Code Assistant-Modell bereitzustellen und damit zu interagieren. Diese Anleitung zeigt die Verwendung von [Ollama](https://ollama.com) wie folgt: entweder mit der [Ollama-Anwendung](#using-the-ollama-application) über die Hugging Face Hub-Integration oder ein lokales Modell, oder mit dem [`llama-cpp-python`-Paket](#use-llama-cpp-python).

#### Ollama-Anwendung verwenden {#using-the-ollama-application}

Die Ollama-Anwendung bietet eine einfache Lösung, um LLMs lokal auszuführen. Sie ist benutzerfreundlich und verfügt über eine CLI, die den gesamten Einrichtungsprozess, die Modellverwaltung und die Interaktion unkompliziert gestaltet. Sie eignet sich ideal für schnelle Experimente und für Nutzer, die möglichst wenig technischen Aufwand betreiben möchten.

##### Ollama installieren {#install-ollama}

1. Lade die [Ollama-Anwendung](https://ollama.com/download) herunter

1. Installiere die heruntergeladene Datei

1. Starte die installierte Ollama-Anwendung


    <Admonition type="info">
        Die Anwendung läuft erfolgreich, wenn das Ollama-Symbol in der Menüleiste des Desktops erscheint. Du kannst auch überprüfen, ob der Dienst läuft, indem du `http://localhost:11434/` aufrufst.
    </Admonition>

1. Probiere Ollama in deinem Terminal aus und starte Modelle. Beispiel:


    ```
    ollama run hf.co/Qiskit/Qwen2.5-Coder-14B-Qiskit
    ```

##### Ollama mit der Hugging Face Hub-Integration einrichten {#set-up-ollama-using-the-hugging-face-hub-integration}

Die [Ollama/Hugging Face Hub-Integration](https://huggingface.co/docs/hub/ollama) ermöglicht die Interaktion mit auf dem Hugging Face Hub gehosteten Modellen, ohne eine neue Modelfile erstellen oder die GGUF- oder Safetensors-Dateien manuell herunterladen zu müssen. Die Standard-`template`- und `params`-Dateien sind bereits für das Modell auf dem Hugging Face Hub enthalten.

1. Stelle sicher, dass die Ollama-Anwendung läuft.


1. Gehe zur gewünschten Modellseite und kopiere die URL. Zum Beispiel: https://huggingface.co/Qiskit/Qwen2.5-Coder-14B-Qiskit-GGUF.


1. Führe in deinem Terminal den folgenden Befehl aus:


    ```
    ollama run hf.co/Qiskit/Qwen2.5-Coder-14B-Qiskit
    ```

Du kannst das Modell `hf.co/Qiskit/Qwen2.5-Coder-14B-Qiskit` oder eines der anderen aktuell empfohlenen offiziellen GGUF-Modelle `hf.co/Qiskit/mistral-small-3.2-24b-qiskit-GGUF` oder `hf.co/Qiskit/granite-3.3-8b-qiskit-GGUF` verwenden.

##### Ollama mit einem manuell heruntergeladenen Qiskit Code Assistant-GGUF-Modell einrichten {#set-up-ollama-with-a-manually-downloaded-qiskit-code-assistant-gguf-model}

Wenn du ein GGUF-Modell wie https://huggingface.co/Qiskit/Qwen2.5-Coder-14B-Qiskit-GGUF manuell heruntergeladen hast und mit verschiedenen Templates und Parametern experimentieren möchtest, kannst du diese Schritte ausführen, um es in deine lokale Ollama-Anwendung zu laden.

1. Erstelle eine `Modelfile` mit folgendem Inhalt und aktualisiere `<PATH-TO-GGUF-FILE>` mit dem tatsächlichen Pfad zu deinem heruntergeladenen Modell.


    ```
    FROM <PATH-TO-GGUF-FILE>
    TEMPLATE """{{ if .System }}
    System:
    {{ .System }}

    {{ end }}{{ if .Prompt }}Question:
    {{ .Prompt }}

    {{ end }}Answer:
    ```python{{ .Response }}
    """

    PARAMETER stop "Question:"
    PARAMETER stop "Answer:"
    PARAMETER stop "System:"
    PARAMETER stop "```"

    PARAMETER temperature 0
    PARAMETER top_k 1

    ```

1. Führe den folgenden Befehl aus, um eine benutzerdefinierte Modellinstanz basierend auf der `Modelfile` zu erstellen.


    ```
    ollama create Qwen2.5-Coder-14B-Qiskit -f ./path-to-model-file

    ```

    <Admonition type="note">
        Dieser Vorgang kann einige Zeit dauern, da Ollama die Modelldatei einlesen, die Modellinstanz initialisieren und entsprechend den angegebenen Spezifikationen konfigurieren muss.
    </Admonition>

##### Das manuell in Ollama heruntergeladene Qiskit Code Assistant-Modell ausführen

Nachdem das Modell `Qwen2.5-Coder-14B-Qiskit` in Ollama eingerichtet wurde, führe den folgenden Befehl aus, um das Modell zu starten und im Terminal damit zu interagieren (im Chat-Modus).

```
ollama run Qwen2.5-Coder-14B-Qiskit

```

Einige nützliche Befehle:

- `ollama list` - Modelle auf deinem Computer auflisten

- `ollama rm Qwen2.5-Coder-14B-Qiskit` - Das Modell löschen

- `ollama show Qwen2.5-Coder-14B-Qiskit` - Modellinformationen anzeigen

- `ollama stop Qwen2.5-Coder-14B-Qiskit` - Ein aktuell laufendes Modell stoppen

- `ollama ps` - Anzeigen, welche Modelle aktuell geladen sind


</AccordionItem>

<AccordionItem title="Die Qiskit Code Assistant-Modelle lokal über das `llama-cpp-python`-Paket manuell bereitstellen">

<span id="use-llama-cpp-python"></span>
An alternative to the Ollama application is the `llama-cpp-python` package, which is a Python binding for `llama.cpp`. It gives you more control and flexibility to run the GGUF model locally, and is ideal for users who wish to integrate the local model in their workflows and Python applications.

1. Installiere [`llama-cpp-python`](https://pypi.org/project/llama-cpp-python/)

2. Interagiere mit dem Modell innerhalb deiner Anwendung mithilfe von `llama_cpp`. Zum Beispiel:


```python
from llama_cpp import Llama

model_path = <PATH-TO-GGUF-FILE>

model = Llama(
        model_path,
        seed=17,
        n_ctx=10000,
        n_gpu_layers=37, # to offload in gpu, but put 0 if all in cpu
    )

input = 'Generate a quantum circuit with 2 qubits'
raw_pred = model(input)["choices"][0]["text"]

```

Du kannst dem Modell auch Textgenerierungsparameter hinzufügen, um die Inferenz anzupassen:

```python
generation_kwargs = {
        "max_tokens": 512,
        "echo": False, # Echo the prompt in the output
        "top_k": 1
    }

raw_pred = model(input, **generation_kwargs)["choices"][0]["text"]

```

</AccordionItem>

<AccordionItem title="Die Qiskit Code Assistant-Modelle lokal über llama.cpp manuell bereitstellen">
#### Die `llama.cpp`-Bibliothek verwenden

Eine weitere Alternative ist die Verwendung von `llama.cpp`, einer Open-Source-Bibliothek zur Durchführung von LLM-Inferenz auf einer CPU mit minimalem Setup.
Sie bietet Low-Level-Kontrolle über die Modellausführung und wird üblicherweise über die Kommandozeile ausgeführt, wobei auf eine lokale GGUF-Modelldatei verwiesen wird.

Es gibt mehrere Möglichkeiten, `llama.cpp` auf deinem Rechner zu installieren:

- Installiere llama.cpp mit [brew, nix oder winget](https://github.com/ggml-org/llama.cpp/blob/master/docs/install.md)

- Mit Docker ausführen: Sieh dir die [Docker-Dokumentation des `llama.cpp`-Teams](https://github.com/ggml-org/llama.cpp/blob/master/docs/docker.md) an

- Lade vorgefertigte Binärdateien von der [Releases-Seite](https://github.com/ggml-org/llama.cpp/releases) herunter

- Baue aus dem Quellcode, indem du [dieses Repository klonst](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md)


Nach der Installation kannst du `llama.cpp` wie folgt verwenden, um im Konversationsmodus mit GGUF-Modellen zu interagieren:
```bash

# Use a local model file {#use-a-local-model-file}
llama-cli -m my_model.gguf -cnv

# Or download and run a model directly from Hugging Face {#or-download-and-run-a-model-directly-from-hugging-face}
llama-cli -hf Qiskit/Qwen2.5-Coder-14B-Qiskit-GGUF -cnv

```

Du kannst außerdem auf folgende Weise einen OpenAI-kompatiblen API-Server für das Modell starten:
```bash
llama-server -hf Qiskit/Qwen2.5-Coder-14B-Qiskit-GGUF

```

##### Erweiterte Parameter
Mit dem Programm `llama-cli` kannst du die Modellgenerierung über Kommandozeilenoptionen steuern. Du kannst beispielsweise mit dem Flag `-p/--prompt` einen anfänglichen „System“-Prompt angeben. Im Konversationsmodus (`-cnv`) fungiert dieser anfängliche Prompt als Systemnachricht. Andernfalls kannst du deinem Prompt-Text einfach eine beliebige gewünschte Anweisung voranstellen. Du kannst auch Sampling-Parameter anpassen – zum Beispiel: Temperatur (`--temp`), Top-k (`--top-k`), Top-p (`--top-p`), Repetition Penalty (`--repeat-penalty`) und den zu verwendenden Seed (`--seed`). Im Folgenden findest du einen Beispielaufruf mit diesen Optionen:

```bash
llama-cli -hf Qiskit/Qwen2.5-Coder-14B-Qiskit-GGUF \
  -p "You are a friendly assistant." -cnv \
  --temp 0.7 \
  --top-k 50 \
  --top-p 0.95 \
  --repeat-penalty 1.1 \
  --seed 42

```

Um die einwandfreie Funktionalität unserer Qiskit-Modelle sicherzustellen, empfehlen wir die Verwendung des in unseren HF-GGUF-Repositories bereitgestellten System-Prompts: System-Prompt für [mistral-small-3.2-24b-qiskit-GGUF](https://huggingface.co/Qiskit/mistral-small-3.2-24b-qiskit-GGUF/blob/main/system), [Qwen2.5-Coder-14B-Qiskit-GGUF](https://huggingface.co/Qiskit/Qwen2.5-Coder-14B-Qiskit-GGUF/blob/main/system), [granite-3.3-8b-qiskit-GGUF](https://huggingface.co/Qiskit/granite-3.3-8b-qiskit-GGUF/blob/main/system) und [granite-3.2-8b-qiskit-GGUF](https://huggingface.co/Qiskit/granite-3.2-8b-qiskit-GGUF/blob/main/system).

</AccordionItem>

<AccordionItem title="Continue (VS Code) manuell verbinden">

#### [Continue](https://marketplace.visualstudio.com/items?itemName=Continue.continue) (VS Code)

##### 1. Installiere die Erweiterung

Öffne VS Code, gehe zu Extensions (`Cmd+Shift+X`), suche nach **Continue** und installiere es.

##### 2. Öffne die Konfiguration

Klicke auf das Continue-Symbol in der Seitenleiste, dann auf das Zahnrad-Symbol, oder öffne die Command Palette (`Cmd+Shift+P`) und führe **Continue: Open Config File** aus.

Dies öffnet `~/.continue/config.yaml` (oder `config.json` in älteren Versionen).

##### 3. Konfiguriere das Modell

Füge Folgendes zu `config.yaml` hinzu:

```yaml
models:
  - name: Qiskit Code Assistant
    provider: ollama
    model: mistral-small-3.2-24b-qiskit
    apiBase: http://localhost:11434

```

Dadurch wird das Qiskit-Modell im **Chat-Panel** (Konversationen in der Seitenleiste, Inline-Q&A) und für **Inline-Edit**-Befehle verfügbar.

##### 4. Teste es

- **Chat:** Öffne das Continue-Panel in der Seitenleiste und stelle eine Frage (z. B. „Wie erstelle ich einen parametrisierten Circuit in Qiskit?“)

- **Inline Edit:** Wähle einen Codeblock aus und drücke `Cmd+I` (Mac) oder `Ctrl+I` (Linux/Windows)

  
  
  
  
  
</AccordionItem>

<AccordionItem title="Jupyter AI (JupyterLab) manuell verbinden">

#### [Jupyter AI](https://jupyter-ai.readthedocs.io/en/v3/index.html) (JupyterLab)

**Hinweis:** Diese Anleitung behandelt Jupyter AI v2.x.

##### 1. Installiere Jupyter AI und den Ollama-Provider

```bash
pip install "jupyter-ai<3" langchain-ollama

```

Die Fixierung `"jupyter-ai<3"` stellt sicher, dass du v2.x erhältst. Das Paket `langchain-ollama` wird benötigt, damit Jupyter AI Ollama als Provider erkennt. Ohne dieses Paket erscheint Ollama nicht im Einstellungsfenster.

Starte anschließend JupyterLab neu.

##### 2. Konfiguriere das Chat-Modell

Öffne JupyterLab und klicke auf das **Chat-Symbol** in der linken Seitenleiste. Im Einstellungsfenster:

1. Wähle unter **Language model** **Ollama** als Provider aus.

2. Gib `mistral-small-3.2-24b-qiskit` als Modellnamen ein.

3. Für Ollama wird kein API-Schlüssel benötigt (lasse das Feld leer).

4. Klicke auf den Zurück-Pfeil, um mit dem Chatten zu beginnen.


##### 3. Verwende den Magic-Befehl `%%ai`

Mit dem Magic-Befehl `%%ai` kannst du das Modell direkt in Notebook-Zellen abfragen.

```python
%load_ext jupyter_ai_magics

```

Dann in einer Zelle:

```python
%%ai ollama:mistral-small-3.2-24b-qiskit
Write a function that implements Grover's algorithm using Qiskit

```

##### 4. Benutzerdefinierter Ollama-Host (optional)

Standardmäßig verbindet sich Jupyter AI mit `http://127.0.0.1:11434`. Wenn dein Ollama-Server unter einer anderen Adresse oder einem anderen Port läuft:

**In der Chat-Oberfläche:** Setze das Feld „Base API URL“ im KI-Einstellungsfenster.
