# Qiskit SDK v2.3 {#qiskit-sdk-v23}

## Januar 2026 {#january-2026}
- Aufbauend auf der Dynamik der v2.x-Reihe, die sich darauf konzentriert hat, Qiskit als führende Plattform für hybride Quanten-HPC-Workflows zu positionieren, bringt [Qiskit SDK v2.3](https://www.ibm.com/quantum/blog/qiskit-2-3-release-summary) eine deutliche Erweiterung der C API sowie schnellere, flexiblere Tools zum Erstellen und Optimieren von Quantenschaltkreisen.


  Zu den wichtigsten Updates gehören:

  - **Benutzerdefinierte Transpiler-Passes in C** – Schreibe benutzerdefinierte Transpiler-Passes über die C API von Qiskit mithilfe des neuen `QkDag`-Objekts und eines erweiterten `QkTarget`-Objekts, die eine schrittweise Prüfung, Änderung und Erweiterung des Kompilierungsprozesses ermöglichen – ohne die gesamte Compiler-Pipeline neu aufzubauen.


  - **Schnellere Hardware-Layout-Auswahl** – Upgrades und Rust-gestützte Performance-Verbesserungen an `VF2Layout` und `VF2PostLayout` erhöhen die Geschwindigkeit und Skalierbarkeit der Zuordnung von Schaltkreisen zum Hardware-Layout, reduzieren den Kompilierungs-Overhead und verbessern die Fidelity auf Quantenhardware.


  - **Neue Multi-Qubit-Pauli-Messung** – Die neue `PauliProductMeasurement`-Instruktion ermöglicht eine gemeinsame projektive Messung über mehrere Qubits in einer einzigen Operation und erschließt die Kompilierung für Pauli-basiertes Computing – eine gängige Darstellung im fehlertoleranten Quantencomputing.


  - **Verbesserungen bei der frühen fehlertoleranten Transpilation** – Performance- und Funktionsverbesserungen für die Transpilation zu frühen fehlertoleranten Zielen – insbesondere Clifford+T-Ziele – helfen Nutzern, Transpilations-Pipelines für zukünftige QPUs effizienter aufzubauen.


  Diese Fähigkeiten geben Entwicklern mehr Flexibilität, um Optimierungen von Quantenschaltkreisen anzupassen und in bestehende HPC-Workflows zu integrieren. [Besuche den Blog](https://www.ibm.com/quantum/blog/qiskit-2-3-release-summary) für die vollständige technische Zusammenfassung.

Du fragst dich, was sich geändert hat? Lies den [Changelog](https://github.com/Qiskit/qiskit/releases/tag/2.3.0) und die [Release Notes zu v2.3](https://docs.quantum.ibm.com/api/qiskit/release-notes/2.3).

## April 2026 {#april-2026}

<span id="executor-primitive"></span>
- **Introducing the Executor primitive**: We're excited to announce the release of the new `Executor` primitive and a new version of the noise-learning helper class, `NoiseLearnerV3`, both of which were first previewed at QDC 2025.

  Zusammen mit [Samplomatic](https://qiskit.github.io/samplomatic/index.html) bilden sie das [Directed Execution Model](/guides/directed-execution-model), das vollständige Transparenz und Kontrolle bietet, um deinen Fehlerminderungs-Workflow feinabzustimmen. Das Tutorial [Probabilistic error cancellation with shaded lightcones](https://qiskit.github.io/qiskit-addon-slc/tutorials/01_getting_started.html) zeigt beispielsweise, wie dieses Modell verwendet wird, um fortschrittliche Techniken zu kombinieren, darunter Shaded Lightcones, Probabilistic Error Cancellation (PEC), Twirled Readout Error eXtinction (TREX) und [messbasierte Postselektion](/guides/post-selection), um die Ergebnisqualität weiter zu verbessern.

  Wenn du eine höhere Abstraktionsebene bevorzugst, bietet [`EstimatorV2`](/guides/estimator-noise-management) in Qiskit Runtime weiterhin mehrere integrierte Techniken zur Fehlerminderung und -unterdrückung, die du mit der Option [`resilience_level`](/guides/estimator-noise-management#resilience-level) einfach anpassen kannst.

  Weitere Informationen findest du in den folgenden Guides:

    - [Schnelleinstieg in Executor](/guides/get-started-with-executor)

    - [Noise-Learning-Helper](/guides/noise-learning)


  Beide neuen Funktionen befinden sich derzeit in der Beta-Phase und erfordern `qiskit-ibm-runtime` in Version 0.47.0 oder höher.
