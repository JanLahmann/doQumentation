# Von `BackendV1` zu `BackendV2` migrieren {#migrate-from-backendv1-to-backendv2}

Die Qiskit-Klasse [`BackendV1`](https://docs.quantum.ibm.com/api/qiskit/1.4/qiskit.providers.BackendV1) wurde als veraltet markiert und wird aus dem Dienst entfernt. Dieser Migrationsleitfaden beschreibt die kleinen Anpassungen, die du vornehmen musst, wenn du einen Anbieter verwendest, der von [`BackendV1`](https://docs.quantum.ibm.com/api/qiskit/1.4/qiskit.providers.BackendV1) auf [`BackendV2`](https://docs.quantum.ibm.com/api/qiskit/qiskit.providers.BackendV2) umgestellt hat.

<Admonition type="note">
 Wenn du ausschließlich `qiskit_ibm_runtime` und `qiskit_aer` verwendest, ist keine Aktion erforderlich. Das Paket `qiskit_ibm_runtime` verwendet stets `BackendV2`, und `qiskit_aer` nutzt `BackendV2` seit Version 0.13.
 </Admonition>

## Übergeordnete Änderungen in `BackendV2` {#high-level-changes-in-backendv2}

Das Qiskit-[`Backend`](https://docs.quantum.ibm.com/api/qiskit/qiskit.providers.Backend)-Modell wurde entwickelt, um dem Qiskit SDK eine
Abstraktionsschicht bereitzustellen, die das Arbeiten mit Quantencomputern im Rahmen des SDK ermöglicht. Die erste Iteration des Modells wurde mit der
Klasse [`BackendV1`](https://docs.quantum.ibm.com/api/qiskit/1.4/qiskit.providers.BackendV1) eingeführt. Diese Klasse speicherte die Backend-Informationen in einer Reihe
von Datencontainern, nämlich den Klassen [`BackendConfiguration`](https://docs.quantum.ibm.com/api/qiskit/1.4/qiskit.providers.models.BackendConfiguration) und
[`BackendProperties`](https://docs.quantum.ibm.com/api/qiskit/1.4/qiskit.providers.models.BackendProperties).

Die Klasse [`BackendV2`](https://docs.quantum.ibm.com/api/qiskit/qiskit.providers.BackendV2) hat den
Benutzerzugriff auf die meisten Backend-Eigenschaften neu definiert, damit sie mit nativen Qiskit-Datenstrukturen funktionieren und flachere
Zugriffsmuster aufweisen. Der Kern des [`BackendV2`](https://docs.quantum.ibm.com/api/qiskit/qiskit.providers.BackendV2)-Modells ist die
Klasse [`Target`](https://docs.quantum.ibm.com/api/qiskit/qiskit.transpiler.Target), eine Darstellung des QPU, die die Transpilationsbeschränkungen enthält, die Qiskit zur Optimierung von Schaltkreisen für die Ausführung verwenden kann.

Das Qiskit SDK wurde aktualisiert, um ausschließlich mit [`BackendV2`](https://docs.quantum.ibm.com/api/qiskit/qiskit.providers.BackendV2)-Eingaben zu arbeiten,
und die meisten Anbieter haben von [`BackendV1`](https://docs.quantum.ibm.com/api/qiskit/1.4/qiskit.providers.BackendV1) auf [`BackendV2`](https://docs.quantum.ibm.com/api/qiskit/qiskit.providers.BackendV2) umgestellt. Es wird erwartet, dass bestehende Anbieter den alten Zugriff, wo möglich, als veraltet markieren, um eine schrittweise Migration zu ermöglichen, aber letztendlich müssen Nutzer ihren Code anpassen.

Das Prinzip hinter [`BackendV2`](https://docs.quantum.ibm.com/api/qiskit/qiskit.providers.BackendV2) ist,
dass die meisten Informationen über ein Backend in seinem
[`Target`](https://docs.quantum.ibm.com/api/qiskit/qiskit.transpiler.Target)-Objekt enthalten sind und die Attribute des Backends häufig das
Attribut `BackendV2.target` abfragen, um Informationen zurückzugeben. In vielen Fällen liefern die Attribute jedoch nur
eine Teilmenge der Informationen, die das Target enthalten kann. Beispielsweise gibt `backend.coupling_map`
eine [`CouplingMap`](https://docs.quantum.ibm.com/api/qiskit/qiskit.transpiler.CouplingMap) zurück, die aus dem
[`Target`](https://docs.quantum.ibm.com/api/qiskit/qiskit.transpiler.Target) konstruiert wurde, der über das Attribut
`BackendV2.target` zugänglich ist. Das Target kann jedoch
Anweisungen enthalten, die auf mehr als zwei Qubits wirken (was in einer
[`CouplingMap`](https://docs.quantum.ibm.com/api/qiskit/qiskit.transpiler.CouplingMap) nicht dargestellt werden kann), oder Anweisungen, die nur auf
einer Teilmenge von Qubits (oder Zwei-Qubit-Verbindungen, bei einer Zwei-Qubit-Anweisung) wirken, die
in der vollständigen Coupling-Map, die von
`BackendV2.coupling_map` zurückgegeben wird, nicht im Detail aufgeführt sind. Je nach Anwendungsfall
kann es daher notwendig sein, tiefer zu schauen als nur der äquivalente Zugriff mit
[`BackendV2`](https://docs.quantum.ibm.com/api/qiskit/qiskit.providers.BackendV2).

## Spezifische Änderungen in `BackendV2` {#specific-changes-in-backendv2}

Die meisten Attribute haben einen direkten Ersatz, was die Migrationsarbeit vereinfacht. Der einzige Unterschied zwischen den Schnittstellen liegt in der [`CouplingMap`](https://docs.quantum.ibm.com/api/qiskit/qiskit.transpiler.CouplingMap).

Im Folgenden findest du eine Tabelle mit Beispiel-Zugriffsmustern in [`BackendV1`](https://docs.quantum.ibm.com/api/qiskit/1.4/qiskit.providers.BackendV1) und der neuen Form
mit [`BackendV2`](https://docs.quantum.ibm.com/api/qiskit/qiskit.providers.BackendV2).
