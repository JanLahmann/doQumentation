# Встановлення Qiskit C API {#install-the-qiskit-c-api}

Цей посібник описує, як встановити та використовувати Qiskit C API. Після завершення встановлення прочитай [Розширення Python за допомогою Qiskit C API](/guides/c-extension-for-python).

Наступний приклад будує спостережувану величину (observable) на C:

```c
// file: example.c
#include <stdio.h>
#include <stdint.h>
#include <qiskit.h>

int main(int argc, char *argv[]) {
    // build a 100-qubit empty observable
    uint32_t num_qubits = 100;
    QkObs *obs = qk_obs_zero(num_qubits);

    // add the term 2 * (X0 Y1 Z2) to the observable
    QkComplex64 coeff = {2, 0};
    QkBitTerm bit_terms[3] = {QkBitTerm_X, QkBitTerm_Y, QkBitTerm_Z}; 
    // bit terms: X Y Z
    uint32_t indices[3] = {0, 1, 2};  // indices: 0 1 2
    QkObsTerm term = {coeff, 3, bit_terms, indices, num_qubits};
    qk_obs_add_term(obs, &term);  // append the term

    // print some properties and the observable itself
    printf("num_qubits: %i\n", qk_obs_num_qubits(obs));
    printf("num_terms: %lu\n", qk_obs_num_terms(obs));
    printf("observable: %s\n", qk_obs_str(obs));

    // free the memory allocated for the observable
    qk_obs_free(obs);

    return 0;
}
```

## UNIX-подібні системи {#unix-like}

Цей розділ містить інструкції зі збірки для UNIX-подібних систем.

### Вимоги {#requirements}

Компіляція вимагає наступних інструментів:
* Компілятор Rust: дивись, наприклад, [посібник зі встановлення Qiskit із вихідного коду](/guides/install-qiskit-source)
* Компілятор C: наприклад, GCC на Linux або Clang на MacOS. C API Qiskit сумісний із компіляторами, що відповідають стандарту [C11](https://en.wikipedia.org/wiki/C11_(C_standard_revision)).
* [`cbindgen`](https://github.com/mozilla/cbindgen): інструмент для генерації заголовкового файлу C — встановлюється командою `cargo install cbindgen`
   Запуск інструменту з командного рядка має бути увімкнений, що може вимагати додання `/path/to/.cargo/bin` до змінної середовища `PATH`.
* Встановлена бібліотека Python (Python 3.9+): бібліотека Python потрібна під час динамічного компонування. Зверни увагу, що Python не використовується під час виконання і інтерпретатор ніколи не ініціалізується — лише деякі символи з `libpython` мають бути визначені. Дивись [це issue](https://github.com/Qiskit/qiskit/issues/14240) для деталей.
* (GNU) Make: необов'язковий, але рекомендований інструмент для автоматизації процесу встановлення.

Ці команди перевіряють, що все встановлено правильно:

```bash
rustc --version
gcc --version
cbindgen --version
make --version  # optional, but recommended
```

### Збірка {#build}

Щоб зібрати заголовковий файл C і бібліотеку, виконай таку команду Make[^1] у кореневій директорії Qiskit:
[^1]: Якщо Make не встановлено, перевір `Makefile` у кореневій директорії Qiskit, щоб дізнатися про потрібні команди — або просто встанови Make; ще не пізно.

```bash
make c
```
Ця команда помістить скомпільовану спільну бібліотеку у `dist/c/lib`, а заголовковий файл `qiskit.h` із усіма оголошеннями функцій — у `dist/c/include`. Зверни увагу, що точна назва бібліотеки залежить від платформи: наприклад, `libqiskit.so` на UNIX і `libqiskit.dylib` на MacOS.
(Зверни увагу, що на цьому кроці наразі виводиться багато попереджень — це очікувана поведінка і не є приводом для занепокоєння. У наступних версіях їх буде усунено.)

Після цього можна скомпілювати програму на C, використовуючи заголовковий файл і бібліотеку Qiskit:

```bash
gcc example.c -o example.o -I /path/to/dist/c/include -L /path/to/dist/c/lib -lqiskit
```
Щоб бібліотека Qiskit знаходилась під час компонування, додай `/path/to/dist/c/lib` до шляху бібліотек виконання. Якщо бібліотека Python не доступна за замовчуванням під час динамічного компонування, її також потрібно додати. Ці команди залежать від платформи. На Linux:

```bash
export LD_LIBRARY_PATH=/path/to/dist/c/lib:$LD_LIBRARY_PATH
# On Linux, the Python library is typically included 
# in the dynamic library path by default.
export LD_LIBRARY_PATH=/path/to/python/lib:$LD_LIBRARY_PATH
```
На MacOS:

```bash
export DYLD_LIBRARY_PATH=/path/to/dist/c/lib:$DYLD_LIBRARY_PATH
export DYLD_LIBRARY_PATH=/path/to/python/lib:$DYLD_LIBRARY_PATH
```
Як альтернативу, можна вказати шлях бібліотек виконання безпосередньо під час компіляції, додавши

```
-Wl,-rpath,/path/to/dist/c/lib
# same for Python
```
до прапорців компілятора.
Крім того, бібліотека Python має бути доступна під час динамічного компонування. У Linux-середовищах це, як правило, стандартна поведінка.

Тепер можна запустити бінарний файл:

```bash
./example.o
```
Якщо використовувати наведений вище приклад коду, це має вивести:

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```

## Windows {#windows}

Цей розділ містить інструкції зі збірки для систем Windows.

Існує два незалежних способи використання C API у Windows:

* **Створюй модулі розширень Python**, що використовують Qiskit C API. Виконай кроки 1-5. Цей шлях використовує заголовки C, які постачаються з пакетом Python `qiskit`, і не потребує Rust або cbindgen.

* **Створи автономну бібліотеку C** для компонування з чистою програмою на C, як це зроблено в розділі [UNIX-like](#unix). Виконай крок 1, а потім перейди до [Build the standalone library](#build-the-standalone-library), де перелічені додаткові вимоги.


### Вимоги {#requirements-1}

- Для деяких кроків потрібні права адміністратора.

- 5-8 ГБ вільного місця на диску.

- Компілятор C: Microsoft Visual C++ (MSVC), встановлений на кроці 1.

- 64-бітна інсталяція Python (3.10 або новіша), встановлена на кроці 1.

### Крок 3 - Завантаження середовища MSVC {#step-3-load-the-msvc-environment}

Виконуй наступний код у кожній новій сесії Python (наприклад, кожного разу, коли перезапускаєш ядро Jupyter). Він автоматично знаходить і завантажує середовище розробника MSVC, тому тобі не потрібне вбудоване командне вікно x64.

Приклад у цій документації створює C-розширення за допомогою `setuptools` з MSVC. Загалом, потрібно визначити `QISKIT_PYTHON_EXTENSION`, підключити `qiskit.h` і викликати `qk_import()` у своїй функції ініціалізації. Під час збірки потрібні лише заголовки з `qiskit.capi.get_include()` — жодна бібліотека не лінкується. Дивись [Extend Qiskit in Python with C](/guides/c-extension-for-python) для деталей.

<Accordion>
  <AccordionItem title="Завантаж середовище MSVC">

```python
import os, sys, subprocess, glob, shutil

def load_msvc_env():
    if os.name != "nt":
        return "Not Windows — the system C compiler is used as-is."
    if shutil.which("cl"):
        return "cl.exe is already available in this kernel."

    pf86 = os.environ.get("ProgramFiles(x86)", r"C:\Program Files (x86)")
    pf = os.environ.get("ProgramFiles", r"C:\Program Files")
    vcvars = None

    vswhere = os.path.join(pf86, "Microsoft Visual Studio", "Installer", "vswhere.exe")
    if os.path.isfile(vswhere):
        # vswhere outputs UTF-8 regardless of system locale
        inst = subprocess.run(
            [vswhere, "-latest", "-products", "*",
             "-requires", "Microsoft.VisualStudio.Component.VC.Tools.x86.x64",
             "-property", "installationPath"],
            capture_output=True, text=True, encoding="utf-8").stdout.strip()
        if inst:
            cand = os.path.join(inst, "VC", "Auxiliary", "Build", "vcvars64.bat")
            if os.path.isfile(cand):
                vcvars = cand

    if not vcvars:
        pat = os.path.join("Microsoft Visual Studio", "*", "*",
                           "VC", "Auxiliary", "Build", "vcvars64.bat")
        hits = glob.glob(os.path.join(pf86, pat)) + glob.glob(os.path.join(pf, pat))
        if hits:
            vcvars = sorted(hits)[-1]

    if not vcvars:
        return ("Could not find vcvars64.bat. Install MSVC Build Tools (Step 1.3), "
                "or launch Jupyter from the x64 Native Tools Command Prompt.")

    # cmd.exe outputs in the OEM codepage (cp437/cp850/etc.), not the ANSI codepage
    out = subprocess.run(f'"{vcvars}" >nul 2>&1 && set',
                         capture_output=True, text=True, encoding="oem", shell=True).stdout
    for line in out.splitlines():
        if "=" in line:
            k, _, v = line.partition("=")
            os.environ[k] = v

    return ("Loaded MSVC from:\n  " + vcvars) if shutil.which("cl") \
        else "Ran vcvars64.bat but cl.exe is still not found — check your MSVC install."

print(load_msvc_env())
print("cl.exe on PATH:", shutil.which("cl") is not None)
```
</AccordionItem>

```python
    "setuptools": importlib.util.find_spec("setuptools") is not None,
    "wheel":      importlib.util.find_spec("wheel") is not None,
    "cl.exe":     shutil.which("cl") is not None,
}
for name, ok in checks.items():
    print(f"  [{'PASS' if ok else 'FAIL':>4}] {name}")

if not checks["cl.exe"]:
    print("\n  cl.exe is not on PATH. rerun the cell above to load the MSVC environment.")
elif all(checks.values()):
    print("\n  Toolchain ready. Continue to the smoke test.")
```
</AccordionItem>
</Accordion>

### Крок 4 - Smoke-тест: Побудова C-розширення {#step-4-smoke-test-build-a-c-extension}

Виконай наведений нижче код. Він записує вихідні файли в `_smoke_pkg/`, будує C-розширення проти Qiskit C API і імпортує результат. Якщо виводиться "SMOKE TEST PASSED", твій набір інструментів готовий.

Пакет слідує процесу [Extend Qiskit in Python with C](/guides/c-extension-for-python) і використовує функції з [Qiskit C API reference](https://docs.quantum.ibm.com/api/qiskit-c).

<Accordion>
  <AccordionItem title="Код smoke-тесту">

```python
import sys, subprocess, pathlib, importlib

root = pathlib.Path("_smoke_pkg")
pkg = root / "src" / "qgss_smoke"
pkg.mkdir(parents=True, exist_ok=True)

(root / "pyworkspace.toml").write_text("""
[build-system]
requires = ["setuptools", "qiskit>=2.4.2"]
build-backend = "setuptools.build_meta"

[workspace]
name = "qgss_smoke"
version = "0.0.1"
dependencies = ["qiskit>=2.4.2"]

[tool.setuptools]
package-dir = {"" = "src"}
""".lstrip())

(root / "setup.py").write_text("""
import qiskit
from setuptools import setup, Extension

core_ext = Extension(
    name="qgss_smoke._core",
    sources=["src/qgss_smoke/_coremodule.c"],
    include_dirs=[qiskit.capi.get_include()],
)
setup(ext_modules=[core_ext])
""".lstrip())

(pkg / "__init__.py").write_text("from . import _core\nbuild_demo = _core.build_demo\n")

(pkg / "_coremodule.c").write_text("""
#define QISKIT_PYTHON_EXTENSION
#include <Python.h>
#include <qiskit.h>
#include <stdint.h>

static PyObject *build_demo(PyObject *self, PyObject *args) {
    QkCircuit *qc = qk_circuit_new(2, 0);
    uint32_t q0[1] = {0};
    qk_circuit_gate(qc, QkGate_H, q0, NULL);
    uint32_t q1[1] = {1};
    qk_circuit_gate(qc, QkGate_X, q1, NULL);
    return qk_circuit_to_python_full(qc);
}

static PyMethodDef core_methods[] = {
    {"build_demo", build_demo, METH_NOARGS, "Build a 2-qubit demo circuit in C."},
    {NULL, NULL, 0, NULL},
};
static struct PyModuleDef core_module = {
    .m_base = PyModuleDef_HEAD_INIT,
    .m_name = "_core",
    .m_methods = core_methods,
};
PyMODINIT_FUNC PyInit__core(void) {
    if (qk_import() < 0) {
        return NULL;
    }
    return PyModuleDef_Init(&core_module);
}
""".lstrip())

# On Windows, an imported .pyd is file-locked by the OS. Drop the module from
# sys.modules BEFORE pip install --force-reinstall, otherwise pip fails with
# WinError 32 ("file in use") trying to overwrite the locked .pyd.
if "qgss_smoke._core" in sys.modules:
    del sys.modules["qgss_smoke._core"]
if "qgss_smoke" in sys.modules:
    del sys.modules["qgss_smoke"]

r = subprocess.run(
    [sys.executable, "-m", "pip", "install", "--no-build-isolation",
     "--force-reinstall", "--quiet", str(root.resolve())],
    capture_output=True, text=True,
)
if r.returncode != 0:
    output = (r.stderr + r.stdout).strip()
    print("BUILD FAILED:\n")
    print(output)
    if "WinError 32" in output or "being used by another process" in output:
        print("\n--- TIP ---")
        print("The .pyd file is locked because it was previously imported in this kernel.")
        print("Restart the kernel (Ctrl+Shift+P → 'Jupyter: Restart Kernel'), then rerun")
        print("the Step 3 MSVC cell first, then this cell again.")
    elif "cl.exe" in output.lower() or "vcvars" in output.lower() or "cannot find" in output.lower():
        print("\n--- TIP ---")
        print("The compiler was not found. rerun the Step 3 cell to load the MSVC environment.")
else:
    importlib.invalidate_caches()
    import qgss_smoke
    from qiskit import QuantumCircuit

    qc = qgss_smoke.build_demo()
    ops = dict(qc.count_ops())
    ok = isinstance(qc, QuantumCircuit) and ops.get("h") == 1 and ops.get("x") == 1

    print("Returned object is a QuantumCircuit:", isinstance(qc, QuantumCircuit))
    print("Gates built in C:", ops)
    print("\nSMOKE TEST PASSED — your Windows toolchain can build Qiskit C extensions."
          if ok else "\nSomething is off — check the gates above.")
```
</AccordionItem>
</Accordion>

### Побудова автономної бібліотеки {#build-the-standalone-library}

Цей розділ будує автономну C-бібліотеку, яка потрібна лише якщо ти хочеш компілювати й лінкувати чисті C-програми, як описано в розділі [UNIX-like](#unix). Окрім передумов Кроку 1, для цього потрібні такі інструменти:

* Компілятор Rust: дивись, наприклад, [посібник зі встановлення Qiskit з вихідного коду](https://github.com/Qiskit/qiskit/blob/main/CONTRIBUTING.md#installing-qiskit-from-source)

* [`cbindgen`](https://github.com/mozilla/cbindgen): інструмент для створення C-заголовка, який можна встановити за допомогою `cargo install cbindgen`.
    Запуск інструменту з командного рядка має бути ввімкнено, що може потребувати оновлення змінної `PATH`, щоб включити шлях до cargo.
* Встановлення Python з доступом як до ``python3.lib``, так і до ``python3.dll``
* Клон [репозиторію Qiskit](https://github.com/Qiskit/qiskit) (`git clone https://github.com/Qiskit/qiskit.git`)
<Accordion>
<AccordionItem title="Побудова автономної бібліотеки">
Спершу скомпілюй динамічну бібліотеку `qiskit_cext`, виконавши таке в терміналі VS Code (PowerShell) у корені Qiskit:

```powershell
$env:PATH = "\path\to\pythonlib;" + $env:PATH
cargo rustc --release --crate-type cdylib -p qiskit-cext
```
Це створить динамічну бібліотеку ``.dll`` та пов'язаний файл ``.dll.lib`` у `target/release`.
Далі згенеруй заголовковий файл:

```powershell
cbindgen --crate qiskit-cext --output dist\c\include\qiskit.h
```
Це запише заголовковий файл, сумісний із MSVC, у ``dist\c\include``.

Тепер можна використати `cl` для компіляції програми на C. Щоб компілятор знайшов бібліотеку qiskit,
 додай `target\release` до змінної `PATH`.

```powershell
$env:PATH = "\path\to\target\release;" + $env:PATH
cl example.c qiskit_cext.dll.lib -I\path\to\dist\c\include
```

Перед запуском потрібно вказати шлях до ``python3.dll``.

```powershell
$env:PATH = "\path\to\python3-dll;" + $env:PATH
.\example.exe
```
Після цього має вивестися:

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```
</AccordionItem>
</Accordion>

### Усунення несправностей {#troubleshooting}
<Accordion>
<AccordionItem title="`winget` не розпізнається">
Онови [App Installer](https://apps.microsoft.com/detail/9nblggh4nns1) з Microsoft Store або скористайся відповідними посиланнями для ручного завантаження
</AccordionItem>
<AccordionItem title="`cl` не розпізнається">
Перезапусти комірку завантаження MSVC (Крок 3) або скористайся x64 Native Tools Command Prompt
</AccordionItem>
<AccordionItem title="`python` відкриває Microsoft Store">
Перейди в Settings → Apps → Advanced app settings → App execution aliases і вимкни `python.exe`
</AccordionItem>
<AccordionItem title="`.ps1 cannot be loaded` / скрипти вимкнено">
Виконай `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, потім повтори спробу
</AccordionItem>
<AccordionItem title="`cannot open file 'qiskit.h'`">
Виконай `python -c "import qiskit.capi; print(qiskit.capi.get_include())"` і переконайся, що шлях існує
</AccordionItem>
<AccordionItem title="`qiskit.capi` не знайдено">
Виконай `pip install "qiskit[visualization]~=2.4.2"`
</AccordionItem>
<AccordionItem title="Збірка `qiskit-aer` не вдається">
Виконай `pip install qiskit-aer --only-binary=:all:`. Якщо це також не спрацює, використай Python 3.12 або пропусти aer, який є необов'язковим
</AccordionItem>
<AccordionItem title="Збірка проходить, але імпорт не вдається з помилкою версії">
Зібране C-розширення Qiskit і встановлена версія Qiskit повинні мати однакову версію. Перевстанови Qiskit за допомогою `pip install "qiskit~=2.4.2"`
</AccordionItem>
<AccordionItem title="Я перезібрав C, але схема не змінилася">
C-розширення не можна повторно імпортувати наживо. Перезапусти ядро, повторно виконай команди MSVC (Крок 3), потім перезбери
</AccordionItem>
<AccordionItem title="Скрипт PowerShell було заблоковано">
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
</AccordionItem>
<AccordionItem title="Помилки довжини шляху">
Використай короткий кореневий шлях на C:\ (наприклад, `C:\workspace`, або шлях, який ти вказав на етапі налаштування), або увімкни Long Paths: Settings → System → For developers → Long Paths
</AccordionItem>
<AccordionItem title="Conda активна (запрошення показує `(base)`) або збірки поводяться дивно після використання Anaconda">
Виконуй `conda deactivate`, доки `CONDA_DEFAULT_ENV` і `CONDA_PREFIX` обидва не зникнуть з середовища. Перевір за допомогою `$env:CONDA_PREFIX`. Якщо вони залишаються, відкрий новий PowerShell (не Anaconda prompt) і повтори спробу з Кроку 2.
</AccordionItem>
<AccordionItem title="Віртуальне середовище було створено з керованого conda Python (перевір рядок `home =` у `.venv\pyvenv.cfg`)">
Віртуальне середовище успадкувало середовище виконання C від conda, і це не можна виправити на місці. Видали його, завантаж Python 3.12 з сайту [Python](https://www.python.org/downloads/) і перезбери. Виконай `Remove-Item -Recurse -Force .venv`, потім повторно виконай фрагмент виявлення Python з Кроку 1, щоб встановити `$PYTHON_EXE`, а потім знову створи віртуальне середовище (Крок 2).
</AccordionItem>
<AccordionItem title="`DLL load failed` під час імпорту">
Ймовірно, conda проникає у віртуальне середовище. Перевір обидві проблеми, наведені безпосередньо вище. Також перевір, що Python 64-бітний: `python -c "import platform; print(platform.architecture())"`
</AccordionItem>
<AccordionItem title="Збірка не вдається з викривленими шляхами або `C1083`">
Ім'я твого користувача або шлях до робочого простору містить не-ASCII символи. Перенеси робочий простір на короткий шлях, що містить лише ASCII (наприклад, `C:\workspace`)
</AccordionItem>
<AccordionItem title="Збірка або імпорт випадково не вдаються, працюють при повторній спробі">
Папка робочого простору синхронізується OneDrive. Перенеси її на локальний шлях, наприклад `C:\workspace`
</AccordionItem>
<AccordionItem title="Збірка перервана на середині (наприклад, стався збій живлення)">
Видали папку `_smoke_pkg` у своєму робочому просторі, повторно виконай комірку завантаження MSVC, потім повторно виконай комірку smoke-тесту
</AccordionItem>
<AccordionItem title="`pip install` не вдається з помилкою SSL-сертифіката">
Твоя мережа використовує проксі, що перехоплює HTTPS. Спробуй виконати `pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org qiskit` або звернись до свого мережевого адміністратора за CA-сертифікатом проксі
</AccordionItem>
<AccordionItem title="Windows Defender поміщає файл `.pyd` у карантин">
Додай папки `.venv` і `_smoke_pkg` свого робочого простору до винятків Defender, перейшовши в Windows Security → Virus & threat protection → Manage settings → Exclusions
</AccordionItem>
<AccordionItem title="VS Build Tools не вдається встановити (немає прав адміністратора)">
Потрібен доступ адміністратора. Звернись до свого IT-відділу за доступом
</AccordionItem>
<AccordionItem title="`WinError 32` / файл використовується під час перезбирання">
.pyd заблокований запущеним ядром. Перезапусти ядро (Ctrl+Shift+P → Jupyter: Restart Kernel), повторно виконай Крок 3, потім перезбери
</AccordionItem>
<AccordionItem title="Команди мовчки нічого не роблять (без помилки, без виводу)">
Можливо, ти перебуваєш у cmd.exe замість PowerShell. Перевір своє запрошення: PowerShell показує `PS C:\>`, cmd показує `C:\>`. Відкрий PowerShell з меню Пуск або Win+X
</AccordionItem>
<AccordionItem title="Встановлення MSVC виглядає завислим">
Прапорці `--passive --wait` блокують PowerShell, поки встановлювач працює у фоновому режимі. Перевір панель завдань на наявність вікна "Visual Studio Installer". Встановлення може зайняти 10-30 хвилин
</AccordionItem>
</Accordion>
