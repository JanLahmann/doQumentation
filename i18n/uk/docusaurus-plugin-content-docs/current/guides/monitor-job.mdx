## Моніторинг завдання {#monitor-a-job}

Використовуй ці методи, щоб перевірити статус надісланих завдань, отримати результати та переглянути деталі, пов'язані із завданням та його виконанням.

<Tabs>
    <TabItem value="Qiskit" label="Monitor a job with Qiskit">
        Екземпляр завдання надає кілька методів для моніторингу:

        | Method | Description |
        | --- | --- |
        | `job.status()` | Check the current job status |
        | `job.job_id()` | Get the unique job identifier |
        | `job.result()` | Retrieve job results (blocking call until complete) |
        | `job.wait_for_final_state()` | Block until the job reaches a terminal state |

        
    </TabItem>
    <TabItem value="IQP" label="Monitor a job on IBM Quantum Platform">
        Перейди на [сторінку Workloads](https://quantum.cloud.ibm.com/workloads) і перевір стовпець Status. Статус твого завдання відображається як один із наступних:
        - **Pending**: завдання очікує на виконання на QPU
        - **In progress**: завдання наразі виконується
        - **Completed**: завдання успішно завершено
        - **Failed**: під час виконання завдання виникла помилка
        - **Canceled**: користувач скасував завдання

        Натисни на назву завдання або рядок, щоб відкрити детальний перегляд, де ти можеш побачити таку інформацію, як результати та будь-які повідомлення про помилки.

    </TabItem>
</Tabs>

### Чому завдання залишається у статусі "In progress" {#why-a-job-stays-in-progress}

Ти можеш помітити, що завдання (в режимі job або batch), яке, як ти очікуєш, займе лише кілька секунд, залишається у статусі **In progress** (у Qiskit це називається `RUNNING`) значно довше. Це нормально, і це не означає, що завдання витрачає весь цей час як використання. Це відбувається через те, як завдання плануються на QPU:

- Кожне завдання вимагає класичної попередньої обробки, перш ніж воно зможе виконуватися на QPU. Завдання переходить у стан **In progress** (`RUNNING`), щойно починається ця класична обробка — а не тоді, коли воно починає виконуватися на QPU.

- Більшість цієї класичної обробки виконується паралельно, тому кілька завдань можуть перебувати в статусі **In progress** одночасно.

- Однак лише одне завдання одночасно може виконуватися на QPU. Коли кілька завдань завершують класичну обробку і готові до виконання, вони мають чекати своєї черги на QPU. Це називається *конкуренцією за QPU*. Коли конкуренція висока, завдання може залишатися у статусі **In progress** помітно довше, ніж кілька секунд часу QPU, які йому насправді потрібні.

- Конкуренція також може виникати, коли на QPU виконується завдання системного обслуговування, наприклад калібрування. Твоє завдання залишається у статусі **In progress**, доки завдання обслуговування не завершиться і QPU не стане доступним.


Через це фактичний астрономічний час, який завдання проводить у статусі **In progress**, не збігається з його використанням. Як [оцінка використання](/guides/estimate-job-run-time), так і [максимальний час виконання](/guides/max-execution-time) базуються лише на часі, протягом якого QPU заблоковано для виконання твого завдання, і тому не враховують багатопотокову класичну обробку, описану вище. Тривалий час у статусі **In progress** не збільшує заявлене використання чи вартість.

#### Режим сесії відрізняється {#session-mode-is-different}

Попередня поведінка стосується [режиму job](/guides/execution-modes#job-mode) та [режиму batch](/guides/execution-modes#batch-mode). У [режимі session](/guides/execution-modes#session-mode) протягом активного вікна сесії користувач має ексклюзивний доступ до бекенду, і жодні інші завдання не можуть виконуватися, включно з калібрувальними завданнями. Тому будь-яка конкуренція за QPU відбувається лише серед твоїх власних завдань сесії. Крім того, оскільки потужність QPU резервується на час сесії, використання сесії вимірюється як астрономічний час, поки сесія залишається активною, незалежно від того, чи виконуються завдання активно. Дивись [Використання робочого навантаження](/guides/estimate-job-run-time#usage) для отримання додаткової інформації.

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve a job by ID
job = service.job("<job_id>")

# Get job ID (useful for saving for later retrieval)
print(f"Job ID: {job.job_id()}")

# Check current status
print(f"Status: {job.status()}")

# Wait for job to complete (blocking call)
job.wait_for_final_state()
print("Job completed")

# Get results
results = job.result()
print(results)
```

## Перегляд метрик завдань {#view-job-metrics}

Отримай огляд твоїх поданих завдань, включно з метриками робочих навантажень batch та session.

<Tabs>
    <TabItem value="Qiskit" label="Get job metrics with Qiskit">
        Використай метод [`service.jobs()`](https://docs.quantum.ibm.com/api/qiskit-ibm-runtime/qiskit-runtime-service#jobs) з фільтрами, щоб отримати інформацію про твої подані завдання, наприклад скільки їх було подано, який їхній статус і коли вони були створені. Наступний приклад отримує всі завдання, подані за останні сім днів, і обчислює загальне використання цих завдань.

        
    </TabItem>
    <TabItem value="IQP" label="View job metrics on IBM Quantum Platform">
        Перейди на [сторінку Analytics](https://quantum.cloud.ibm.com/analytics), щоб переглянути та завантажити дані, такі як:
        - загальне використання
        - використання з фільтрацією за екземпляром, квантовим комп'ютером і користувачем
        - кількість робочих навантажень job, batch і session

        **Примітка**: ти можеш отримати доступ до сторінки Analytics лише для облікових записів, якими ти володієш або керуєш.
    </TabItem>
</Tabs>

```python
from datetime import datetime, timedelta
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve all jobs in the last 7 days
seven_days_ago = datetime.now() - timedelta(days=7)
jobs = service.jobs(limit=None, created_after=seven_days_ago)

# To retrieve all jobs in a Session or Batch, use the session_id filter
# jobs = service.jobs(session_id="<session id>")

total_usage = 0
for job in jobs:
    total_usage += job.usage()

print(f"{len(jobs)} jobs were submitted in the last 7 days.")
print(f"Total usage was {total_usage} seconds")
```

## Отримання властивостей бекенду {#retrieve-backend-properties}

<Tabs>
    <TabItem value="Qiskit" label="Retrieve backend properties with Qiskit">
        Ти можеш використати `job.properties()`, щоб отримати властивості бекенду, включно з частотами помилок, на момент виконання завдання.

        Цей приклад демонструє, як отримати властивості бекенду, актуальні на момент виконання завдання, включно з часами $T_1$/$T_2$ та частотами помилок для конкретного кубіта (0).

        

        <Admonition type="note" title="Застарілі пакети провайдерів">
            `service.jobs()` також повертає завдання, запущені із застарілого пакета `qiskit-ibm-provider`. Завдання, подані старішим (також застарілим) пакетом `qiskit-ibmq-provider`, більше недоступні.
        </Admonition>
    </TabItem>
    <TabItem value="IQP" label="Retrieve backend properties on IBM Quantum Platform">
        Ти можеш переглянути дані калібрування бекенду на момент виконання завдання, а також на момент його створення.
        1. Перейди на [сторінку Workloads](https://quantum.cloud.ibm.com/workloads)
        2. Натисни на робоче навантаження, щоб відкрити його сторінку деталей
        3. У розділі Quantum computer натисни View calibration history
        4. Скористайся спадним меню, щоб змінити перегляд даних із "At job execution start" на "At job creation"
    </TabItem>
</Tabs>

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Uncomment the next line to retrieve a specific job by ID
# job = service.job("<job_id>")

# Optionally retrieve multiple jobs with filters
# Use `limit` to retrieve a specific number of jobs. The default `limit` is 10.
my_backend = "<your-backend>"
recent_jobs = service.jobs(backend_name=my_backend, limit=10)

print(f"Retrieved {len(recent_jobs)} recent jobs from {my_backend}\n")

# Get results from all jobs
for job in recent_jobs:
    print(f"Job ID: {job.job_id()}")
    print(f"Status: {job.status()}")

    # Retrieve results if the job is complete
    if str(job.status()) == "DONE":
        try:
            results = job.result()
            print(f"Results: {results}")
        except Exception as e:
            print(f"Error retrieving results: {e}")
    else:
        print("Results: Not available (job still running or failed)")
    print()
```

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve a specific job by ID
job = service.job("<job_id>")

print(f"Job ID: {job.job_id()}")
print(f"Backend: {job.backend}\n")

# Fetch backend properties at the time of job execution
properties = job.properties()

if properties:
    print("Backend Properties at Job Execution Time:")
    print("=" * 60)

    # Get T1 (relaxation time) for qubit 0
    t1 = properties.t1(0)
    print(f"Qubit 0 T1 (relaxation time): {t1}")

    # Get T2 (dephasing time) for qubit 0
    t2 = properties.t2(0)
    print(f"Qubit 0 T2 (dephasing time): {t2}")

    # Get readout error for qubit 0
    readout_error = properties.readout_error(0)
    print(f"Qubit 0 readout error: {readout_error}")

    # Get all properties for a specific qubit
    print("All properties for qubit 0:")
    qubit_props = properties.qubit_property(0)
    for prop_name, prop_value in qubit_props.items():
        print(f"  {prop_name}: {prop_value}")
else:
    print("No properties available for this job")
```

## Скасування завдання {#cancel-a-job}

Скасуй завдання, яке перебуває в черзі або виконується. Після скасування завдання відновити його неможливо.

<Tabs>
    <TabItem value="Qiskit" label="Cancel with Qiskit">
        Використай метод `job.cancel()`, щоб скасувати завдання програмно.

        
    </TabItem>
    <TabItem value="IQP" label="Cancel on IBM Quantum Platform">
        1. **З таблиці робочих навантажень**: натисни меню переповнення в кінці рядка робочого навантаження, яке хочеш скасувати, і вибери **Cancel**.
        2. **Зі сторінки деталей завдання**: натисни на робоче навантаження, щоб відкрити його сторінку деталей, скористайся спадним меню **Actions** угорі та вибери **Cancel**.
    </TabItem>
</Tabs>

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve the job
job = service.job("<job_id>")

# Cancel the job
job.cancel()

print(f"Job {job.job_id()} has been canceled")
```
