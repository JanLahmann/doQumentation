# Qiskit SDK v2.3 {#qiskit-sdk-v23}

## มกราคม 2026 {#january-2026}
- ต่อยอดจากแรงผลักดันที่สร้างขึ้นตลอดซีรีส์ v2.x ซึ่งมุ่งเน้นการวาง Qiskit ให้เป็นแพลตฟอร์มชั้นนำสำหรับเวิร์กโฟลว์ hybrid quantum-HPC [Qiskit SDK v2.3](https://www.ibm.com/quantum/blog/qiskit-2-3-release-summary) มอบการขยาย C API อย่างมีนัยสำคัญ พร้อมด้วยเครื่องมือที่เร็วขึ้นและยืดหยุ่นมากขึ้นสำหรับการสร้างและหาค่าเหมาะที่สุดของ quantum circuit


  การอัปเดตหลักประกอบด้วย:

  - **Custom transpiler passes ใน C** - เขียน custom transpiler pass ผ่าน C API ของ Qiskit โดยใช้อ็อบเจกต์ `QkDag` ใหม่และอ็อบเจกต์ `QkTarget` ที่ขยายเพิ่ม ซึ่งช่วยให้สามารถตรวจสอบ แก้ไข และขยายกระบวนการคอมไพล์ทีละขั้นตอนได้ โดยไม่ต้องสร้าง compiler pipeline ทั้งหมดขึ้นใหม่


  - **การเลือก hardware layout ที่เร็วขึ้น** - การอัปเกรดและการปรับปรุงประสิทธิภาพที่ขับเคลื่อนด้วย Rust สำหรับ `VF2Layout` และ `VF2PostLayout` ช่วยเพิ่มความเร็วและความสามารถในการขยายขนาดของการเลือก layout จาก circuit ไปยังฮาร์ดแวร์ ลดโอเวอร์เฮดของการคอมไพล์และปรับปรุงความเที่ยงตรงบนฮาร์ดแวร์ quantum


  - **การวัด multi-qubit Pauli แบบใหม่** - คำสั่งใหม่ `PauliProductMeasurement` เปิดใช้งานการวัดแบบ projective ร่วมกันข้าม qubit หลายตัวในการดำเนินการเดียว ปลดล็อกการคอมไพล์ไปสู่ Pauli-based computation ซึ่งเป็นการแทนค่าที่พบทั่วไปใน fault-tolerant quantum computing


  - **การปรับปรุงใน early fault-tolerant transpilation** - การปรับปรุงประสิทธิภาพและฟีเจอร์สำหรับการทำ transpilation ไปยัง early fault-tolerant target โดยเฉพาะ Clifford+T target ช่วยให้ผู้ใช้สร้าง transpilation pipeline สำหรับ QPU ในอนาคตได้อย่างมีประสิทธิภาพมากขึ้น


  ความสามารถเหล่านี้มอบความยืดหยุ่นให้แก่นักพัฒนามากขึ้นในการปรับแต่งการหาค่าเหมาะที่สุดของ quantum circuit และผสานรวมกับเวิร์กโฟลว์ HPC ที่มีอยู่ [เยี่ยมชมบล็อก](https://www.ibm.com/quantum/blog/qiskit-2-3-release-summary) เพื่อดูสรุปทางเทคนิคฉบับเต็ม

## เมษายน 2026 {#april-2026}

<span id="executor-primitive"></span>
- **Introducing the Executor primitive**: We're excited to announce the release of the new `Executor` primitive and a new version of the noise-learning helper class, `NoiseLearnerV3`, both of which were first previewed at QDC 2025.

  ร่วมกับ [Samplomatic](https://qiskit.github.io/samplomatic/index.html) ทั้งสองเป็นส่วนประกอบของ [directed execution model](/guides/directed-execution-model) ซึ่งให้ความโปร่งใสและการควบคุมอย่างเต็มที่ในการปรับแต่งเวิร์กโฟลว์การบรรเทาข้อผิดพลาดของคุณ ตัวอย่างเช่น บทเรียน [Probabilistic error cancellation with shaded lightcones](https://qiskit.github.io/qiskit-addon-slc/tutorials/01_getting_started.html) แสดงให้เห็นว่าโมเดลนี้ถูกใช้เพื่อรวมเทคนิคขั้นสูงเข้าด้วยกันอย่างไร รวมถึง shaded lightcones, probabilistic error cancellation (PEC), Twirled Readout Error eXtinction (TREX) และ[การเลือกภายหลังจากการวัด](/guides/post-selection) เพื่อปรับปรุงคุณภาพของผลลัพธ์เพิ่มเติม

  หากคุณต้องการระดับนามธรรมที่สูงขึ้น [`EstimatorV2`](/guides/estimator-noise-management) ใน Qiskit Runtime ยังคงมอบเทคนิคการบรรเทาและระงับข้อผิดพลาดในตัวหลายแบบ ซึ่งคุณสามารถปรับแต่งได้อย่างง่ายดายโดยใช้ตัวเลือก [`resilience_level`](/guides/estimator-noise-management#resilience-level)

  หากต้องการเรียนรู้เพิ่มเติม โปรดดูคู่มือต่อไปนี้:

    - [Executor quickstart](/guides/get-started-with-executor)

    - [Noise learning helper](/guides/noise-learning)


  ทั้งสองฟีเจอร์ใหม่นี้อยู่ในสถานะเบต้าในปัจจุบัน และต้องการ `qiskit-ibm-runtime` เวอร์ชัน 0.47.0 ขึ้นไป
