## ติดตาม job {#monitor-a-job}

ใช้เมธอดเหล่านี้เพื่อตรวจสอบสถานะของ job ที่คุณส่งไปแล้ว ดึงผลลัพธ์ และดูรายละเอียดที่เกี่ยวข้องกับ job และการทำงานของมัน

<Tabs>
    <TabItem value="Qiskit" label="Monitor a job with Qiskit">
        job instance มีเมธอดหลายตัวสำหรับการติดตาม:

        | Method | Description |
        | --- | --- |
        | `job.status()` | ตรวจสอบสถานะปัจจุบันของ job |
        | `job.job_id()` | รับตัวระบุ job ที่ไม่ซ้ำกัน |
        | `job.result()` | ดึงผลลัพธ์ของ job (blocking call จนกว่าจะเสร็จสิ้น) |
        | `job.wait_for_final_state()` | บล็อกจนกว่า job จะถึงสถานะสุดท้าย |

        
    </TabItem>
    <TabItem value="IQP" label="Monitor a job on IBM Quantum Platform">
        ไปที่ [Workloads page](https://quantum.cloud.ibm.com/workloads) และตรวจสอบคอลัมน์ Status สถานะ job ของคุณจะปรากฏเป็นหนึ่งในสิ่งต่อไปนี้:
        - **Pending**: job กำลังรอที่จะรันบน QPU
        - **In progress**: job กำลังทำงานอยู่
        - **Completed**: job เสร็จสิ้นสำเร็จ
        - **Failed**: job พบข้อผิดพลาด
        - **Canceled**: ผู้ใช้ยกเลิก job

        คลิกที่ชื่อ job หรือแถวเพื่อเปิดมุมมองรายละเอียด ซึ่งคุณจะเห็นข้อมูลเช่นผลลัพธ์และข้อความ error ต่างๆ

    </TabItem>
</Tabs>

### ทำไม job ถึงค้างอยู่ที่ "In progress" {#why-a-job-stays-in-progress}

คุณอาจสังเกตว่า job (ไม่ว่าจะเป็น job mode หรือ batch mode) ที่คุณคาดว่าจะใช้เวลาแค่ไม่กี่วินาที กลับค้างอยู่ที่สถานะ **In progress** (เรียกว่า `RUNNING` ใน Qiskit) นานกว่านั้นมาก นี่เป็นเรื่องปกติ และไม่ได้หมายความว่า job กำลังใช้เวลาทั้งหมดนั้นเป็นการใช้งาน (usage) เหตุการณ์นี้เกิดขึ้นเนื่องจากวิธีที่ job ถูกจัดตารางเวลาลงบน QPU:

- job ทุกตัวต้องผ่านการประมวลผลแบบ classical pre-processing ก่อนที่จะสามารถรันบน QPU ได้ job จะย้ายไปยังสถานะ **In progress** (`RUNNING`) ทันทีที่การประมวลผล classical นี้เริ่มต้น — ไม่ใช่เมื่อมันเริ่มทำงานบน QPU

- การประมวลผล classical ส่วนใหญ่นี้ทำงานแบบขนาน ดังนั้น job หลายตัวจึงสามารถอยู่ในสถานะ **In progress** พร้อมกันได้

- อย่างไรก็ตาม มีเพียง job เดียวเท่านั้นที่สามารถรันบน QPU ได้ในแต่ละครั้ง เมื่อ job หลายตัวประมวลผล classical เสร็จสิ้นและพร้อมที่จะทำงาน พวกมันต้องรอคิวสำหรับ QPU สิ่งนี้เรียกว่า *QPU contention* เมื่อ contention สูง job อาจค้างอยู่ที่ **In progress** นานกว่าเวลา QPU เพียงไม่กี่วินาทีที่มันต้องการจริงๆ อย่างเห็นได้ชัด

- Contention ยังสามารถเกิดขึ้นได้เมื่อมีงานบำรุงรักษาระบบ เช่น calibration กำลังรันอยู่บน QPU job ของคุณจะยังคงอยู่ที่ **In progress** จนกว่างานบำรุงรักษาจะเสร็จสิ้นและ QPU พร้อมใช้งาน


ด้วยเหตุนี้ เวลาที่ผ่านไปจริง (wall-clock time) ที่ job ใช้ในสถานะ **In progress** จึงไม่เหมือนกับ usage ของมัน ทั้ง [estimated usage](/guides/estimate-job-run-time) และ [maximum execution time](/guides/max-execution-time) คำนวณจากเวลาที่ QPU ถูกล็อกเพื่อรัน job ของคุณเท่านั้น จึงไม่รวมการประมวลผล classical แบบ multi-threaded ที่อธิบายไว้ข้างต้น เวลา **In progress** ที่นานไม่ได้เพิ่ม usage หรือค่าใช้จ่ายที่รายงานของคุณ

#### Session mode แตกต่างออกไป {#session-mode-is-different}

พฤติกรรมข้างต้นนี้ใช้กับ [job mode](/guides/execution-modes#job-mode) และ [batch mode](/guides/execution-modes#batch-mode) ใน [session mode](/guides/execution-modes#session-mode) ระหว่างช่วงเวลาที่ session ทำงานอยู่ ผู้ใช้จะมีสิทธิ์เข้าถึง backend แต่เพียงผู้เดียว และไม่มี job อื่นใดที่สามารถรันได้ รวมถึง calibration job ด้วย ดังนั้น QPU contention ใดๆ จะเกิดขึ้นเฉพาะระหว่าง job ของ session ของคุณเองเท่านั้น นอกจากนี้ เนื่องจากความจุ QPU ถูกจองไว้ตลอดระยะเวลาของ session การใช้งาน session จะถูกวัดเป็นเวลาที่ผ่านไปในขณะที่ session ยังคงทำงานอยู่ ไม่ว่า job จะกำลังรันอยู่จริงหรือไม่ก็ตาม ดู [Workload usage](/guides/estimate-job-run-time#usage) สำหรับข้อมูลเพิ่มเติม

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve a job by ID
job = service.job("<job_id>")

# Get job ID (useful for saving for later retrieval)
print(f"Job ID: {job.job_id()}")

# Check current status
print(f"Status: {job.status()}")

# Wait for job to complete (blocking call)
job.wait_for_final_state()
print("Job completed")

# Get results
results = job.result()
print(results)
```

## ดู job metrics {#view-job-metrics}

ดูภาพรวมของการส่ง job ของคุณ รวมถึง metrics ของ workload แบบ batch และ session

<Tabs>
    <TabItem value="Qiskit" label="Get job metrics with Qiskit">
        ใช้เมธอด [`service.jobs()`](https://docs.quantum.ibm.com/api/qiskit-ibm-runtime/qiskit-runtime-service#jobs) พร้อม filters เพื่อดึงข้อมูลเกี่ยวกับ job ที่คุณส่งไปแล้ว เช่น มีการส่งไปกี่ job สถานะของแต่ละ job เป็นอย่างไร และถูกสร้างขึ้นเมื่อไร ตัวอย่างต่อไปนี้ดึง job ทั้งหมดที่ส่งภายในเจ็ดวันที่ผ่านมาและคำนวณ usage ทั้งหมดจาก job เหล่านั้น

        
    </TabItem>
    <TabItem value="IQP" label="View job metrics on IBM Quantum Platform">
        ไปที่ [Analytics page](https://quantum.cloud.ibm.com/analytics) เพื่อดูและดาวน์โหลดข้อมูล เช่น:
        - Usage ทั้งหมด
        - Usage แยกตาม instance, quantum computer, และผู้ใช้
        - จำนวน workload ของ job, batch, และ session

        **หมายเหตุ**: คุณสามารถเข้าถึงหน้า Analytics ได้เฉพาะสำหรับบัญชีที่คุณเป็นเจ้าของหรือจัดการเท่านั้น
    </TabItem>
</Tabs>

```python
from datetime import datetime, timedelta
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve all jobs in the last 7 days
seven_days_ago = datetime.now() - timedelta(days=7)
jobs = service.jobs(limit=None, created_after=seven_days_ago)

# To retrieve all jobs in a Session or Batch, use the session_id filter
# jobs = service.jobs(session_id="<session id>")

total_usage = 0
for job in jobs:
    total_usage += job.usage()

print(f"{len(jobs)} jobs were submitted in the last 7 days.")
print(f"Total usage was {total_usage} seconds")
```

## ดึงคุณสมบัติของ backend {#retrieve-backend-properties}

<Tabs>
    <TabItem value="Qiskit" label="Retrieve backend properties with Qiskit">
        คุณสามารถใช้ `job.properties()` เพื่อดึงคุณสมบัติของ backend รวมถึงอัตราความผิดพลาด ณ เวลาที่ job ทำงาน

        ตัวอย่างนี้แสดงวิธีดึงคุณสมบัติของ backend ที่เป็นค่าปัจจุบัน ณ เวลาที่ job ถูกรัน รวมถึงเวลา $T_1$/$T_2$ และอัตราความผิดพลาดสำหรับ qubit เฉพาะเจาะจง (0)

        

        <Admonition type="note" title="Deprecated provider packages">
            `service.jobs()` ยังส่งคืน job ที่รันจาก package `qiskit-ibm-provider` ที่เลิกใช้งานแล้วด้วย job ที่ส่งโดย package `qiskit-ibmq-provider` เก่ากว่า (ซึ่งเลิกใช้งานแล้วเช่นกัน) ไม่สามารถใช้งานได้อีกต่อไป
        </Admonition>
    </TabItem>
    <TabItem value="IQP" label="Retrieve backend properties on IBM Quantum Platform">
        คุณสามารถดูข้อมูล calibration สำหรับ backend ณ เวลาที่ job ทำงาน รวมถึง ณ เวลาที่สร้าง job
        1. ไปที่ [Workloads page](https://quantum.cloud.ibm.com/workloads)
        2. คลิก workload เพื่อเปิดหน้า Details
        3. ภายใต้ Quantum computer คลิก View calibration history
        4. ใช้เมนู dropdown เพื่อเปลี่ยนจากการดูข้อมูล "At job execution start" เป็น "At job creation"
    </TabItem>

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Uncomment the next line to retrieve a specific job by ID
# job = service.job("<job_id>")

# Optionally retrieve multiple jobs with filters
# Use `limit` to retrieve a specific number of jobs. The default `limit` is 10.
my_backend = "<your-backend>"
recent_jobs = service.jobs(backend_name=my_backend, limit=10)

print(f"Retrieved {len(recent_jobs)} recent jobs from {my_backend}\n")

# Get results from all jobs
for job in recent_jobs:
    print(f"Job ID: {job.job_id()}")
    print(f"Status: {job.status()}")

    # Retrieve results if the job is complete
    if str(job.status()) == "DONE":
        try:
            results = job.result()
            print(f"Results: {results}")
        except Exception as e:
            print(f"Error retrieving results: {e}")
    else:
        print("Results: Not available (job still running or failed)")
    print()
```

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve a specific job by ID
job = service.job("<job_id>")

print(f"Job ID: {job.job_id()}")
print(f"Backend: {job.backend}\n")

# Fetch backend properties at the time of job execution
properties = job.properties()

if properties:
    print("Backend Properties at Job Execution Time:")
    print("=" * 60)

    # Get T1 (relaxation time) for qubit 0
    t1 = properties.t1(0)
    print(f"Qubit 0 T1 (relaxation time): {t1}")

    # Get T2 (dephasing time) for qubit 0
    t2 = properties.t2(0)
    print(f"Qubit 0 T2 (dephasing time): {t2}")

    # Get readout error for qubit 0
    readout_error = properties.readout_error(0)
    print(f"Qubit 0 readout error: {readout_error}")

    # Get all properties for a specific qubit
    print("All properties for qubit 0:")
    qubit_props = properties.qubit_property(0)
    for prop_name, prop_value in qubit_props.items():
        print(f"  {prop_name}: {prop_value}")
else:
    print("No properties available for this job")
```

## ยกเลิก job {#cancel-a-job}

ยกเลิก job ที่กำลังอยู่ในคิวหรือกำลังทำงาน เมื่อ job ถูกยกเลิกแล้ว จะไม่สามารถกลับมาทำงานต่อได้

<Tabs>
    <TabItem value="Qiskit" label="Cancel with Qiskit">
        ใช้เมธอด `job.cancel()` เพื่อยกเลิก job แบบโปรแกรมมิ่ง

        
    </TabItem>
    <TabItem value="IQP" label="Cancel on IBM Quantum Platform">
        1. **จากตาราง workloads**: คลิก overflow menu ที่ท้ายแถวของ workload ที่คุณต้องการยกเลิก และเลือก **Cancel**
        2. **จากหน้า job details**: คลิกที่ workload เพื่อเปิดหน้ารายละเอียด ใช้ dropdown **Actions** ที่ด้านบน และเลือก **Cancel**
    </TabItem>
</Tabs>

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve the job
job = service.job("<job_id>")

# Cancel the job
job.cancel()

print(f"Job {job.job_id()} has been canceled")
```
