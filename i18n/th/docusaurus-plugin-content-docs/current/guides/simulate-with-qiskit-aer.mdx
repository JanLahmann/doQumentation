[Exact simulation with Qiskit SDK primitives](/guides/simulate-with-qiskit-sdk-primitives) demonstrates how to use the reference primitives included with Qiskit to perform exact simulation of quantum circuits. Currently existing quantum processors suffer from errors, or noise, so the results of an exact simulation do not necessarily reflect the results you would expect when running circuits on real hardware. While the reference primitives in Qiskit do not support modeling noise, [Qiskit Aer](https://qiskit.org/ecosystem/aer/) includes implementations of the primitives that do support modeling noise. Qiskit Aer is a high-performance quantum circuit simulator that you can use in place of the reference primitives for better performance and more features. It is part of the [Qiskit Ecosystem](https://qiskit.github.io/ecosystem/). In this article, we demonstrate the use of Qiskit Aer primitives for exact and noisy simulation.

<Admonition type="note" title="หมายเหตุ">

- ดู [เอกสาร AerSimulator](https://qiskit.github.io/qiskit-aer/stubs/qiskit_aer.AerSimulator) สำหรับรายละเอียดเกี่ยวกับตัวเลือกวิธีการจำลองที่ Aer รองรับ
</Admonition>

วงจรนี้มีพารามิเตอร์ที่แทนมุมการหมุนสำหรับเกต $R_y$ และ $R_z$ เมื่อจำลองวงจรนี้ เราจำเป็นต้องระบุค่าที่ชัดเจนสำหรับพารามิเตอร์เหล่านี้ ในเซลล์ถัดไป เราจะระบุค่าสำหรับพารามิเตอร์เหล่านี้และใช้ primitive Estimator จาก Qiskit Aer เพื่อคำนวณค่าคาดหวังที่แม่นยำของ observable $ZZ \cdots Z$

```python
from qiskit.quantum_info import SparsePauliOp
from qiskit.transpiler import generate_preset_pass_manager
from qiskit_aer import AerSimulator
from qiskit_aer.primitives import EstimatorV2 as Estimator

observable = SparsePauliOp("Z" * n_qubits)
params = [0.1] * circuit.num_parameters

exact_estimator = Estimator()
# The circuit needs to be transpiled to the AerSimulator target
pass_manager = generate_preset_pass_manager(3, AerSimulator())
isa_circuit = pass_manager.run(circuit)
pub = (isa_circuit, observable, params)
job = exact_estimator.run([pub])
result = job.result()
pub_result = result[0]
exact_value = float(pub_result.data.evs)
exact_value
```

```text
0.8870140234256602
```

ตอนนี้ มาเริ่มต้นโมเดลสัญญาณรบกวนที่รวมความผิดพลาดแบบ depolarizing 2% บนทุกเกต CX ในทางปฏิบัติ ความผิดพลาดที่เกิดจากเกตสองคิวบิต ซึ่งในที่นี้คือเกต CX เป็นแหล่งความผิดพลาดหลักเมื่อรันวงจร ดู [สร้างโมเดลสัญญาณรบกวน](/guides/build-noise-models) สำหรับภาพรวมของการสร้างโมเดลสัญญาณรบกวนใน Qiskit Aer

ในเซลล์ถัดไป เราจะสร้าง Estimator ที่รวมโมเดลสัญญาณรบกวนนี้และใช้เพื่อคำนวณค่าคาดหวังของ observable

```python
from qiskit_aer.noise import NoiseModel, depolarizing_error

noise_model = NoiseModel()
cx_depolarizing_prob = 0.02
noise_model.add_all_qubit_quantum_error(
    depolarizing_error(cx_depolarizing_prob, 2), ["cx"]
)

noisy_estimator = Estimator(
    options=dict(backend_options=dict(noise_model=noise_model))
)
job = noisy_estimator.run([pub])
result = job.result()
pub_result = result[0]
noisy_value = float(pub_result.data.evs)
noisy_value
```

```text
0.7247404214143528
```

ในเซลล์ถัดไป เราจะสร้าง Estimator ที่รวมแบบจำลองสัญญาณรบกวนนี้ และใช้มันคำนวณค่าคาดหวังของ observable

เพื่อให้เข้าใจคร่าวๆ ว่าสัญญาณรบกวนส่งผลต่อผลลัพธ์สุดท้ายอย่างไร ลองพิจารณาโมเดลสัญญาณรบกวนของเรา ซึ่งเพิ่มความผิดพลาดแบบ depolarizing 2% ให้กับแต่ละเกต CX ความผิดพลาดแบบ depolarizing ที่มีความน่าจะเป็น $p$ ถูกกำหนดให้เป็นช่องสัญญาณควอนตัม $E$ ที่มีการกระทำต่อไปนี้บนเมทริกซ์ความหนาแน่น $\rho$:

$$
E(\rho) = (1 - p) \rho + p\frac{I}{2^n}
$$

โดยที่ $n$ คือจำนวนคิวบิต ในกรณีนี้คือ 2 นั่นคือ ด้วยความน่าจะเป็น $p$ สถานะจะถูกแทนที่ด้วยสถานะผสมอย่างสมบูรณ์ และสถานะจะคงอยู่ด้วยความน่าจะเป็น $1 - p$ หลังจากการใช้ช่องสัญญาณ depolarizing $m$ ครั้ง ความน่าจะเป็นที่สถานะจะคงอยู่จะเป็น $(1 - p)^m$ ดังนั้น เราคาดว่าความน่าจะเป็นในการรักษาสถานะที่ถูกต้องเมื่อสิ้นสุดการจำลองจะลดลงแบบเอ็กซ์โพเนนเชียลตามจำนวนเกต CX ในวงจรของเรา

ลองนับจำนวนเกต CX ในวงจรของเราและคำนวณ $(1 - p)^m$ เราจะเรียก `count_ops` เพื่อรับพจนานุกรมที่แมปชื่อเกตไปยังจำนวน และดึงรายการสำหรับเกต CX

```python
cx_count = circuit.count_ops()["cx"]
(1 - cx_depolarizing_prob) ** cx_count
```
