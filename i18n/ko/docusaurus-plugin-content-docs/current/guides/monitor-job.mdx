## 작업 모니터링 {#monitor-a-job}

제출한 작업의 상태를 확인하고, 결과를 검색하고, 작업 및 실행과 관련된 세부 정보를 보려면 다음 메서드를 사용하세요.

<Tabs>
    <TabItem value="Qiskit" label="Qiskit으로 작업 모니터링하기">
        job 인스턴스는 모니터링을 위한 여러 메서드를 제공합니다.

        | Method | Description |
        | --- | --- |
        | `job.status()` | Check the current job status |
        | `job.job_id()` | Get the unique job identifier |
        | `job.result()` | Retrieve job results (blocking call until complete) |
        | `job.wait_for_final_state()` | Block until the job reaches a terminal state |

        
    </TabItem>
    <TabItem value="IQP" label="IBM Quantum Platform에서 작업 모니터링하기">
        [Workloads 페이지](https://quantum.cloud.ibm.com/workloads)로 이동하여 Status 열을 확인하세요. 작업 상태는 다음 중 하나로 표시됩니다.
        - **Pending**: 작업이 QPU에서 실행되기를 대기 중입니다
        - **In progress**: 작업이 현재 실행 중입니다
        - **Completed**: 작업이 성공적으로 완료되었습니다
        - **Failed**: 작업에서 오류가 발생했습니다
        - **Canceled**: 사용자가 작업을 취소했습니다

        작업 이름이나 행을 클릭하면 결과 및 오류 메시지 같은 정보를 확인할 수 있는 세부 보기가 열립니다.

    </TabItem>
</Tabs>

### 작업이 "In progress" 상태로 유지되는 이유 {#why-a-job-stays-in-progress}

몇 초밖에 걸리지 않을 것이라 예상한 작업(작업 모드 또는 배치 모드 사용)이 훨씬 더 오랫동안 **In progress** 상태(Qiskit에서는 `RUNNING`이라고 함)로 유지되는 경우가 있을 수 있습니다. 이는 정상적인 현상이며, 작업이 그 전체 시간을 사용량으로 소비하고 있다는 의미는 아닙니다. 이는 작업이 QPU에 스케줄링되는 방식 때문에 발생합니다.

- 모든 작업은 QPU에서 실행되기 전에 고전적 전처리가 필요합니다. 이 고전적 처리가 시작되는 즉시 작업은 **In progress**(`RUNNING`)로 전환됩니다. QPU에서 실행이 시작될 때가 아닙니다.

- 이 고전적 처리의 대부분은 병렬로 실행되므로 여러 작업이 동시에 **In progress** 상태일 수 있습니다.

- 그러나 한 번에 하나의 작업만 QPU에서 실행될 수 있습니다. 여러 작업이 고전적 처리를 마치고 실행 준비가 되면, QPU 차례를 기다려야 합니다. 이를 *QPU 경합(contention)*이라고 합니다. 경합이 심할 때는 작업이 실제로 필요한 QPU 시간이 몇 초에 불과하더라도 **In progress** 상태가 눈에 띄게 더 오래 지속될 수 있습니다.

- 교정(calibration)과 같은 시스템 유지보수 작업이 QPU에서 실행 중일 때도 경합이 발생할 수 있습니다. 유지보수 작업이 완료되고 QPU를 사용할 수 있게 될 때까지 작업은 **In progress** 상태로 유지됩니다.


이 때문에 작업이 **In progress** 상태로 소비하는 실제 경과 시간(wall-clock time)은 사용량과 동일하지 않습니다. [예상 사용량](/guides/estimate-job-run-time)과 [최대 실행 시간](/guides/max-execution-time)은 모두 QPU가 작업을 실행하도록 잠겨 있는 시간만을 기준으로 하므로, 위에서 설명한 다중 스레드 고전적 처리는 제외됩니다. **In progress** 시간이 길다고 해서 보고되는 사용량이나 비용이 증가하지는 않습니다.

#### 세션 모드는 다릅니다 {#session-mode-is-different}

앞서 설명한 동작은 [작업 모드](/guides/execution-modes#job-mode)와 [배치 모드](/guides/execution-modes#batch-mode)에 적용됩니다. [세션 모드](/guides/execution-modes#session-mode)에서는 세션의 활성 기간 동안 사용자가 백엔드에 독점적으로 접근하며, 교정 작업을 포함하여 다른 작업은 실행될 수 없습니다. 따라서 QPU 경합은 오직 자신의 세션 작업들 사이에서만 발생합니다. 또한 세션 기간 동안 QPU 용량이 예약되어 있으므로, 세션 사용량은 작업이 실제로 실행 중인지 여부와 관계없이 세션이 활성 상태로 유지되는 경과 시간으로 측정됩니다. 자세한 내용은 [워크로드 사용량](/guides/estimate-job-run-time#usage)을 참조하세요.

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve a job by ID
job = service.job("<job_id>")

# Get job ID (useful for saving for later retrieval)
print(f"Job ID: {job.job_id()}")

# Check current status
print(f"Status: {job.status()}")

# Wait for job to complete (blocking call)
job.wait_for_final_state()
print("Job completed")

# Get results
results = job.result()
print(results)
```

## 작업 지표 보기 {#view-job-metrics}

배치 및 세션 워크로드 지표를 포함하여 작업 제출에 대한 개요를 확인하세요.

<Tabs>
    <TabItem value="Qiskit" label="Qiskit으로 작업 지표 가져오기">
        [`service.jobs()`](https://docs.quantum.ibm.com/api/qiskit-ibm-runtime/qiskit-runtime-service#jobs) 메서드를 필터와 함께 사용하여 제출한 작업의 개수, 상태, 생성 시점 등 정보를 검색하세요. 다음 예제는 지난 7일 동안 제출된 모든 작업을 검색하고 해당 작업들의 총 사용량을 계산합니다.

        
    </TabItem>
    <TabItem value="IQP" label="IBM Quantum Platform에서 작업 지표 보기">
        [Analytics 페이지](https://quantum.cloud.ibm.com/analytics)로 이동하여 다음과 같은 데이터를 확인하고 다운로드할 수 있습니다.
        - 총 사용량
        - 인스턴스, 양자 컴퓨터, 사용자별로 필터링된 사용량
        - 작업, 배치, 세션 워크로드 개수

        **참고**: Analytics 페이지는 본인이 소유하거나 관리하는 계정에 대해서만 접근할 수 있습니다.
    </TabItem>
</Tabs>

```python
from datetime import datetime, timedelta
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve all jobs in the last 7 days
seven_days_ago = datetime.now() - timedelta(days=7)
jobs = service.jobs(limit=None, created_after=seven_days_ago)

# To retrieve all jobs in a Session or Batch, use the session_id filter
# jobs = service.jobs(session_id="<session id>")

total_usage = 0
for job in jobs:
    total_usage += job.usage()

print(f"{len(jobs)} jobs were submitted in the last 7 days.")
print(f"Total usage was {total_usage} seconds")
```

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Uncomment the next line to retrieve a specific job by ID
# job = service.job("<job_id>")

# Optionally retrieve multiple jobs with filters
# Use `limit` to retrieve a specific number of jobs. The default `limit` is 10.
my_backend = "<your-backend>"
recent_jobs = service.jobs(backend_name=my_backend, limit=10)

print(f"Retrieved {len(recent_jobs)} recent jobs from {my_backend}\n")

# Get results from all jobs
for job in recent_jobs:
    print(f"Job ID: {job.job_id()}")
    print(f"Status: {job.status()}")

    # Retrieve results if the job is complete
    if str(job.status()) == "DONE":
        try:
            results = job.result()
            print(f"Results: {results}")
        except Exception as e:
            print(f"Error retrieving results: {e}")
    else:
        print("Results: Not available (job still running or failed)")
    print()
```

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve a specific job by ID
job = service.job("<job_id>")

print(f"Job ID: {job.job_id()}")
print(f"Backend: {job.backend}\n")

# Fetch backend properties at the time of job execution
properties = job.properties()

if properties:
    print("Backend Properties at Job Execution Time:")
    print("=" * 60)

    # Get T1 (relaxation time) for qubit 0
    t1 = properties.t1(0)
    print(f"Qubit 0 T1 (relaxation time): {t1}")

    # Get T2 (dephasing time) for qubit 0
    t2 = properties.t2(0)
    print(f"Qubit 0 T2 (dephasing time): {t2}")

    # Get readout error for qubit 0
    readout_error = properties.readout_error(0)
    print(f"Qubit 0 readout error: {readout_error}")

    # Get all properties for a specific qubit
    print("All properties for qubit 0:")
    qubit_props = properties.qubit_property(0)
    for prop_name, prop_value in qubit_props.items():
        print(f"  {prop_name}: {prop_value}")
else:
    print("No properties available for this job")
```

## 작업 취소 {#cancel-a-job}

대기 중이거나 실행 중인 작업을 취소하세요. 작업이 취소되면 다시 재개할 수 없습니다.

<Tabs>
    <TabItem value="Qiskit" label="Qiskit으로 취소하기">
        `job.cancel()` 메서드를 사용하여 프로그래밍 방식으로 작업을 취소하세요.

        
    </TabItem>
    <TabItem value="IQP" label="IBM Quantum Platform에서 취소하기">
        1. **워크로드 테이블에서**: 취소하려는 워크로드 행 끝에 있는 오버플로 메뉴를 클릭하고 **Cancel**을 선택합니다.
        2. **작업 세부 정보 페이지에서**: 워크로드를 클릭하여 세부 정보 페이지를 열고, 상단의 **Actions** 드롭다운을 사용하여 **Cancel**을 선택합니다.
    </TabItem>
</Tabs>

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve the job
job = service.job("<job_id>")

# Cancel the job
job.cancel()

print(f"Job {job.job_id()} has been canceled")
```
