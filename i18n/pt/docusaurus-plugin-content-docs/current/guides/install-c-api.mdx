# Instalar a API C do Qiskit {#install-the-qiskit-c-api}

Este guia descreve como instalar e usar a API C do Qiskit. Após a instalação estar concluída, leia [Estender Python com a API C do Qiskit](/guides/c-extension-for-python).

O exemplo a seguir constrói um observable com C:

```c
// file: example.c
#include <stdio.h>
#include <stdint.h>
#include <qiskit.h>

int main(int argc, char *argv[]) {
    // build a 100-qubit empty observable
    uint32_t num_qubits = 100;
    QkObs *obs = qk_obs_zero(num_qubits);

    // add the term 2 * (X0 Y1 Z2) to the observable
    QkComplex64 coeff = {2, 0};
    QkBitTerm bit_terms[3] = {QkBitTerm_X, QkBitTerm_Y, QkBitTerm_Z}; 
    // bit terms: X Y Z
    uint32_t indices[3] = {0, 1, 2};  // indices: 0 1 2
    QkObsTerm term = {coeff, 3, bit_terms, indices, num_qubits};
    qk_obs_add_term(obs, &term);  // append the term

    // print some properties and the observable itself
    printf("num_qubits: %i\n", qk_obs_num_qubits(obs));
    printf("num_terms: %lu\n", qk_obs_num_terms(obs));
    printf("observable: %s\n", qk_obs_str(obs));

    // free the memory allocated for the observable
    qk_obs_free(obs);

    return 0;
}
```

## UNIX-like {#unix-like}

Esta seção fornece instruções de compilação para sistemas do tipo UNIX.

### Requisitos {#requirements}

A compilação requer as seguintes ferramentas:
* Um compilador Rust: veja, por exemplo, o [guia de instalação do Qiskit a partir do código-fonte](/guides/install-qiskit-source)
* Um compilador C: por exemplo, GCC no Linux e Clang no MacOS. A API C do Qiskit é compatível com compiladores que seguem o padrão [C11](https://en.wikipedia.org/wiki/C11_(C_standard_revision)).
* [`cbindgen`](https://github.com/mozilla/cbindgen): uma ferramenta para criar o cabeçalho C, que você pode instalar com `cargo install cbindgen`
   Executar a ferramenta pela linha de comando deve estar habilitado, o que pode exigir a exportação da variável `PATH` para incluir `/path/to/.cargo/bin`.
* Biblioteca Python instalada (Python 3.9+): a biblioteca Python é necessária durante a vinculação dinâmica. Note que o Python não é usado em tempo de execução e o interpretador nunca é inicializado; apenas alguns símbolos de `libpython` precisam estar definidos. Veja [esta issue](https://github.com/Qiskit/qiskit/issues/14240) para mais detalhes.
* (GNU) Make: opcional, mas recomendado para usar processos de instalação automatizados.

Este código verifica que tudo foi instalado corretamente:

```bash
rustc --version
gcc --version
cbindgen --version
make --version  # optional, but recommended
```

### Compilação {#build}

Para compilar o cabeçalho C e a biblioteca, você pode executar o seguinte comando Make[^1] na raiz do Qiskit,
[^1]: Se você não instalou o Make, verifique o `Makefile` na raiz do Qiskit para os comandos necessários — ou simplesmente instale o Make; ainda dá tempo.)

```bash
make c
```
o que fornecerá a biblioteca compartilhada compilada em `dist/c/lib` e o cabeçalho `qiskit.h` com
todas as declarações de funções em `dist/c/include`. Note que o nome exato da biblioteca depende
da plataforma; por exemplo, `libqiskit.so` no UNIX e `libqiskit.dylib` no MacOS.
(Note que esta etapa atualmente emite muitos avisos, o que é esperado e não é motivo de preocupação. Versões futuras removerão os avisos.)

Você pode então compilar um programa C usando o cabeçalho e a biblioteca C do Qiskit:

```bash
gcc example.c -o example.o -I /path/to/dist/c/include -L /path/to/dist/c/lib -lqiskit
```
Para garantir que a biblioteca do Qiskit seja encontrada durante a vinculação, defina o caminho da biblioteca em tempo de execução para
incluir `/path/to/dist/c/lib`. Se a biblioteca Python não estiver disponível por padrão durante a vinculação dinâmica,
ela também precisará ser adicionada. Esses comandos dependem da plataforma. No Linux:

```bash
export LD_LIBRARY_PATH=/path/to/dist/c/lib:$LD_LIBRARY_PATH
# On Linux, the Python library is typically included 
# in the dynamic library path by default.
export LD_LIBRARY_PATH=/path/to/python/lib:$LD_LIBRARY_PATH
```
No MacOS:

```bash
export DYLD_LIBRARY_PATH=/path/to/dist/c/lib:$DYLD_LIBRARY_PATH
export DYLD_LIBRARY_PATH=/path/to/python/lib:$DYLD_LIBRARY_PATH
```
Como alternativa, você pode definir o caminho da biblioteca em tempo de execução durante a compilação adicionando

```
-Wl,-rpath,/path/to/dist/c/lib
# same for Python
```
aos flags do compilador.
Além disso, a biblioteca Python precisa estar disponível durante a vinculação dinâmica. Em ambientes Linux,
isso normalmente é o padrão.

Agora você pode executar o binário:

```bash
./example.o
```
que, se usar o trecho de exemplo mostrado anteriormente, deve imprimir

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```

## Windows {#windows}

Esta seção fornece instruções de compilação para sistemas Windows.

Existem duas formas independentes de usar a API C no Windows:

* **Compile módulos de extensão Python** que usam a API C do Qiskit. Siga as etapas 1-5. Esse caminho usa os cabeçalhos C fornecidos com o pacote Python `qiskit` e não requer Rust nem cbindgen.

* **Compile a biblioteca C independente** para vincular a um programa C puro, como é feito na seção [semelhante ao UNIX](#unix). Complete a etapa 1 e depois pule para [Compilar a biblioteca independente](#build-the-standalone-library), que lista seus requisitos adicionais.


### Requisitos {#requirements-1}

- São necessários direitos de administrador para algumas etapas.

- 5-8 GB de espaço livre em disco.

- Um compilador C: Microsoft Visual C++ (MSVC), instalado na etapa 1.

- Uma instalação do Python de 64 bits (3.10 ou posterior), instalada na etapa 1.


### Antes de começar {#before-you-begin}

Crie seu espaço de trabalho. Este deve ser um caminho curto em uma unidade local. Não use pastas sincronizadas com o OneDrive (como Documents ou Desktop), unidades de rede, ou caminhos com espaços ou caracteres não ASCII. Se seu nome de usuário contiver caracteres não ingleses, não o coloque dentro da sua pasta de usuário.

Exemplos de bons caminhos de espaço de trabalho: `C:\workspace`, `D:\workspace`, `C:\Users\john\workspace`

### Etapa 3 - Carregue o ambiente MSVC {#step-3-load-the-msvc-environment}

Execute o seguinte código em cada nova sessão do Python (por exemplo, toda vez que reiniciar um kernel do Jupyter). Ele localiza e carrega automaticamente o ambiente de desenvolvedor do MSVC, para que você não precise do prompt de comando embutido x64.

O exemplo desta documentação compila módulos de extensão C usando `setuptools` com o MSVC. Geralmente, você define `QISKIT_PYTHON_EXTENSION`, inclui `qiskit.h` e chama `qk_import()` na sua função de inicialização. Apenas os cabeçalhos de `qiskit.capi.get_include()` são necessários no momento da compilação — nenhuma biblioteca é vinculada. Consulte [Estender o Qiskit em Python com C](/guides/c-extension-for-python) para mais detalhes.

<Accordion>
  <AccordionItem title="Carregue o ambiente MSVC">

```python
import os, sys, subprocess, glob, shutil

def load_msvc_env():
    if os.name != "nt":
        return "Not Windows — the system C compiler is used as-is."
    if shutil.which("cl"):
        return "cl.exe is already available in this kernel."

    pf86 = os.environ.get("ProgramFiles(x86)", r"C:\Program Files (x86)")
    pf = os.environ.get("ProgramFiles", r"C:\Program Files")
    vcvars = None

    vswhere = os.path.join(pf86, "Microsoft Visual Studio", "Installer", "vswhere.exe")
    if os.path.isfile(vswhere):
        # vswhere outputs UTF-8 regardless of system locale
        inst = subprocess.run(
            [vswhere, "-latest", "-products", "*",
             "-requires", "Microsoft.VisualStudio.Component.VC.Tools.x86.x64",
             "-property", "installationPath"],
            capture_output=True, text=True, encoding="utf-8").stdout.strip()
        if inst:
            cand = os.path.join(inst, "VC", "Auxiliary", "Build", "vcvars64.bat")
            if os.path.isfile(cand):
                vcvars = cand

    if not vcvars:
        pat = os.path.join("Microsoft Visual Studio", "*", "*",
                           "VC", "Auxiliary", "Build", "vcvars64.bat")
        hits = glob.glob(os.path.join(pf86, pat)) + glob.glob(os.path.join(pf, pat))
        if hits:
            vcvars = sorted(hits)[-1]

    if not vcvars:
        return ("Could not find vcvars64.bat. Install MSVC Build Tools (Step 1.3), "
                "or launch Jupyter from the x64 Native Tools Command Prompt.")

    # cmd.exe outputs in the OEM codepage (cp437/cp850/etc.), not the ANSI codepage
    out = subprocess.run(f'"{vcvars}" >nul 2>&1 && set',
                         capture_output=True, text=True, encoding="oem", shell=True).stdout
    for line in out.splitlines():
        if "=" in line:
            k, _, v = line.partition("=")
            os.environ[k] = v

    return ("Loaded MSVC from:\n  " + vcvars) if shutil.which("cl") \
        else "Ran vcvars64.bat but cl.exe is still not found — check your MSVC install."

print(load_msvc_env())
print("cl.exe on PATH:", shutil.which("cl") is not None)
```
</AccordionItem>

### Etapa 4 - Teste de fumaça: compile uma extensão C {#step-4-smoke-test-build-a-c-extension}

Execute o seguinte código. Ele grava arquivos-fonte em `_smoke_pkg/`, compila uma extensão C usando a API C do Qiskit e importa o resultado. Se ele imprimir "SMOKE TEST PASSED", sua toolchain está pronta.

O pacote segue o processo [Estender o Qiskit em Python com C](/guides/c-extension-for-python) e usa funções da [referência da API C do Qiskit](https://docs.quantum.ibm.com/api/qiskit-c).

<Accordion>
  <AccordionItem title="Smoke test code">

```python
import sys, subprocess, pathlib, importlib

root = pathlib.Path("_smoke_pkg")
pkg = root / "src" / "qgss_smoke"
pkg.mkdir(parents=True, exist_ok=True)

(root / "pyworkspace.toml").write_text("""
[build-system]
requires = ["setuptools", "qiskit>=2.4.2"]
build-backend = "setuptools.build_meta"

[workspace]
name = "qgss_smoke"
version = "0.0.1"
dependencies = ["qiskit>=2.4.2"]

[tool.setuptools]
package-dir = {"" = "src"}
""".lstrip())

(root / "setup.py").write_text("""
import qiskit
from setuptools import setup, Extension

core_ext = Extension(
    name="qgss_smoke._core",
    sources=["src/qgss_smoke/_coremodule.c"],
    include_dirs=[qiskit.capi.get_include()],
)
setup(ext_modules=[core_ext])
""".lstrip())

(pkg / "__init__.py").write_text("from . import _core\nbuild_demo = _core.build_demo\n")

(pkg / "_coremodule.c").write_text("""
#define QISKIT_PYTHON_EXTENSION
#include <Python.h>
#include <qiskit.h>
#include <stdint.h>

static PyObject *build_demo(PyObject *self, PyObject *args) {
    QkCircuit *qc = qk_circuit_new(2, 0);
    uint32_t q0[1] = {0};
    qk_circuit_gate(qc, QkGate_H, q0, NULL);
    uint32_t q1[1] = {1};
    qk_circuit_gate(qc, QkGate_X, q1, NULL);
    return qk_circuit_to_python_full(qc);
}

static PyMethodDef core_methods[] = {
    {"build_demo", build_demo, METH_NOARGS, "Build a 2-qubit demo circuit in C."},
    {NULL, NULL, 0, NULL},
};
static struct PyModuleDef core_module = {
    .m_base = PyModuleDef_HEAD_INIT,
    .m_name = "_core",
    .m_methods = core_methods,
};
PyMODINIT_FUNC PyInit__core(void) {
    if (qk_import() < 0) {
        return NULL;
    }
    return PyModuleDef_Init(&core_module);
}
""".lstrip())

# On Windows, an imported .pyd is file-locked by the OS. Drop the module from
# sys.modules BEFORE pip install --force-reinstall, otherwise pip fails with
# WinError 32 ("file in use") trying to overwrite the locked .pyd.
if "qgss_smoke._core" in sys.modules:
    del sys.modules["qgss_smoke._core"]
if "qgss_smoke" in sys.modules:
    del sys.modules["qgss_smoke"]

r = subprocess.run(
    [sys.executable, "-m", "pip", "install", "--no-build-isolation",
     "--force-reinstall", "--quiet", str(root.resolve())],
    capture_output=True, text=True,
)
if r.returncode != 0:
    output = (r.stderr + r.stdout).strip()
    print("BUILD FAILED:\n")
    print(output)
    if "WinError 32" in output or "being used by another process" in output:
        print("\n--- TIP ---")
        print("The .pyd file is locked because it was previously imported in this kernel.")
        print("Restart the kernel (Ctrl+Shift+P → 'Jupyter: Restart Kernel'), then rerun")
        print("the Step 3 MSVC cell first, then this cell again.")
    elif "cl.exe" in output.lower() or "vcvars" in output.lower() or "cannot find" in output.lower():
        print("\n--- TIP ---")
        print("The compiler was not found. rerun the Step 3 cell to load the MSVC environment.")
else:
    importlib.invalidate_caches()
    import qgss_smoke
    from qiskit import QuantumCircuit

    qc = qgss_smoke.build_demo()
    ops = dict(qc.count_ops())
    ok = isinstance(qc, QuantumCircuit) and ops.get("h") == 1 and ops.get("x") == 1

    print("Returned object is a QuantumCircuit:", isinstance(qc, QuantumCircuit))
    print("Gates built in C:", ops)
    print("\nSMOKE TEST PASSED — your Windows toolchain can build Qiskit C extensions."
          if ok else "\nSomething is off — check the gates above.")
```

### Compilar a biblioteca standalone {#build-the-standalone-library}

Esta seção compila a biblioteca C standalone, que só é necessária se você quiser compilar e vincular programas C puros, conforme descrito na seção [UNIX-like](#unix). Além dos pré-requisitos da Etapa 1, isso requer as seguintes ferramentas:

* Um compilador Rust: veja por exemplo o [guia sobre como instalar o Qiskit a partir do código-fonte](https://github.com/Qiskit/qiskit/blob/main/CONTRIBUTING.md#installing-qiskit-from-source)

* [`cbindgen`](https://github.com/mozilla/cbindgen): uma ferramenta para criar o header C, que você pode instalar com `cargo install cbindgen`.
    Executar a ferramenta a partir da linha de comando deve estar habilitado, o que pode exigir atualizar sua variável `PATH` para incluir o caminho do cargo.
* Uma instalação do Python com acesso tanto a ``python3.lib`` quanto a ``python3.dll``
* Um clone do [repositório do Qiskit](https://github.com/Qiskit/qiskit) (`git clone https://github.com/Qiskit/qiskit.git`)
<Accordion>
<AccordionItem title="Build the standalone library">
Primeiro, compile a biblioteca dinâmica `qiskit_cext`, executando o seguinte no terminal do VS Code (PowerShell) na raiz do Qiskit:

```powershell
$env:PATH = "\path\to\pythonlib;" + $env:PATH
cargo rustc --release --crate-type cdylib -p qiskit-cext
```
Isso irá gerar a biblioteca dinâmica ``.dll`` e o arquivo ``.dll.lib`` associado em `target/release`.
Em seguida, gere o cabeçalho com

```powershell
cbindgen --crate qiskit-cext --output dist\c\include\qiskit.h
```
Isso escreve o cabeçalho compatível com MSVC em ``dist\c\include``.

Agora você pode usar `cl` para compilar o programa C. Para garantir que o compilador encontre a biblioteca do Qiskit,
inclua `target\release` na variável `PATH`.

```powershell
$env:PATH = "\path\to\target\release;" + $env:PATH
cl example.c qiskit_cext.dll.lib -I\path\to\dist\c\include
```

Antes de executar, inclua o caminho para o seu ``python3.dll``.

```powershell
$env:PATH = "\path\to\python3-dll;" + $env:PATH
.\example.exe
```
deve então imprimir

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```
</AccordionItem>
</Accordion>

### Solução de problemas {#troubleshooting}
<Accordion>
<AccordionItem title="`winget` is not recognized">
Atualize o [App Installer](https://apps.microsoft.com/detail/9nblggh4nns1) na Microsoft Store, ou use os links de download manual relevantes
</AccordionItem>
<AccordionItem title="`cl` is not recognized">
Execute novamente a célula de carregamento do MSVC (Etapa 3), ou use o x64 Native Tools Command Prompt
</AccordionItem>
<AccordionItem title="`python` opens Microsoft Store">
Vá em Configurações → Aplicativos → Configurações avançadas de aplicativos → Aliases de execução de aplicativos e desative `python.exe`
</AccordionItem>
<AccordionItem title="`.ps1 cannot be loaded` / scripts disabled">
Execute `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` e tente novamente
</AccordionItem>
<AccordionItem title="`cannot open file 'qiskit.h'`">
Execute `python -c "import qiskit.capi; print(qiskit.capi.get_include())"` e confirme se o caminho existe
</AccordionItem>
<AccordionItem title="`qiskit.capi` not found">
Execute `pip install "qiskit[visualization]~=2.4.2"`
</AccordionItem>
<AccordionItem title="`qiskit-aer` build fails">
Execute `pip install qiskit-aer --only-binary=:all:`. Se isso também falhar, use o Python 3.12 ou pule o aer, que é opcional
</AccordionItem>
<AccordionItem title="Build runs but import fails with a version error">
A extensão C do Qiskit compilada e a versão do Qiskit instalada precisam ter a mesma versão.  Reinstale o Qiskit com `pip install "qiskit~=2.4.2"`
</AccordionItem>
<AccordionItem title="I rebuilt the C but the circuit did not change">
Uma extensão C não pode ser reimportada em tempo real. Reinicie o kernel, execute novamente os comandos do MSVC (Etapa 3) e depois recompile
</AccordionItem>
<AccordionItem title="PowerShell script was blocked">
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
</AccordionItem>
<AccordionItem title="Path length errors">
Use um caminho raiz curto em C:\ (por exemplo, `C:\workspace`, ou o caminho que você definiu na etapa de configuração), ou habilite Caminhos Longos: Configurações → Sistema → Para desenvolvedores → Caminhos Longos
</AccordionItem>
<AccordionItem title="Conda is active (the prompt shows `(base)`) or builds behave oddly after using Anaconda">
Execute `conda deactivate` até que `CONDA_DEFAULT_ENV` e `CONDA_PREFIX` desapareçam do ambiente. Verifique com `$env:CONDA_PREFIX`. Se persistirem, abra um novo PowerShell (não um prompt do Anaconda) e tente novamente a partir da Etapa 2.
</AccordionItem>
<AccordionItem title="The virtual environment was created from a conda-managed Python (check the `home =` line in `.venv\pyvenv.cfg`)">
O ambiente virtual herdou o runtime C do conda e não pode ser corrigido no local. Exclua-o, baixe o Python 3.12 no site do [Python](https://www.python.org/downloads/) e recompile. Execute `Remove-Item -Recurse -Force .venv`, depois execute novamente o snippet de detecção do Python na Etapa 1 para definir `$PYTHON_EXE`, e então recrie o ambiente virtual (Etapa 2).
</AccordionItem>
<AccordionItem title="`DLL load failed` on import">
É provável que o conda esteja vazando para dentro do ambiente virtual. Verifique os dois problemas imediatamente acima. Verifique também se o Python é de 64 bits: `python -c "import platform; print(platform.architecture())"`
</AccordionItem>
<AccordionItem title="Build fails with garbled paths or `C1083`">
Seu nome de usuário ou caminho do workspace contém caracteres não ASCII. Mova o workspace para um caminho curto somente ASCII (por exemplo, `C:\workspace`)
</AccordionItem>
<AccordionItem title="Build or import randomly fails, works on retry">
A pasta do workspace está sincronizada pelo OneDrive. Mova-a para um caminho local como `C:\workspace`
</AccordionItem>
<AccordionItem title="Build interrupted midway (for example, there was a power loss)">
Exclua a pasta `_smoke_pkg` no seu workspace, execute novamente a célula de carregamento do MSVC e, em seguida, execute novamente a célula do smoke test
</AccordionItem>
<AccordionItem title="`pip install` fails with SSL certificate error">
Sua rede usa um proxy que intercepta o HTTPS. Tente executar `pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org qiskit` ou peça ao administrador da rede o certificado CA do proxy
</AccordionItem>
<AccordionItem title="Windows Defender quarantines the `.pyd` file">
Adicione as pastas `.venv` e `_smoke_pkg` do seu workspace às exclusões do Defender indo em Segurança do Windows → Proteção contra vírus e ameaças → Gerenciar configurações → Exclusões
</AccordionItem>
<AccordionItem title="VS Build Tools cannot be installed (no admin rights)">
É necessário acesso de administrador. Peça acesso ao seu departamento de TI
</AccordionItem>
<AccordionItem title="`WinError 32` / file in use during rebuild">
O .pyd está bloqueado pelo kernel em execução. Reinicie o kernel (Ctrl+Shift+P → Jupyter: Restart Kernel), execute novamente a Etapa 3 e depois recompile
</AccordionItem>
<AccordionItem title="Commands silently do nothing (no error, no output)">
Você pode estar no cmd.exe em vez do PowerShell. Verifique seu prompt: o PowerShell mostra `PS C:\>`, o cmd mostra `C:\>`. Abra o PowerShell pelo Menu Iniciar ou Win+X
</AccordionItem>
<AccordionItem title="MSVC install appears stuck">
As flags `--passive --wait` bloqueiam o PowerShell enquanto o instalador é executado em segundo plano. Verifique sua barra de tarefas em busca de uma janela "Visual Studio Installer". Pode levar de 10 a 30 minutos para instalar
</AccordionItem>
</Accordion>
