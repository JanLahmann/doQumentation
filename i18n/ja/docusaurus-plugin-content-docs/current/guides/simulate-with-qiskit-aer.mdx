[Exact simulation with Qiskit SDK primitives](/guides/simulate-with-qiskit-sdk-primitives) demonstrates how to use the reference primitives included with Qiskit to perform exact simulation of quantum circuits. Currently existing quantum processors suffer from errors, or noise, so the results of an exact simulation do not necessarily reflect the results you would expect when running circuits on real hardware. While the reference primitives in Qiskit do not support modeling noise, [Qiskit Aer](https://qiskit.org/ecosystem/aer/) includes implementations of the primitives that do support modeling noise. Qiskit Aer is a high-performance quantum circuit simulator that you can use in place of the reference primitives for better performance and more features. It is part of the [Qiskit Ecosystem](https://qiskit.github.io/ecosystem/). In this article, we demonstrate the use of Qiskit Aer primitives for exact and noisy simulation.

<Admonition type="note" title="Notes">
- `qiskit-aer` v0.14以降が必要です。
- Qiskit Aerプリミティブはプリミティブ・インターフェースを実装していますが、IBM Quantumプリミティブと同じオプションは提供していません。例えば、レジリエンス・レベルはQiskit Aerプリミティブでは利用できません。
- Aerがサポートするシミュレーション方式のオプションの詳細については、[AerSimulatorのドキュメント](https://qiskit.github.io/qiskit-aer/stubs/qiskit_aer.AerSimulator)を参照してください。
</Admonition>

```python
from qiskit.circuit.library import efficient_su2

n_qubits = 8
circuit = efficient_su2(n_qubits)
circuit.draw("mpl")
```

![Output of the previous code cell](/docs/images/guides/simulate-with-qiskit-aer/extracted-outputs/df70b5fd-971d-4e7d-a23a-8df037c0fa47-0.svg)

この回路には、$R_y$および$R_z$ゲートの回転角度を表すパラメーターが含まれています。この回路をシミュレートする際には、これらのパラメーターに明示的な値を指定する必要があります。次のセルでは、これらのパラメーターにいくつかの値を指定し、Qiskit AerのEstimatorプリミティブを使用して、オブザーバブル$ZZ \cdots Z$の正確な期待値を計算します。

```python
from qiskit.quantum_info import SparsePauliOp
from qiskit.transpiler import generate_preset_pass_manager
from qiskit_aer import AerSimulator
from qiskit_aer.primitives import EstimatorV2 as Estimator

observable = SparsePauliOp("Z" * n_qubits)
params = [0.1] * circuit.num_parameters

exact_estimator = Estimator()
# The circuit needs to be transpiled to the AerSimulator target
pass_manager = generate_preset_pass_manager(3, AerSimulator())
isa_circuit = pass_manager.run(circuit)
pub = (isa_circuit, observable, params)
job = exact_estimator.run([pub])
result = job.result()
pub_result = result[0]
exact_value = float(pub_result.data.evs)
exact_value
```

```text
0.8870140234256602
```

次に、すべてのCXゲートに2%の脱分極エラーを含むノイズモデルを初期化します。実際には、2量子ビットゲート（ここではCXゲート）から生じるエラーが、回路を実行する際の主要なエラー源です。Qiskit Aerでのノイズモデルの構築の概要については、[ノイズモデルの構築](/guides/build-noise-models)を参照してください。

次のセルでは、このノイズモデルを組み込んだEstimatorを構築し、それを使用してオブザーバブルの期待値を計算します。

```python
from qiskit_aer.noise import NoiseModel, depolarizing_error

noise_model = NoiseModel()
cx_depolarizing_prob = 0.02
noise_model.add_all_qubit_quantum_error(
    depolarizing_error(cx_depolarizing_prob, 2), ["cx"]
)

noisy_estimator = Estimator(
    options=dict(backend_options=dict(noise_model=noise_model))
)
job = noisy_estimator.run([pub])
result = job.result()
pub_result = result[0]
noisy_value = float(pub_result.data.evs)
noisy_value
```

```text
0.7247404214143528
```

ご覧の通り、ノイズが存在する場合の期待値は正しい値からかなり離れています。実際には、ノイズの影響に対抗するためにさまざまなエラー緩和技術を使用できますが、これらの技術についての議論は本記事の範囲外です。

ノイズが最終結果にどのように影響するかを大まかに把握するために、各CXゲートに2%の脱分極エラーを追加するノイズモデルを考えます。確率$p$の脱分極エラーは、密度行列$\rho$に対して以下のような作用を持つ量子チャネル$E$として定義されます。

$$
E(\rho) = (1 - p) \rho + p\frac{I}{2^n}
$$

ここで$n$は量子ビットの数で、この場合は2です。つまり、確率$p$で状態は完全混合状態に置き換えられ、確率$1 - p$で状態は保持されます。脱分極チャネルを$m$回適用した後、状態が保持される確率は$(1 - p)^m$になります。したがって、シミュレーションの最後で正しい状態が保持される確率は、回路内のCXゲートの数に応じて指数関数的に減少すると予想されます。

回路内のCXゲートの数を数えて、$(1 - p)^m$を計算しましょう。`count_ops`を呼び出して、ゲート名を個数にマップする辞書を取得し、CXゲートのエントリを取得します。

```python
cx_count = circuit.count_ops()["cx"]
(1 - cx_depolarizing_prob) ** cx_count
```

```text
0.6542558123199923
```

この値、65%は、最終状態が正しい確率のおおよその推定値です。シミュレーションの初期状態を考慮していないため、これは控えめな推定値です。

この値（65%）は、最終状態が正しい確率の概算です。シミュレーションの初期状態を考慮していないため、これは保守的な推定値です。
