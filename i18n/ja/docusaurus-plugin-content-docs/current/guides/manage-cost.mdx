# 従量課金制プランのコスト管理 {#manage-cost-on-the-pay-as-you-go-plan}

このガイドでは、従量課金制プランのインスタンスにコスト上限を設定する方法について説明します。また、[ワークロードの QPU 使用量を最小化する](/guides/minimize-time)方法や、ワークロードに[最大実行時間](/guides/max-execution-time)を設定することでもコストを管理できます。

_コスト上限_とは、インスタンスが作成されてから実行されたすべてのワークロードの合計コストを指し、常に合計コスト以上の値になります。インスタンスが指定した合計秒数に達すると、それ以上のワークロードは実行できなくなり、追加のコストも発生しなくなります。

    <Admonition type="note">
      コスト上限は常に米ドル（USD）で指定され、その後ランタイム秒数に変換されます。ただし、月次請求の目的では、IBM Cloud&reg; アカウントで指定されたお客様の現地通貨で請求されます。為替レートは変動する可能性があるため、X ランタイム秒のコストは、最初に USD で計算した時点と、実際に現地通貨で請求される時点で異なる場合があります。そのため、現地通貨が USD でない場合、このフィールドで指定した秒数に対して請求される合計金額は、指定したドル金額と異なる場合があります。
    </Admonition>

<span id="cost-limit"></span>

## コスト上限の設定または変更 {#set-or-change-a-cost-limit}

支出を制限するには、いくつかの方法があります。

* **IBM Quantum Platform**: [インスタンス](https://quantum.cloud.ibm.com/instances)ページを開きます。制限したいインスタンスを見つけ、行末のアクションメニューをクリックして、**詳細を編集**をクリックします。合計コスト上限または使用量上限を設定し、**変更を保存**をクリックします。
   <Admonition type="note">
   従量課金制プランで新しいインスタンスを作成する際にも、コストまたは使用量上限を設定できます。従量課金制タイルを選択すると、「合計コスト上限（任意）」というラベルのフィールドが表示されます。このフィールドに合計コスト上限を入力できます。
   </Admonition>

* **API**: [インスタンス上限を秒単位で設定します](https://docs.quantum.ibm.com/api/qiskit-runtime-rest/tags/instances#tags__instances__operations__replace_instance_data)。


   ```api
   PUT /v1/instances/configuration "instance_limit":<seconds>
   ```

* **IBM Cloud CLI**: CLI の使用方法については、[IBM Cloud CLI 入門](https://cloud.ibm.com/docs/cli?topic=cli-getting-started)を参照してください。


   ```cli
      ibmcloud resource service-instance-update <instance_CRN>
      -p '{"instance_limit_seconds":"<seconds>"}'
   ```

## コスト上限の確認 {#view-the-cost-limit}

現在のコスト上限を確認するには、いくつかの方法があります。

* **IBM Quantum Platform**: 合計コスト上限は、[インスタンス](https://quantum.cloud.ibm.com/instances)テーブルの従量課金制タブに表示されます。


* **API**:


   ```api
   GET /v1/instances/configuration
   ```
   [REST API ドキュメント](https://docs.quantum.ibm.com/api/qiskit-runtime-rest/tags/instances)を参照してください。

* **IBM Cloud CLI**: CLI の使用方法については、[IBM Cloud CLI 入門](https://cloud.ibm.com/docs/cli?topic=cli-getting-started)を参照してください。


   ```cli
   ibmcloud resource service-instance-update <instance_CRN> -p
   '{"instance_limit_seconds":null}'
   ```

## コスト上限の削除 {#remove-a-cost-limit}

コスト上限はいくつかの方法で削除できます。

* **IBM Quantum Platform**: [インスタンス](https://quantum.cloud.ibm.com/instances)テーブルを開きます。更新したいインスタンスを見つけ、行末のオーバーフローメニューをクリックして、**詳細を編集**をクリックします。合計コスト上限または使用量を削除し、**変更を保存**をクリックします。


* **API**: [インスタンス上限を `null` に設定します](https://docs.quantum.ibm.com/api/qiskit-runtime-rest/tags/instances)。


   ```api
   PUT /v1/instances/configuration "instance_limit":null
   ```

* **IBM Cloud CLI**: CLI の使用方法については、[IBM Cloud CLI 入門](https://cloud.ibm.com/docs/cli?topic=cli-getting-started)を参照してください。


   ```cli
   ibmcloud resource service-instance-update <instance_CRN> -p
   '{"instance_limit_seconds":null}'
   ```
<Admonition type="note">
インスタンスを編集できるのは、管理者とオーナーのみです。アクセス権の割り当てについては、[アクセスポリシーとアクセスグループの作成](/guides/access-groups)ガイドを参照してください。
</Admonition>

### コスト上限に達した場合の動作 {#what-happens-when-the-cost-limit-is-reached}

実行中のジョブが使用量を報告し、それによってインスタンスのコスト上限を超過すると、そのインスタンスから現在実行中のジョブはすべて停止され、そのステータスは `Ran too long` という理由で `Canceled` に設定され、アカウントにはその使用量分の請求が行われます。

ジョブの実行時間は実行中に定期的にのみ報告されることに注意してください。そのため、ジョブは上限を超えて実行され続けたり、完了まで実行されたりする可能性があり、その結果、指定された上限を超える使用量に対してアカウントに請求される場合があります。

コスト上限が引き上げられるまで、このインスタンスから送信されたジョブはこれ以上実行を開始しません。

## 請求内容の確認方法 {#how-to-see-what-youre-being-charged}

リソース料金の詳細が記載された月次請求書を受け取ります。[IBM Cloud の請求と使用状況](https://cloud.ibm.com/billing)ページでは、いつでも使用金額を確認できます。

[Analytics](https://quantum.cloud.ibm.com/analytics) ページには、設定したフィルターに応じた使用状況が表示されます。また、以下に詳述するように、[インスタンス](https://quantum.cloud.ibm.com/instances)ページからいつでもインスタンスごとまたはジョブごとのコストを確認できます。

### インスタンスの使用状況の確認 {#view-instance-usage}

インスタンスに請求された金額を確認するには、[インスタンス](https://quantum.cloud.ibm.com/instances)ページからインスタンスをクリックして詳細ページを開きます。**Instance usage** フィールドには、このインスタンスが作成されてからの QPU 使用量の合計が表示されます。

請求サイクルは[請求と使用状況ページ](https://cloud.ibm.com/billing)で確認できます。

### ワークロードの使用状況の確認 {#view-workload-usage}

インスタンスに関連付けられた各ワークロードに請求された金額を確認するには、[インスタンス](https://quantum.cloud.ibm.com/instances)ページからインスタンスをクリックして詳細ページを開きます。次に、**Total workloads (all types)** の下の値をクリックします。

**Usage** 列には、そのジョブが消費した QPU の量が表示されます。

## 支出通知の設定 {#set-up-spending-notifications}

アカウントまたは特定のサービスが設定した特定の支出しきい値に達したときに通知を受け取るよう、支出通知を設定できます。詳細については、[IBM Cloud アカウントタイプ](https://cloud.ibm.com/docs/account?topic=account-accounts)ページを参照してください。IBM Cloud の支出通知は、いくつかの理由により、他のコスト管理方法と併用する必要があります。

*   通知は、コストが指定した上限を超えた*後にのみ*トリガーされます。

*   コストは 1 時間ごとに請求システムに送信されます。そのため、ジョブの送信と支出通知の送信の間に長い遅延が生じる可能性があります。

*   請求システムが請求書発行システムに情報を送るまでに数日かかる場合があり、通知がさらに遅延する可能性があります。IBM Cloud 請求システムの仕組みについては、[支出通知の設定](https://cloud.ibm.com/docs/billing-usage?topic=billing-usage-spending)を参照してください。
