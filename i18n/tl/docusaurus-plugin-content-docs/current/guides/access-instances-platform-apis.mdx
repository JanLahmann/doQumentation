# Gamitin ang IBM Cloud Resource Controller API para sa pamamahala ng instance {#use-ibm-cloud-resource-controller-api-for-instance-management}

Maaari mong gamitin ang IBM Cloud&reg; Resource Controller REST API para programmatically na kumuha, lumikha, at mag-update ng mga [instance](/guides/instances). 

Lahat ng endpoint ng Resource Controller ay nangangailangan na mag-authenticate ka sa pamamagitan ng pagpasa ng header na tinatawag na `Authorization` na may bearer token. Sumangguni sa [REST API setup guide](/guides/cloud-setup-rest-api).

## Kumuha ng instance {#get-an-instance}

Gamitin ang [`GET /v2/resource_instances/{crn}`](https://cloud.ibm.com/apidocs/resource-controller/resource-controller#get-resource-instance) endpoint para makakuha ng impormasyon tungkol sa isang partikular na instance. Ang [CRN](/guides/instances) ay dapat na URL-encoded sa path.

Bukod sa mga standard na field ng Resource Controller, kasama sa response ang mga field na tukoy sa quantum sa parehong `parameters` at `extensions`. Iniimbak ng `extensions` ang normalized na metadata ng instance, samantalang ang `parameters` ay nag-iimbak lamang ng pinakahuling request na mag-modify sa instance. Kaya, dapat kang magbasa mula sa `extensions` sa halip na `parameters`.

Kasama sa object na `extensions` ang mga field na ito:

- `instance_limit_seconds` — Integer, o `null`. Ang limitasyon ng oras ng paggamit para sa instance. Tingnan ang [Set instance allocation limits](/guides/allocation-limits).

- `usage_allocation_seconds` — Integer, o `null`. Ang oras na inilaan para sa instance na ito, ginagamit ng [fair-share scheduler](/guides/fair-share-scheduler) para matukoy ang priyoridad sa pila. Tingnan ang [Set instance allocation limits](/guides/allocation-limits).

- `backends` — Array ng mga string. Ang allowlist ng mga pangalan ng backend na available sa instance na ito. Ibig sabihin ng `["ANY"]` na lahat ng backend sa plano ay available (ang default). Ibig sabihin ng `[]` na walang available na backend.


<Admonition type="caution" title="Maaaring luma na ang field na backends">
  Ang field na `backends` sa object na `extensions` ay maaaring luma na. Maaari itong mangyari kapag binago ng IBM Quantum Support ang iyong account sa paraang nakakaapekto sa mga instance. Halimbawa, kapag inalis ang isang backend mula sa isang account, iu-update nito ang `backends` para sa instance, ngunit ang pagbabagong iyon ay hindi pa naipapakita sa Resource Controller API sa kasalukuyan.

  Sa halip, ang kasalukuyang workaround ay gamitin ang [IBM Quantum Compute Service REST API](https://docs.quantum.ibm.com/api/qiskit-runtime-rest) kasama ang [`GET /v1/backends`](https://docs.quantum.ibm.com/api/qiskit-runtime-rest/tags/backends#tags__backends__operations__list_backends) endpoint. (Siguraduhing itakda mo ang header na `Service-CRN` sa CRN ng iyong instance.)
</Admonition>

<Tabs>
  <TabItem value="curl" label="cURL">
    Ang CRN ay dapat na URL-encoded sa path. Palitan ang bawat `:` ng `%3A` at ang bawat `/` ng `%2F`. Halimbawa, ang `crn:v1:bluemix:...` ay nagiging `crn%3Av1%3Abluemix%3A...`.

    ```bash
    curl \
      --request GET \
      --url 'https://resource-controller.cloud.ibm.com/v2/resource_instances/<YOUR_INSTANCE_CRN_URL_ENCODED>' \
      --header 'Authorization: Bearer <YOUR_BEARER_TOKEN>'
    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
    import urllib.parse
    import requests

    crn = "<YOUR_INSTANCE_CRN>"
    # We use urllib.parse.quote to URL-encode the CRN.
    url = (
        "https://resource-controller.cloud.ibm.com/v2/resource_instances/"
        + urllib.parse.quote(crn, safe="")
    )

    resp = requests.get(
        url,
        headers={"Authorization": f"Bearer {token}"},
        timeout=30,
    )
    resp.raise_for_status()
    print(resp.json())
    ```
  </TabItem>
</Tabs>

## I-update ang isang instance {#update-an-instance}

Gamitin ang [`PATCH /v2/resource_instances/{crn}`](https://cloud.ibm.com/apidocs/resource-controller/resource-controller#update-resource-instance) endpoint para i-update ang limit, allocation, at pinapayagang mga backend para sa isang instance. Ang [CRN](/guides/instances) ay dapat na URL-encoded sa path.

Magpasa ng `parameters` JSON object sa request body kasama ang mga field na gusto mong baguhin, kasama ang header na `"Content-Type: application/json"`. Ang mga field na hindi isinama ay mananatiling hindi nagbabago.

- `instance_limit_seconds` — Integer, o `null`. Ang limitasyon ng oras ng paggamit para sa instance. Tingnan ang [Set instance allocation limits](/guides/allocation-limits).

- `usage_allocation_seconds` — Integer, o `null`. Ang oras na inilaan para sa instance na ito, ginagamit ng [fair-share scheduler](/guides/fair-share-scheduler) para matukoy ang priyoridad sa pila. Tingnan ang [Set instance allocation limits](/guides/allocation-limits). Hindi applicable sa mga Pay-As-You-Go instance.

- `backends` — Array ng mga string. Ang allowlist ng mga pangalan ng backend na available sa instance na ito. Ibig sabihin ng `["ANY"]` na lahat ng backend sa plano ay available. Ibig sabihin ng `[]` na walang available na backend.


<Admonition type="caution" title="Palaging isama ang isang natatanging timestamp">
  Tahimik na binabalewala ng API ang request kung ang `parameters` ay kapareho ng nakaraang request. Sa object na `parameters`, palaging isama ang field na `timestamp` na itinakda sa kasalukuyang oras para ituring na natatangi ang bawat request.
</Admonition>

Ang response ng endpoint ay katulad ng [pagkuha ng isang instance](#get-an-instance), kasama ang paraan ng paghawak nito sa object na `extensions`.

<Tabs>
  <TabItem value="curl" label="cURL">
    Ang CRN ay dapat na URL-encoded sa path. Palitan ang bawat `:` ng `%3A` at ang bawat `/` ng `%2F`. Halimbawa, ang `crn:v1:bluemix:...` ay nagiging `crn%3Av1%3Abluemix%3A...`.

    ```bash
    curl \
    --request PATCH \
    --url 'https://resource-controller.cloud.ibm.com/v2/resource_instances/<YOUR_INSTANCE_CRN_URL_ENCODED>' \
    --header 'Authorization: Bearer <YOUR_BEARER_TOKEN>' \
    --header 'Content-Type: application/json' \
    --data "{
        \"parameters\": {
            \"timestamp\": \"$(date -u +"%Y-%m-%dT%H:%M:%SZ")\",
            \"usage_allocation_seconds\": 220
        }
    }"
    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
    import urllib.parse
    import datetime
    import requests

    crn = "<YOUR_INSTANCE_CRN>"
    # We use urllib.parse.quote to URL-encode the CRN.
    url = (
        "https://resource-controller.cloud.ibm.com/v2/resource_instances/"
        + urllib.parse.quote(crn, safe="")
    )

    timestamp = datetime.datetime.now(datetime.timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
    body = {
        "parameters": {
            "timestamp": timestamp,
            "usage_allocation_seconds": 220,
        }
    }

    resp = requests.patch(
        url,
        headers={
            "Authorization": f"Bearer {token}",
            "Content-Type": "application/json",
        },
        json=body,
        timeout=30,
    )
    resp.raise_for_status()
    print(resp.json())
    ```
  </TabItem>
</Tabs>

## Lumikha ng bagong instance {#create-a-new-instance}

Gamitin ang [`POST /v2/resource_instances`](https://cloud.ibm.com/apidocs/resource-controller/resource-controller#create-resource-instance) endpoint para lumikha (mag-provision) ng bagong instance. Magpasa ng JSON body kasama ang header na `"Content-Type: application/json"`.

Mga kinakailangang field:

- `name` — Isang pangalan para sa instance na madaling basahin ng tao.

- `target` — Ang region, tulad ng `us-east` o `eu-de`.

- `resource_plan_id` — Ang plano para sa instance na ito. Tingnan ang [talahanayan ng plan ID](#get-a-list-of-all-instances).

- `resource_group` — Ang [resource group](https://cloud.ibm.com/docs/account?topic=account-rgs) na gagamitin.


Maaari ka ring magsama ng `parameters` object para itakda ang mga halagang tukoy sa quantum:

- `instance_limit_seconds` — Integer, o `null`. Ang limitasyon ng oras ng paggamit para sa instance. Tingnan ang [Set instance allocation limits](/guides/allocation-limits).

- `usage_allocation_seconds` — Integer, o `null`. Ang oras na inilaan para sa instance na ito, ginagamit ng [fair-share scheduler](/guides/fair-share-scheduler) para matukoy ang priyoridad sa pila. Tingnan ang [Set instance allocation limits](/guides/allocation-limits). Hindi applicable sa mga Pay-As-You-Go instance.

- `backends` — Array ng mga string. Ang allowlist ng mga pangalan ng backend na available sa instance na ito. Ibig sabihin ng `["ANY"]` na lahat ng backend sa plano ay available. Ibig sabihin ng `[]` na walang available na backend.


<Tabs>
  <TabItem value="curl" label="cURL">

    ```bash
    curl \
      --request POST \
      --url 'https://resource-controller.cloud.ibm.com/v2/resource_instances' \
      --header 'Authorization: Bearer <YOUR_BEARER_TOKEN>' \
      --header 'Content-Type: application/json' \
      --data '{
          "name": "my-new-instance",
          "target": "us-east",
          "resource_plan_id": "7f666d17-7893-47d8-bf9d-2b2389fc4dfc",
          "resource_group": "<YOUR_RESOURCE_GROUP_ID>",
          "parameters": {
              "instance_limit_seconds": 300,
              "usage_allocation_seconds": 220
          }
      }'
    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
    import requests

    body = {
        "name": "my-new-instance",
        "target": "us-east",
        "resource_plan_id": "7f666d17-7893-47d8-bf9d-2b2389fc4dfc",
        "resource_group": "<YOUR_RESOURCE_GROUP_ID>",
        "parameters": {
            "instance_limit_seconds": 300,
            "usage_allocation_seconds": 220,
        },
    }

    resp = requests.post(
        "https://resource-controller.cloud.ibm.com/v2/resource_instances",
        headers={
            "Authorization": f"Bearer {token}",
            "Content-Type": "application/json",
        },
        json=body,
        timeout=30,
    )
    resp.raise_for_status()
    print(resp.json())
    ```

</Tabs>

## I-configure ang access sa Qiskit Functions sa isang instance {#configure-qiskit-functions-access-on-an-instance}

Gamitin ang mga tagubiling ito para i-configure ang access sa Qiskit Functions sa isang umiiral nang instance ng IBM Quantum Compute Service sa pamamagitan ng paggamit ng IBM Cloud Resource Controller API.  Sundin ang mga tagubilin ayon sa pagkakasunod-sunod, dahil ang mga command ay umaasa sa isa't isa.  Halimbawa, ang mga variable tulad ng token at URL ay itinatakda sa isang hakbang at muling ginagamit sa mga susunod na hakbang. 

### Mga paunang kailangan {#prerequisites}

- Isang IBM Cloud API key (tinatawag ding token).  Kung kinakailangan, lumikha ng iyong API key sa [dashboard](https://quantum.cloud.ibm.com). 

- Ang CRN ng instance na gusto mong i-configure.  Ang CRN ng instance ay nakalista sa iyong pahina ng [Instances](https://quantum.cloud.ibm.com/instances).


### Hakbang 1: Kumuha ng bearer token {#step-1-get-a-bearer-token}

Ipagpalit ang iyong API key para sa isang bearer token. Ipapasa mo ang token na ito sa authorization header ng lahat ng resource controller request. Patakbuhin ang sumusunod na code para bumuo ng bearer token:

<Tabs>
  <TabItem value="curl" label="cURL">

    ```bash
curl --request POST \
  --url 'https://iam.cloud.ibm.com/identity/token' \
  --header 'Content-Type: application/x-www-form-urlencoded' \
  --data 'apikey=<YOUR_API_KEY>&grant_type=urn%3Aibm%3Aparams%3Aoauth%3Agrant-type%3Aapikey'
  --silent | jq .
    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
import requests

api_key = "<YOUR_API_KEY>"

resp = requests.post(
    "https://iam.cloud.ibm.com/identity/token",
    headers={"Content-Type": "application/x-www-form-urlencoded"},
    params={
        "apikey": api_key,
        "grant_type": "urn:ibm:params:oauth:grant-type:apikey",
    },
    timeout=30,
)
resp.raise_for_status()
token = resp.json()["access_token"]
print(token) 
    ```
  </TabItem>
</Tabs>

Kasama sa response ang field na `access_token`, na siyang iyong bearer token. Kopyahin ang halagang ito.

### Hakbang 2: I-verify ang access {#step-2-verify-access}

Bago gumawa ng anumang pagbabago, kumpirmahin na gumagana ang iyong token at suriin ang kasalukuyang configuration ng instance.

<Tabs>
  <TabItem value="curl" label="cURL">
<Admonition type="note" title="Mahalaga">
Ang CRN ay dapat na manual na URL-encoded sa path. Palitan ang bawat `:` ng `%3A` at ang bawat `/` ng `%2F`. Halimbawa, ang `crn:v1:bluemix:...` ay nagiging `crn%3Av1%3Abluemix%3A...`.
</Admonition>

    ```bash
curl --request GET \
  --url 'https://resource-controller.cloud.ibm.com/v2/resource_instances/<YOUR_INSTANCE_CRN_URL_ENCODED>' \
  --header 'Authorization: Bearer <YOUR_BEARER_TOKEN>'

    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
import urllib.parse

crn = "<YOUR_INSTANCE_CRN>"
# Ang CRN ay ise-URL-encode papunta sa path.
instance_url = (
    "https://resource-controller.cloud.ibm.com/v2/resource_instances/"
    + urllib.parse.quote(crn, safe="")
)
headers = {"Authorization": f"Bearer {token}", "Content-Type": "application/json"}

resp = requests.get(instance_url, headers=headers, timeout=30)
resp.raise_for_status()
print(resp.json()["extensions"])

    ```
  </TabItem>
</Tabs>

Kinukumpirma ng response na `200 OK` na valid ang iyong token. Ang kasalukuyang configuration ng instance ay nasa field na extensions ng response. Gamitin ito sa halip na parameters, na maaaring luma na.

### Hakbang 3: Alamin ang configuration ng functions sa antas ng account {#step-3-look-up-the-account-level-functions-configuration}

Ang isang instance ay maaari lamang bigyan ng access sa kung ano ang karapat-dapat sa account. Bago i-configure ang instance, alamin ang configuration ng account para malaman mo kung aling mga functions, business models, at permissions ang available na ibigay. Ito ang pinagmumulan ng katotohanan para sa mga halagang ipapadala mo sa Hakbang 4.

Tawagin ang `GET /accounts/{id}` sa Qiskit Runtime API gamit ang iyong API key. Ang `{id}` ay ang iyong account ID na walang prefix na `a/`.  Makikita mo ito mula sa CRN ng instance (`crn:v1:bluemix:public:quantum-computing:...:a/<ACCOUNT_ID>:...`).

<Tabs>
  <TabItem value="curl" label="cURL">

    ```bash
curl --request GET \
  --url 'https://quantum.cloud.ibm.com/api/v1/accounts/<ACCOUNT_ID>' \
  --header 'Authorization: apikey <YOUR_API_KEY>'

    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
account_id = "<ACCOUNT_ID>"  # from the CRN: crn:...:a/<ACCOUNT_ID>:...

resp = requests.get(
    f"https://quantum.cloud.ibm.com/api/v1/accounts/{account_id}",
    headers={"Authorization": f"apikey {api_key}"},
    timeout=30,
)
resp.raise_for_status()
for plan in resp.json()["plans"]:
    print(plan["plan_id"], plan.get("functions"), plan.get("custom_functions"))

    ```
  </TabItem>
</Tabs>

Kasama sa bawat plano sa response ang isang array na functions at, kung na-configure, isang object na `custom_functions`. Nakalista dito ang eksaktong pangalan, provider, business model, at mga halaga ng permissions na maaari mong ibigay sa isang instance sa ilalim ng planong iyon.

<Admonition type="note">
`GET /accounts/{id}` shows what is available to grant at the account level. `GET /functions` (see [Verify the result](#verify-result)) shows what a specific instance has already been granted. Use the **account** endpoint to discover valid values, and the **functions** endpoint to confirm the result.
</Admonition>

### Hakbang 4: I-configure ang access sa functions {#step-4-configure-functions-access}

I-update ang instance para bigyan ito ng access sa Catalog Functions at Custom Functions.

<Admonition type="note" title="Mahalagang tala">
- Ang mga halaga ng `name`, `provider`, at `business_model` sa functions ay dapat eksaktong tumugma sa mga entry na na-configure sa antas ng account (tingnan ang [nakaraang hakbang](#step-3)). Ang permissions ay dapat na isang non-empty subset ng permissions ng account para sa function na iyon. Katulad nito, ang `custom_functions.permissions` ay dapat na isang non-empty subset ng mga permissions ng `custom_functions` ng account.
- Magsama ng timestamp sa parameters sa bawat PATCH. Dine-deduplicate ng Resource Controller ang mga PATCH request sa pamamagitan ng paghahambing ng papasok na parameters sa huling halagang naimbak nito. Kung magkatugma ang mga ito, tahimik na tinatanggihan ang request na may `200 OK` nang hindi naaabot ang service. Magsama ng nagbabagong halaga ng timestamp para maiwasan ito.
</Admonition>

<Tabs>
  <TabItem value="curl" label="cURL">

    ```bash
curl --request PATCH \
  --url 'https://resource-controller.cloud.ibm.com/v2/resource_instances/<YOUR_INSTANCE_CRN_URL_ENCODED>' \
  --header 'Authorization: Bearer <YOUR_BEARER_TOKEN>' \
  --header 'Content-Type: application/json' \
  --data '{
    "parameters": {
      "timestamp": "2026-06-30T00:00:00Z",
      "functions": [
        {
          "name": "<FUNCTION_NAME>",
          "provider": "<PROVIDER>",
          "business_model": "<BUSINESS_MODEL>",
          "permissions": [
            "function.read",
            "function.run",
            "function-files.read",
            "function-files.write"
          ]
        }
      ],
      "custom_functions": {
        "permissions": [
          "function-custom.write",
          "function-custom.run"
        ]
      }
    }
  }'

    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
from datetime import datetime, timezone

# Ang isang nagbabagong timestamp ay pumipigil sa Resource Controller mula sa pag-de-duplicate ng request.
_now = datetime.now(timezone.utc)
timestamp = _now.strftime("%Y-%m-%dT%H:%M:%S.") + f"{_now.microsecond:06d}000Z"

body = {
    "parameters": {
        "timestamp": timestamp,
        "functions": [
            {
                "name": "<FUNCTION_NAME>",
                "provider": "<PROVIDER>",
                "business_model": "<BUSINESS_MODEL>",
                "permissions": [
                    "function.read",
                    "function.run",
                    "function-files.read",
                    "function-files.write",
                ],
            }
        ],
        "custom_functions": {
            "permissions": ["function-custom.write", "function-custom.run"],
        },
    }
}

resp = requests.patch(instance_url, headers=headers, json=body, timeout=30)
resp.raise_for_status()
print(resp.json()["extensions"])
    ```
  </TabItem>
</Tabs>

Ang response na `200 OK` ay nagpapahiwatig ng tagumpay. Ang na-update na configuration ay lilitaw sa field na extensions ng response.

### I-verify ang resulta {#verify-the-result}

Para kumpirmahin na ang instance ay may tamang configuration ng Qiskit Functions, gamitin ang `GET /functions` mula sa Qiskit Runtime API sa halip na ang Resource Controller. Ang naimbak na estado ng Resource Controller ay maaaring luma na kung ang mga pagbabago sa antas ng account ay nag-update sa instance sa labas ng Resource Controller.

<Tabs>
  <TabItem value="curl" label="cURL">

    ```bash
curl --request GET \
  --url 'https://quantum.cloud.ibm.com/api/v1/functions' \
  --header 'Authorization: apikey <YOUR_API_KEY>' \
  --header 'Service-CRN: <YOUR_INSTANCE_CRN>'
    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
# Ang header na Service-CRN ay kumukuha ng raw na CRN, hindi ang URL-encoded na form.
resp = requests.get(
    ```
