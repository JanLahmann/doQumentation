This page demonstrates how to use the [`PadDynamicalDecoupling`](https://docs.quantum.ibm.com/api/qiskit/qiskit.transpiler.passes.PadDynamicalDecoupling) pass to add an error suppression technique called _dynamical decoupling_ to the circuit.

Gumagana ang dynamical decoupling sa pamamagitan ng pagdaragdag ng mga pulse sequence (kilala bilang _dynamical decoupling sequences_) sa mga idle qubit para i-flip ang mga ito sa paligid ng Bloch sphere, na nagkakansela sa epekto ng mga noise channel, sa gayon ay sinusupress ang decoherence. Ang mga pulse sequence na ito ay katulad ng mga refocusing pulse na ginagamit sa nuclear magnetic resonance. Para sa kumpletong paglalarawan, tingnan ang [A Quantum Engineer's Guide to Superconducting Qubits](https://arxiv.org/abs/1904.06560).

Dahil ang `PadDynamicalDecoupling` pass ay gumagana lamang sa mga naka-schedule na circuit at kasangkot ang mga gate na hindi kinakailangang basis gate ng ating target, kakailanganin mo rin ang mga [`ALAPScheduleAnalysis`](https://docs.quantum.ibm.com/api/qiskit/qiskit.transpiler.passes.ALAPScheduleAnalysis) at [`BasisTranslator`](https://docs.quantum.ibm.com/api/qiskit/qiskit.transpiler.passes.BasisTranslator) pass.

Kunin ang `target` information mula sa `backend` at i-save ang mga pangalan ng operation bilang `basis_gates` dahil kakailanganing i-modify ang `target` para magdagdag ng timing information para sa mga gate na ginagamit sa dynamical decoupling.

from qiskit_ibm_runtime.fake_provider import FakeSherbrooke

backend = FakeSherbrooke()

target = backend.target
basis_gates = list(target.operation_names)

Gumawa ng `efficient_su2` circuit bilang halimbawa. Una, i-transpile ang circuit papunta sa backend dahil kailangang idagdag ang mga dynamical decoupling pulse pagkatapos na ma-transpile at ma-schedule ang circuit. Ang dynamical decoupling ay kadalasang gumagana nang pinakamahusay kapag may maraming idle time sa mga quantum circuit - ibig sabihin, may mga qubit na hindi ginagamit habang aktibo ang iba. Ito ang kaso sa circuit na ito dahil ang mga two-qubit `ecr` gate ay inilalapat nang sunud-sunod sa ansatz na ito.

```python
from qiskit.transpiler import generate_preset_pass_manager
from qiskit.circuit.library import efficient_su2

qc = efficient_su2(12, entanglement="circular", reps=1)
pm = generate_preset_pass_manager(1, target=target, seed_transpiler=12345)
qc_t = pm.run(qc)
qc_t.draw("mpl", fold=-1, idle_wires=False)
```

Ang isang dynamical decoupling sequence ay isang serye ng mga gate na kung pagsasamahin ay bumubuo sa identity at pantay-pantay ang agwat sa oras. Bilang halimbawa, magsimula sa paglikha ng isang simpleng sequence na tinatawag na XY4 na binubuo ng apat na gate.

```python
from qiskit.circuit.library import XGate, YGate

X = XGate()
Y = YGate()

dd_sequence = [X, Y, X, Y]
```

Dahil sa regular na timing ng mga dynamical decoupling sequence, kailangang idagdag ang impormasyon tungkol sa `YGate` sa `target` dahil ito ay *hindi* basis gate, samantalang basis gate ang `XGate`. Alam natin *a priori* na ang `YGate` ay may parehong duration at error gaya ng `XGate`, kaya maaari lamang nating kunin ang mga property na iyon mula sa `target` at idagdag muli ang mga ito para sa mga `YGate` object. Ito rin ang dahilan kung bakit hiwalay na na-save ang `basis_gates`, dahil idinadagdag natin ang `YGate` instruction sa `target` kahit na hindi ito talagang basis gate ng `ibm_fez`.

```python
from qiskit.transpiler import InstructionProperties

y_gate_properties = {}
for qubit in range(target.num_qubits):
    y_gate_properties.update(
        {
            (qubit,): InstructionProperties(
                duration=target["x"][(qubit,)].duration,
                error=target["x"][(qubit,)].error,
            )
        }
    )

target.add_instruction(YGate(), y_gate_properties)
```

Ang mga ansatz circuit tulad ng `efficient_su2` ay parameterized, kaya kailangang may value na naka-bind sa mga ito bago ipadala sa backend. Dito, magtalaga ng mga random na parameter.

```python
import numpy as np

rng = np.random.default_rng(1234)
qc_t.assign_parameters(
    rng.uniform(-np.pi, np.pi, qc_t.num_parameters), inplace=True
)
```

Sunod, isagawa ang mga custom pass. I-instantiate ang `PassManager` gamit ang `ALAPScheduleAnalysis` at `PadDynamicalDecoupling`. Patakbuhin muna ang `ALAPScheduleAnalysis` para magdagdag ng timing information tungkol sa quantum circuit bago maidagdag ang mga pantay-pantay na dynamical decoupling sequence. Ang mga pass na ito ay pinapatakbo sa circuit gamit ang `.run()`.

```python
from qiskit.transpiler import PassManager
from qiskit.transpiler.passes.scheduling import (
    ALAPScheduleAnalysis,
    PadDynamicalDecoupling,
)

dd_pm = PassManager(
    [
        ALAPScheduleAnalysis(target=target),
        PadDynamicalDecoupling(target=target, dd_sequence=dd_sequence),
    ]
)
qc_dd = dd_pm.run(qc_t)
```

Gamitin ang visualization tool na [`timeline_drawer`](https://docs.quantum.ibm.com/api/qiskit/qiskit.visualization.timeline_drawer) para makita ang timing ng circuit at kumpirmahin na lumalabas sa circuit ang isang pantay-pantay na sequence ng mga `XGate` object at `YGate` object.

```python
from qiskit.visualization import timeline_drawer

timeline_drawer(qc_dd, idle_wires=False, target=target)
```

Sa wakas, dahil ang `YGate` ay hindi talagang basis gate ng ating backend, manu-manong ilapat ang `BasisTranslator` pass (isa itong default pass, ngunit isinasagawa ito bago ang scheduling, kaya kailangan itong ilapat muli). Ang session equivalence library ay isang library ng mga circuit equivalence na nagbibigay-daan sa transpiler na i-decompose ang mga circuit sa mga basis gate, gaya rin ng tinukoy bilang argumento.

```python
from qiskit.circuit.equivalence_library import (
    SessionEquivalenceLibrary as sel,
)
from qiskit.transpiler.passes import BasisTranslator

qc_dd = BasisTranslator(sel, basis_gates)(qc_dd)
qc_dd.draw("mpl", fold=-1, idle_wires=False)
```

Ngayon, wala na ang mga `YGate` object sa ating circuit, at may explicit na timing information sa anyo ng mga `Delay` gate. Ang na-transpile na circuit na ito na may dynamical decoupling ay handa na ngayong ipadala sa backend.
