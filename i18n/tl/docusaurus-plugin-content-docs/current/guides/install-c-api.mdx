# I-install ang Qiskit C API {#install-the-qiskit-c-api}

Inilalarawan ng gabay na ito kung paano i-install at gamitin ang Qiskit C API. Pagkatapos makumpleto ang pag-install, basahin ang [Extend Python with the Qiskit C API](/guides/c-extension-for-python).

Ang sumusunod na halimbawa ay gumagawa ng observable gamit ang C:

```c
// file: example.c
#include <stdio.h>
#include <stdint.h>
#include <qiskit.h>

int main(int argc, char *argv[]) {
    // build a 100-qubit empty observable
    uint32_t num_qubits = 100;
    QkObs *obs = qk_obs_zero(num_qubits);

    // add the term 2 * (X0 Y1 Z2) to the observable
    QkComplex64 coeff = {2, 0};
    QkBitTerm bit_terms[3] = {QkBitTerm_X, QkBitTerm_Y, QkBitTerm_Z}; 
    // bit terms: X Y Z
    uint32_t indices[3] = {0, 1, 2};  // indices: 0 1 2
    QkObsTerm term = {coeff, 3, bit_terms, indices, num_qubits};
    qk_obs_add_term(obs, &term);  // append the term

    // print some properties and the observable itself
    printf("num_qubits: %i\n", qk_obs_num_qubits(obs));
    printf("num_terms: %lu\n", qk_obs_num_terms(obs));
    printf("observable: %s\n", qk_obs_str(obs));

    // free the memory allocated for the observable
    qk_obs_free(obs);

    return 0;
}
```

## UNIX-like {#unix-like}

Ang seksyong ito ay nagbibigay ng mga tagubilin sa pag-build para sa mga UNIX-like na sistema.

### Mga Kinakailangan {#requirements}

Ang compilation ay nangangailangan ng mga sumusunod na tools:
* Isang Rust compiler: tingnan halimbawa ang [gabay sa pag-install ng Qiskit mula sa source](/guides/install-qiskit-source)
* Isang C compiler: halimbawa, GCC sa Linux at Clang sa MacOS. Ang Qiskit C API ay compatible sa isang compiler na sumusunod sa pamantayang [C11](https://en.wikipedia.org/wiki/C11_(C_standard_revision)).
* [`cbindgen`](https://github.com/mozilla/cbindgen): isang tool para gumawa ng C header, na maaari mong i-install gamit ang `cargo install cbindgen`
   Pinapahintulot ang pagpapatakbo ng tool mula sa command line, na maaaring mangailangan ng pag-export ng iyong `PATH` variable para isama ang `/path/to/.cargo/bin`.
* Naka-install na Python library (Python 3.9+): Kailangan ang Python library sa panahon ng dynamic linking. Pansinin na hindi ginagamit ang Python sa runtime at hindi kailanman ini-initialize ang interpreter; ilang simbolo lamang mula sa `libpython` ang kailangang tukuyin. Tingnan ang [isyung ito](https://github.com/Qiskit/qiskit/issues/14240) para sa karagdagang detalye.
* (GNU) Make: opsyonal ito ngunit inirerekomenda para sa mga automated na proseso ng pag-install.

Bine-verify ng code na ito na naka-install na ang lahat:

```bash
rustc --version
gcc --version
cbindgen --version
make --version  # optional, but recommended
```

### Build {#build}

Para i-build ang C header at library, maaari kang magpatakbo ng sumusunod na Make command[^1] sa Qiskit root,
[^1]: Kung hindi mo na-install ang Make, tingnan ang `Makefile` sa Qiskit root para sa mga kinakailangang command — o i-install na lang ang Make; hindi pa huli para doon.)

```bash
make c
```
na magbibigay ng compiled shared library sa `dist/c/lib` at ang `qiskit.h` header na may
lahat ng function declaration sa `dist/c/include`. Tandaan na ang eksaktong pangalan ng library ay depende
sa platform; halimbawa, `libqiskit.so` sa UNIX at `libqiskit.dylib` sa MacOS.
(Tandaan na ang hakbang na ito ay kasalukuyang naglalabas ng maraming babala, na inaasahan, at walang dapat ipag-alala. Aalisin ng mga susunod na bersyon ang mga babala.)

Maaari ka na nitong mag-compile ng C program gamit ang Qiskit C header at library:

```bash
gcc example.c -o example.o -I /path/to/dist/c/include -L /path/to/dist/c/lib -lqiskit
```
Para masiguro na mahahanap ang Qiskit library sa panahon ng linking, itakda ang runtime library path para
isama ang `/path/to/dist/c/lib`. Kung ang Python library ay hindi available bilang default sa panahon ng dynamic linking,
kailangan din itong idagdag. Ang mga command na ito ay depende sa platform. Sa Linux:

```bash
export LD_LIBRARY_PATH=/path/to/dist/c/lib:$LD_LIBRARY_PATH
# On Linux, the Python library is typically included 
# in the dynamic library path by default.
export LD_LIBRARY_PATH=/path/to/python/lib:$LD_LIBRARY_PATH
```
Sa MacOS:

```bash
export DYLD_LIBRARY_PATH=/path/to/dist/c/lib:$DYLD_LIBRARY_PATH
export DYLD_LIBRARY_PATH=/path/to/python/lib:$DYLD_LIBRARY_PATH
```
Bilang alternatibo, maaari mong itakda ang runtime library path sa panahon ng compilation sa pamamagitan ng pagdaragdag ng

```
-Wl,-rpath,/path/to/dist/c/lib
# same for Python
```
sa mga compiler flag.
Bukod pa rito, kailangan na available ang Python library sa panahon ng dynamic linking. Sa mga Linux environment
ito ay karaniwang default.

Maaari ka na ngayong i-execute ang binary:

```bash
./example.o
```
na, kung gagamitin ang halimbawang snippet na ipinakita kanina, ay dapat mag-print ng

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```

## Windows {#windows}

Ang seksyong ito ay nagbibigay ng mga tagubilin sa pag-build para sa mga Windows system.

May dalawang magkahiwalay na paraan upang gamitin ang C API sa Windows:

* **Bumuo ng Python extension modules** na gumagamit ng Qiskit C API. Sundan ang Steps 1-5. Ang landas na ito ay gumagamit ng mga C header na kasama sa `qiskit` Python package at hindi nangangailangan ng Rust o cbindgen.

* **Bumuo ng standalone C library** upang i-link mula sa isang purong C program, tulad ng ginagawa sa [UNIX-like](#unix) section. Kumpletuhin ang Step 1, pagkatapos ay lumaktaw sa [Build the standalone library](#build-the-standalone-library), na naglilista ng mga karagdagang requirement nito.


### Mga Kinakailangan {#requirements-1}

- Kinakailangan ang mga karapatan bilang administrator para sa ilang hakbang.

- 5-8 GB na libreng disk space.

- Isang C compiler: Microsoft Visual C++ (MSVC), na na-install sa Step 1.

- Isang 64-bit na Python installation (3.10 o mas bago), na na-install sa Step 1.


### Bago ka magsimula {#before-you-begin}

Gumawa ng iyong workspace.  Dapat itong maikling path sa isang local drive. Huwag gumamit ng mga OneDrive-synced na folder (tulad ng Documents o Desktop), network drives, o mga path na may spaces o non-ASCII na mga character. Kung ang iyong username ay naglalaman ng non-English na mga character, huwag ilagay ito sa ilalim ng iyong user folder.

Mga halimbawa ng magandang workspace paths: `C:\workspace`, `D:\workspace`, `C:\Users\john\workspace`

### Hakbang 3 - I-load ang MSVC environment {#step-3-load-the-msvc-environment}

Patakbuhin ang sumusunod na code sa bawat bagong Python session (halimbawa, sa tuwing nire-restart mo ang isang Jupyter kernel). Awtomatiko nitong hinahanap at nilo-load ang MSVC developer environment kaya hindi mo na kailangan ang built-in na x64 command prompt.

Bumubuo ang halimbawa sa dokumentasyong ito ng mga C extension module gamit ang `setuptools` kasama ang MSVC. Sa pangkalahatan, dine-define mo ang `QISKIT_PYTHON_EXTENSION`, isinasama ang `qiskit.h`, at tinatawag ang `qk_import()` sa iyong init function. Mga header lang mula sa `qiskit.capi.get_include()` ang kailangan sa build time — walang naka-link na library. Tingnan ang [Extend Qiskit in Python with C](/guides/c-extension-for-python) para sa mga detalye.

<Accordion>
  <AccordionItem title="I-load ang MSVC environment">

```python
import os, sys, subprocess, glob, shutil

def load_msvc_env():
    if os.name != "nt":
        return "Not Windows — the system C compiler is used as-is."
    if shutil.which("cl"):
        return "cl.exe is already available in this kernel."

    pf86 = os.environ.get("ProgramFiles(x86)", r"C:\Program Files (x86)")
    pf = os.environ.get("ProgramFiles", r"C:\Program Files")
    vcvars = None

    vswhere = os.path.join(pf86, "Microsoft Visual Studio", "Installer", "vswhere.exe")
    if os.path.isfile(vswhere):
        # vswhere outputs UTF-8 regardless of system locale
        inst = subprocess.run(
            [vswhere, "-latest", "-products", "*",
             "-requires", "Microsoft.VisualStudio.Component.VC.Tools.x86.x64",
             "-property", "installationPath"],
            capture_output=True, text=True, encoding="utf-8").stdout.strip()
        if inst:
            cand = os.path.join(inst, "VC", "Auxiliary", "Build", "vcvars64.bat")
            if os.path.isfile(cand):
                vcvars = cand

    if not vcvars:
        pat = os.path.join("Microsoft Visual Studio", "*", "*",
                           "VC", "Auxiliary", "Build", "vcvars64.bat")
        hits = glob.glob(os.path.join(pf86, pat)) + glob.glob(os.path.join(pf, pat))
        if hits:
            vcvars = sorted(hits)[-1]

    if not vcvars:
        return ("Could not find vcvars64.bat. Install MSVC Build Tools (Step 1.3), "
                "or launch Jupyter from the x64 Native Tools Command Prompt.")

    # cmd.exe outputs in the OEM codepage (cp437/cp850/etc.), not the ANSI codepage
    out = subprocess.run(f'"{vcvars}" >nul 2>&1 && set',
                         capture_output=True, text=True, encoding="oem", shell=True).stdout
    for line in out.splitlines():
        if "=" in line:
            k, _, v = line.partition("=")
            os.environ[k] = v

    return ("Loaded MSVC from:\n  " + vcvars) if shutil.which("cl") \
        else "Ran vcvars64.bat but cl.exe is still not found — check your MSVC install."

print(load_msvc_env())
print("cl.exe on PATH:", shutil.which("cl") is not None)
```

### Hakbang 4 - Smoke test: Bumuo ng C extension {#step-4-smoke-test-build-a-c-extension}

Patakbuhin ang sumusunod na code.  Isinusulat nito ang mga source file sa `_smoke_pkg/`, bumubuo ng C extension laban sa Qiskit C API, at ini-import ang resulta. Kung nag-print ito ng "SMOKE TEST PASSED", handa na ang iyong toolchain.

Sinusunod ng package ang proseso ng [Extend Qiskit in Python with C](/guides/c-extension-for-python) at gumagamit ng mga function mula sa [Qiskit C API reference](https://docs.quantum.ibm.com/api/qiskit-c).

<Accordion>
  <AccordionItem title="Smoke test na code">

```python
import sys, subprocess, pathlib, importlib

root = pathlib.Path("_smoke_pkg")
pkg = root / "src" / "qgss_smoke"
pkg.mkdir(parents=True, exist_ok=True)

(root / "pyworkspace.toml").write_text("""
[build-system]
requires = ["setuptools", "qiskit>=2.4.2"]
build-backend = "setuptools.build_meta"

[workspace]
name = "qgss_smoke"
version = "0.0.1"
dependencies = ["qiskit>=2.4.2"]

[tool.setuptools]
package-dir = {"" = "src"}
""".lstrip())

(root / "setup.py").write_text("""
import qiskit
from setuptools import setup, Extension

core_ext = Extension(
    name="qgss_smoke._core",
    sources=["src/qgss_smoke/_coremodule.c"],
    include_dirs=[qiskit.capi.get_include()],
)
setup(ext_modules=[core_ext])
""".lstrip())

(pkg / "__init__.py").write_text("from . import _core\nbuild_demo = _core.build_demo\n")

(pkg / "_coremodule.c").write_text("""
#define QISKIT_PYTHON_EXTENSION
#include <Python.h>
#include <qiskit.h>
#include <stdint.h>

static PyObject *build_demo(PyObject *self, PyObject *args) {
    QkCircuit *qc = qk_circuit_new(2, 0);
    uint32_t q0[1] = {0};
    qk_circuit_gate(qc, QkGate_H, q0, NULL);
    uint32_t q1[1] = {1};
    qk_circuit_gate(qc, QkGate_X, q1, NULL);
    return qk_circuit_to_python_full(qc);
}

static PyMethodDef core_methods[] = {
    {"build_demo", build_demo, METH_NOARGS, "Build a 2-qubit demo circuit in C."},
    {NULL, NULL, 0, NULL},
};
static struct PyModuleDef core_module = {
    .m_base = PyModuleDef_HEAD_INIT,
    .m_name = "_core",
    .m_methods = core_methods,
};
PyMODINIT_FUNC PyInit__core(void) {
    if (qk_import() < 0) {
        return NULL;
    }
    return PyModuleDef_Init(&core_module);
}
""".lstrip())

# On Windows, an imported .pyd is file-locked by the OS. Drop the module from
# sys.modules BEFORE pip install --force-reinstall, otherwise pip fails with
# WinError 32 ("file in use") trying to overwrite the locked .pyd.
if "qgss_smoke._core" in sys.modules:
    del sys.modules["qgss_smoke._core"]
if "qgss_smoke" in sys.modules:
    del sys.modules["qgss_smoke"]

r = subprocess.run(
    [sys.executable, "-m", "pip", "install", "--no-build-isolation",
     "--force-reinstall", "--quiet", str(root.resolve())],
    capture_output=True, text=True,
)
if r.returncode != 0:
    output = (r.stderr + r.stdout).strip()
    print("BUILD FAILED:\n")
    print(output)
    if "WinError 32" in output or "being used by another process" in output:
        print("\n--- TIP ---")
        print("The .pyd file is locked because it was previously imported in this kernel.")
        print("Restart the kernel (Ctrl+Shift+P → 'Jupyter: Restart Kernel'), then rerun")
        print("the Step 3 MSVC cell first, then this cell again.")
    elif "cl.exe" in output.lower() or "vcvars" in output.lower() or "cannot find" in output.lower():
        print("\n--- TIP ---")
        print("The compiler was not found. rerun the Step 3 cell to load the MSVC environment.")
else:
    importlib.invalidate_caches()
    import qgss_smoke
    from qiskit import QuantumCircuit

    qc = qgss_smoke.build_demo()
    ops = dict(qc.count_ops())
    ok = isinstance(qc, QuantumCircuit) and ops.get("h") == 1 and ops.get("x") == 1

    print("Returned object is a QuantumCircuit:", isinstance(qc, QuantumCircuit))
    print("Gates built in C:", ops)
    print("\nSMOKE TEST PASSED — your Windows toolchain can build Qiskit C extensions."
          if ok else "\nSomething is off — check the gates above.")
```

### Buuin ang standalone library {#build-the-standalone-library}

Bumubuo ang seksyong ito ng standalone C library, na kailangan lamang kung gusto mong i-compile at i-link ang mga purong C program, tulad ng inilarawan sa seksyong [UNIX-like](#unix). Bilang karagdagan sa mga prerequisite sa Hakbang 1, kailangan nito ang sumusunod na mga tool:

* Isang Rust compiler: tingnan halimbawa ang [gabay sa pag-install ng Qiskit mula sa source](https://github.com/Qiskit/qiskit/blob/main/CONTRIBUTING.md#installing-qiskit-from-source)

* [`cbindgen`](https://github.com/mozilla/cbindgen): isang tool para gumawa ng C header, na maaari mong i-install gamit ang `cargo install cbindgen`.
    Dapat pinagana ang pagpapatakbo ng tool mula sa command line, na maaaring mangailangan ng pag-update sa iyong `PATH` variable upang isama ang cargo path.
* Isang Python installation na may access sa parehong ``python3.lib`` at ``python3.dll``
* Isang clone ng [Qiskit repository](https://github.com/Qiskit/qiskit) (`git clone https://github.com/Qiskit/qiskit.git`)
<Accordion>
<AccordionItem title="Buuin ang standalone library">
Una, i-compile ang `qiskit_cext` dynamic library, sa pamamagitan ng pagpapatakbo ng sumusunod sa VS Code (PowerShell) terminal sa Qiskit root:

```powershell
$env:PATH = "\path\to\pythonlib;" + $env:PATH
cargo rustc --release --crate-type cdylib -p qiskit-cext
```
Gagawa ito ng ``.dll`` dynamic library at ang kasamang ``.dll.lib`` file sa `target/release`.
Susunod, gumawa ng header gamit ang

```powershell
cbindgen --crate qiskit-cext --output dist\c\include\qiskit.h
```
Isinusulat nito ang MSVC-compatible na header sa ``dist\c\include``.

Maaari ka na ngayong gumamit ng `cl` para i-compile ang C program. Para masiguro na mahahanap ng compiler ang qiskit library,
isasama natin ang `target\release` sa `PATH` variable.

```powershell
$env:PATH = "\path\to\target\release;" + $env:PATH
cl example.c qiskit_cext.dll.lib -I\path\to\dist\c\include
```

Bago patakbuhin, isama ang path sa iyong ``python3.dll``.

```powershell
$env:PATH = "\path\to\python3-dll;" + $env:PATH
.\example.exe
```
ay dapat na mag-print ng

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```
</AccordionItem>
</Accordion>

### Pag-troubleshoot {#troubleshooting}
<Accordion>
<AccordionItem title="Hindi nakikilala ang `winget`">
I-update ang [App Installer](https://apps.microsoft.com/detail/9nblggh4nns1) mula sa Microsoft Store, o gamitin ang kaugnay na mga manual na link sa pag-download
</AccordionItem>
<AccordionItem title="Hindi nakikilala ang `cl`">
Patakbuhin ulit ang MSVC load cell (Hakbang 3), o gamitin ang x64 Native Tools Command Prompt
</AccordionItem>
<AccordionItem title="Binubuksan ng `python` ang Microsoft Store">
Pumunta sa Settings → Apps → Advanced app settings → App execution aliases at i-off ang `python.exe`
</AccordionItem>
<AccordionItem title="`.ps1 cannot be loaded` / naka-disable ang mga script">
Patakbuhin ang `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` pagkatapos ay subukan ulit
</AccordionItem>
<AccordionItem title="`cannot open file 'qiskit.h'`">
Patakbuhin ang `python -c "import qiskit.capi; print(qiskit.capi.get_include())"` at kumpirmahin na umiiral ang path
</AccordionItem>
<AccordionItem title="Hindi mahanap ang `qiskit.capi`">
Patakbuhin ang `pip install "qiskit[visualization]~=2.4.2"`
</AccordionItem>
<AccordionItem title="Nabigo ang build ng `qiskit-aer`">
Patakbuhin ang `pip install qiskit-aer --only-binary=:all:`. Kung nabigo rin iyon, gamitin ang Python 3.12 o laktawan ang aer, na opsyonal
</AccordionItem>
<AccordionItem title="Tumatakbo ang build ngunit nabigo ang import dahil sa version error">
Ang binuong Qiskit C extension at ang na-install na bersyon ng Qiskit ay dapat magkaparehong bersyon.  I-reinstall ang Qiskit gamit ang `pip install "qiskit~=2.4.2"`
</AccordionItem>
<AccordionItem title="Muli kong binuo ang C ngunit hindi nagbago ang circuit">
Hindi maaaring i-re-import nang live ang isang C extension. I-restart ang kernel, patakbuhin ulit ang mga MSVC command (Hakbang 3), pagkatapos ay muling buuin
</AccordionItem>
<AccordionItem title="Na-block ang PowerShell script">
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
</AccordionItem>
<AccordionItem title="Mga error sa haba ng path">
Gumamit ng maikling root path sa C:\ (halimbawa, `C:\workspace`, o ang path na itinakda mo sa hakbang ng setup), o paganahin ang Long Paths: Settings → System → For developers → Long Paths
</AccordionItem>
<AccordionItem title="Aktibo ang Conda (ipinapakita ng prompt ang `(base)`) o kakaiba ang kilos ng mga build pagkatapos gumamit ng Anaconda">
Patakbuhin ang `conda deactivate` hanggang mawala ang parehong `CONDA_DEFAULT_ENV` at `CONDA_PREFIX` mula sa environment. Suriin gamit ang `$env:CONDA_PREFIX`. Kung nagpapatuloy pa rin ang mga ito, magbukas ng bagong PowerShell (hindi Anaconda prompt) at subukan ulit mula sa Hakbang 2.
</AccordionItem>
<AccordionItem title="Ginawa ang virtual environment mula sa isang conda-managed na Python (tingnan ang linyang `home =` sa `.venv\pyvenv.cfg`)">
Namana ng virtual environment ang C runtime ng conda at hindi ito maaaring ayusin sa lugar. Burahin ito, i-download ang Python 3.12 mula sa [Python](https://www.python.org/downloads/) website, at muling buuin. Patakbuhin ang `Remove-Item -Recurse -Force .venv`, pagkatapos ay patakbuhin ulit ang Python detection snippet sa Hakbang 1 upang itakda ang `$PYTHON_EXE`, pagkatapos ay gawin ulit ang virtual environment (Hakbang 2).
</AccordionItem>
<AccordionItem title="`DLL load failed` sa import">
Malamang na tumatagas ang Conda sa virtual environment. Suriin ang dalawang isyu na kasunod nito sa itaas. I-verify din na 64-bit ang Python: `python -c "import platform; print(platform.architecture())"`
</AccordionItem>
<AccordionItem title="Nabigo ang build na may sirang mga path o `C1083`">
Naglalaman ang iyong username o workspace path ng mga non-ASCII na character. Ilipat ang workspace sa maikling ASCII-only na path (halimbawa, `C:\workspace`)
</AccordionItem>
<AccordionItem title="Random na nabibigo ang build o import, gumagana sa muling pagsubok">
Naka-sync ang workspace folder gamit ang OneDrive. Ilipat ito sa lokal na path tulad ng `C:\workspace`
</AccordionItem>
<AccordionItem title="Naantala ang build sa gitna (halimbawa, nagkaroon ng power loss)">
Burahin ang `_smoke_pkg` folder sa iyong workspace, patakbuhin ulit ang MSVC load cell, pagkatapos ay patakbuhin ulit ang smoke test cell
</AccordionItem>
<AccordionItem title="Nabigo ang `pip install` dahil sa SSL certificate error">
Gumagamit ang iyong network ng proxy na humaharang sa HTTPS. Subukang patakbuhin ang `pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org qiskit` o hilingin sa iyong network administrator ang proxy CA certificate
</AccordionItem>
<AccordionItem title="Kina-quarantine ng Windows Defender ang `.pyd` file">
Idagdag ang `.venv` at `_smoke_pkg` folder ng iyong workspace sa Defender exclusions sa pamamagitan ng pagpunta sa Windows Security → Virus & threat protection → Manage settings → Exclusions
</AccordionItem>
<AccordionItem title="Hindi ma-install ang VS Build Tools (walang admin rights)">
Kinakailangan ang administrator access. Hilingin sa iyong IT department ang access
</AccordionItem>
<AccordionItem title="`WinError 32` / ginagamit ang file habang muling binubuo">
Naka-lock ang .pyd ng tumatakbong kernel. I-restart ang kernel (Ctrl+Shift+P → Jupyter: Restart Kernel), patakbuhin ulit ang Hakbang 3, pagkatapos ay muling buuin
</AccordionItem>
<AccordionItem title="Tahimik na walang ginagawa ang mga command (walang error, walang output)">
Maaaring nasa cmd.exe ka sa halip na PowerShell. Suriin ang iyong prompt: ipinapakita ng PowerShell ang `PS C:\>`, ipinapakita ng cmd ang `C:\>`. Buksan ang PowerShell mula sa Start Menu o Win+X
</AccordionItem>
<AccordionItem title="Mukhang natigil ang pag-install ng MSVC">
Hinaharang ng mga flag na `--passive --wait` ang PowerShell habang tumatakbo ang installer sa background. Suriin ang iyong taskbar para sa isang "Visual Studio Installer" na window. Maaaring umabot ng 10-30 minuto ang pag-install
</AccordionItem>
</Accordion>
