## I-monitor ang isang job {#monitor-a-job}

Gamitin ang mga method na ito para suriin ang status ng iyong mga isinumiteng job, kunin ang mga resulta, at tingnan ang mga detalye na kaugnay ng job at ng pagpapatakbo nito.

<Tabs>
    <TabItem value="Qiskit" label="Monitor a job with Qiskit">
        Nagbibigay ang job instance ng ilang method para sa pagsubaybay:

        | Method | Description |
        | --- | --- |
        | `job.status()` | Check the current job status |
        | `job.job_id()` | Get the unique job identifier |
        | `job.result()` | Retrieve job results (blocking call until complete) |
        | `job.wait_for_final_state()` | Block until the job reaches a terminal state |

        
    </TabItem>
    <TabItem value="IQP" label="Monitor a job on IBM Quantum Platform">

        - **Pending**: Job is waiting to run on a QPU
        - **In progress**: Job is currently executing
        - **Completed**: Job finished successfully
        - **Failed**: Job encountered an error
        - **Canceled**: User canceled the job

        I-click ang job name o row para buksan ang detailed view, kung saan makikita mo ang impormasyon tulad ng mga resulta at anumang mga error message.

### Bakit nananatiling "In progress" ang isang job {#why-a-job-stays-in-progress}

Mapapansin mo na ang isang job (gamit man ang job mode o batch mode) na inaasahan mong ilang segundo lang ang tatagal ay nananatili sa **In progress** status (tinatawag na `RUNNING` sa Qiskit) nang mas matagal. Normal ito, at hindi ito nangangahulugan na ginagamit ng job ang buong oras na iyon bilang usage. Nangyayari ito dahil sa kung paano naka-iskedyul ang mga job papunta sa isang QPU:

- Kailangan ng bawat job ng classical pre-processing bago ito makapagpatakbo sa QPU. Ang isang job ay lumilipat sa **In progress** (`RUNNING`) sa sandaling magsimula ang classical processing na ito — hindi kapag nagsisimula itong mag-execute sa QPU.

- Karamihan sa classical processing na ito ay tumatakbo nang parallel, kaya maaaring **In progress** ang maraming job nang sabay-sabay.

- Gayunpaman, isang job lang sa isang pagkakataon ang maaaring tumakbo sa QPU. Kapag natapos na ng ilang job ang kanilang classical processing at handa nang mag-execute, kailangan nilang maghintay ng turno para sa QPU. Ito ay tinatawag na *QPU contention*. Kapag mataas ang contention, maaaring manatiling **In progress** ang isang job nang mas matagal kumpara sa ilang segundong QPU time na talagang kailangan nito.

- Maaari ring mangyari ang contention kapag may tumatakbong system-maintenance task, tulad ng calibration, sa QPU. Mananatiling **In progress** ang iyong job hanggang matapos ang maintenance task at maging available ang QPU.


Dahil dito, ang naubos na wall-clock time ng isang job habang **In progress** ay hindi katumbas ng usage nito. Ang parehong [estimated usage](/guides/estimate-job-run-time) at [maximum execution time](/guides/max-execution-time) ay batay lamang sa oras na naka-lock ang QPU para i-execute ang iyong job, at dahil dito hindi kasama ang multi-threaded classical processing na inilarawan sa itaas. Ang mahabang **In progress** na oras ay hindi nagpapataas ng iyong naiuulat na usage o gastos.

#### Iba ang session mode {#session-mode-is-different}

Ang naunang paguugali ay naaangkop sa [job mode](/guides/execution-modes#job-mode) at [batch mode](/guides/execution-modes#batch-mode). Sa [session mode](/guides/execution-modes#session-mode), sa panahon ng active window ng session, eksklusibong access lang ang mayroon ang user sa backend at walang ibang job ang maaaring tumakbo, kabilang ang mga calibration job. Dahil dito, ang anumang QPU contention ay nangyayari lamang sa pagitan ng iyong sariling mga session job. Bukod dito, dahil nakareserba ang QPU capacity sa buong tagal ng session, ang session usage ay sinusukat bilang naubos na oras habang aktibo ang session, anuman ang status ng mga tumatakbong job. Tingnan ang [Workload usage](/guides/estimate-job-run-time#usage) para sa karagdagang impormasyon.

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve a job by ID
job = service.job("<job_id>")

# Get job ID (useful for saving for later retrieval)
print(f"Job ID: {job.job_id()}")

# Check current status
print(f"Status: {job.status()}")

# Wait for job to complete (blocking call)
job.wait_for_final_state()
print("Job completed")

# Get results
results = job.result()
print(results)
```

## Tingnan ang mga metrics ng job {#view-job-metrics}

Kumuha ng overview ng iyong mga pagsumite ng job, kabilang ang batch at session workload metrics.

<Tabs>
    <TabItem value="Qiskit" label="Get job metrics with Qiskit">
        Gamitin ang [`service.jobs()`](https://docs.quantum.ibm.com/api/qiskit-ibm-runtime/qiskit-runtime-service#jobs)  method na may mga filter para makuha ang impormasyon tungkol sa iyong mga isinumiteng job, tulad ng kung ilan ang naisumite, ano ang kanilang status, at kailan sila ginawa. Ang sumusunod na halimbawa ay kumukuha ng lahat ng job na isinumite sa nakaraang pitong araw at kinakalkula ang kabuuang usage mula sa mga job na iyon.

        
    </TabItem>
    <TabItem value="IQP" label="View job metrics on IBM Quantum Platform">
        Pumunta sa [Analytics page](https://quantum.cloud.ibm.com/analytics) para makita at ma-download ang data, tulad ng mga sumusunod:
        - Total usage
        - Usage filtered by instance, quantum computer, and user
        - Count of job, batch, and session workloads

        **Tandaan**: Maa-access mo lang ang Analytics page para sa mga account na pagmamay-ari mo o pinapamahalaan mo.
    </TabItem>
</Tabs>

```python
from datetime import datetime, timedelta
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve all jobs in the last 7 days
seven_days_ago = datetime.now() - timedelta(days=7)
jobs = service.jobs(limit=None, created_after=seven_days_ago)

# To retrieve all jobs in a Session or Batch, use the session_id filter
# jobs = service.jobs(session_id="<session id>")

total_usage = 0
for job in jobs:
    total_usage += job.usage()

print(f"{len(jobs)} jobs were submitted in the last 7 days.")
print(f"Total usage was {total_usage} seconds")
```

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Uncomment the next line to retrieve a specific job by ID
# job = service.job("<job_id>")

# Optionally retrieve multiple jobs with filters
# Use `limit` to retrieve a specific number of jobs. The default `limit` is 10.
my_backend = "<your-backend>"
recent_jobs = service.jobs(backend_name=my_backend, limit=10)

print(f"Retrieved {len(recent_jobs)} recent jobs from {my_backend}\n")

# Get results from all jobs
for job in recent_jobs:
    print(f"Job ID: {job.job_id()}")
    print(f"Status: {job.status()}")

    # Retrieve results if the job is complete
    if str(job.status()) == "DONE":
        try:
            results = job.result()
            print(f"Results: {results}")
        except Exception as e:
            print(f"Error retrieving results: {e}")
    else:
        print("Results: Not available (job still running or failed)")
    print()
```

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve a specific job by ID
job = service.job("<job_id>")

print(f"Job ID: {job.job_id()}")
print(f"Backend: {job.backend}\n")

# Fetch backend properties at the time of job execution
properties = job.properties()

if properties:
    print("Backend Properties at Job Execution Time:")
    print("=" * 60)

    # Get T1 (relaxation time) for qubit 0
    t1 = properties.t1(0)
    print(f"Qubit 0 T1 (relaxation time): {t1}")

    # Get T2 (dephasing time) for qubit 0
    t2 = properties.t2(0)
    print(f"Qubit 0 T2 (dephasing time): {t2}")

    # Get readout error for qubit 0
    readout_error = properties.readout_error(0)
    print(f"Qubit 0 readout error: {readout_error}")

    # Get all properties for a specific qubit
    print("All properties for qubit 0:")
    qubit_props = properties.qubit_property(0)
    for prop_name, prop_value in qubit_props.items():
        print(f"  {prop_name}: {prop_value}")
else:
    print("No properties available for this job")
```

## I-cancel ang isang job {#cancel-a-job}

Kanselahin ang isang job na naka-queue o tumatakbo. Kapag nakansela na ang isang job, hindi na ito maaaring ipagpatuloy.

<Tabs>
    <TabItem value="Qiskit" label="Cancel with Qiskit">
        Gamitin ang `job.cancel()` method para kanselahin ang isang job nang programmatic.

        
    </TabItem>
    <TabItem value="IQP" label="Cancel on IBM Quantum Platform">
        1. **From the workloads table**: I-click ang overflow menu sa dulo ng row para sa workload na gusto mong kanselahin, at piliin ang **Cancel**.
        2. **From the job details page**: I-click ang workload para buksan ang details page nito, gamitin ang **Actions** dropdown sa itaas, at piliin ang **Cancel**.
    </TabItem>
</Tabs>

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve the job
job = service.job("<job_id>")

# Cancel the job
job.cancel()

print(f"Job {job.job_id()} has been canceled")
```
