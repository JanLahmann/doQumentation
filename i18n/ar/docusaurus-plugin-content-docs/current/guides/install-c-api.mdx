# تثبيت واجهة برمجة التطبيقات C الخاصة بـ Qiskit {#install-the-qiskit-c-api}

يصف هذا الدليل كيفية تثبيت واجهة برمجة التطبيقات C الخاصة بـ Qiskit واستخدامها. بعد اكتمال التثبيت، اقرأ [توسيع Python بواجهة برمجة التطبيقات C لـ Qiskit](/guides/c-extension-for-python).

المثال التالي يبني observable باستخدام C:

```c
// file: example.c
#include <stdio.h>
#include <stdint.h>
#include <qiskit.h>

int main(int argc, char *argv[]) {
    // build a 100-qubit empty observable
    uint32_t num_qubits = 100;
    QkObs *obs = qk_obs_zero(num_qubits);

    // add the term 2 * (X0 Y1 Z2) to the observable
    QkComplex64 coeff = {2, 0};
    QkBitTerm bit_terms[3] = {QkBitTerm_X, QkBitTerm_Y, QkBitTerm_Z}; 
    // bit terms: X Y Z
    uint32_t indices[3] = {0, 1, 2};  // indices: 0 1 2
    QkObsTerm term = {coeff, 3, bit_terms, indices, num_qubits};
    qk_obs_add_term(obs, &term);  // append the term

    // print some properties and the observable itself
    printf("num_qubits: %i\n", qk_obs_num_qubits(obs));
    printf("num_terms: %lu\n", qk_obs_num_terms(obs));
    printf("observable: %s\n", qk_obs_str(obs));

    // free the memory allocated for the observable
    qk_obs_free(obs);

    return 0;
}
```

## أنظمة شبيهة بـ UNIX {#unix-like}

يوفر هذا القسم تعليمات البناء للأنظمة الشبيهة بـ UNIX.

### المتطلبات {#requirements}

يستلزم التصريف الأدوات التالية:
* مُصرِّف Rust: راجع على سبيل المثال [دليل تثبيت Qiskit من المصدر](/guides/install-qiskit-source)
* مُصرِّف C: على سبيل المثال، GCC على Linux وClang على MacOS. واجهة برمجة التطبيقات C لـ Qiskit متوافقة مع أي مُصرِّف يلتزم بمعيار [C11](https://en.wikipedia.org/wiki/C11_(C_standard_revision)).
* [`cbindgen`](https://github.com/mozilla/cbindgen): أداة لإنشاء رأس C، يمكنك تثبيتها بتشغيل `cargo install cbindgen`
    تشغيل الأداة من سطر الأوامر يجب أن يكون مفعّلاً، وهو ما قد يستلزم تصدير متغير `PATH` ليشمل `/path/to/.cargo/bin`.
* مكتبة Python مثبّتة (Python 3.9 أو أحدث): مكتبة Python مطلوبة أثناء الربط الديناميكي. لاحظ أن Python لا تُستخدم أثناء التشغيل ولا يُهيَّأ المُفسِّر أبدًا؛ كل ما يلزم هو تعريف بعض الرموز من `libpython`. اطلع على [هذه المسألة](https://github.com/Qiskit/qiskit/issues/14240) لمزيد من التفاصيل.
* (GNU) Make: هذا اختياري لكنه مُوصى به لاستخدام عمليات التثبيت الآلية.

يتحقق هذا الكود من تثبيت كل شيء بشكل صحيح:

```bash
rustc --version
gcc --version
cbindgen --version
make --version  # optional, but recommended
```

### البناء {#build}

لبناء رأس C والمكتبة، يمكنك تشغيل أمر Make التالي[^1] في المجلد الجذر لـ Qiskit،
[^1]: إن لم تثبت Make، اطلع على ملف `Makefile` في المجلد الجذر لـ Qiskit للاطلاع على الأوامر المطلوبة - أو ببساطة قم بتثبيت Make؛ لم يفت الأوان.)

```bash
make c
```
مما سيوفر المكتبة المشتركة المُصرَّفة في `dist/c/lib` ورأس `qiskit.h` مع جميع تعريفات الدوال في `dist/c/include`. لاحظ أن الاسم الدقيق للمكتبة يعتمد على المنصة؛ على سبيل المثال، `libqiskit.so` على UNIX و`libqiskit.dylib` على MacOS.
(لاحظ أن هذه الخطوة تُصدر حاليًا عددًا كبيرًا من التحذيرات، وهذا أمر متوقع ولا داعي للقلق منه. ستزيل الإصدارات المستقبلية هذه التحذيرات.)

يمكنك بعد ذلك تصريف برنامج C باستخدام رأس ومكتبة Qiskit C:

```bash
gcc example.c -o example.o -I /path/to/dist/c/include -L /path/to/dist/c/lib -lqiskit
```
لضمان العثور على مكتبة Qiskit أثناء الربط، قم بتعيين مسار مكتبة وقت التشغيل ليشمل `/path/to/dist/c/lib`. إذا لم تكن مكتبة Python متاحة افتراضيًا أثناء الربط الديناميكي، فيجب إضافتها أيضًا. تعتمد هذه الأوامر على المنصة. على Linux:

```bash
export LD_LIBRARY_PATH=/path/to/dist/c/lib:$LD_LIBRARY_PATH
# On Linux, the Python library is typically included 
# in the dynamic library path by default.
export LD_LIBRARY_PATH=/path/to/python/lib:$LD_LIBRARY_PATH
```
على MacOS:

```bash
export DYLD_LIBRARY_PATH=/path/to/dist/c/lib:$DYLD_LIBRARY_PATH
export DYLD_LIBRARY_PATH=/path/to/python/lib:$DYLD_LIBRARY_PATH
```
بدلًا من ذلك، يمكنك تعيين مسار مكتبة وقت التشغيل أثناء التصريف بإضافة

```
-Wl,-rpath,/path/to/dist/c/lib
# same for Python
```
إلى خيارات المُصرِّف.
بالإضافة إلى ذلك، يجب أن تكون مكتبة Python متاحة أثناء الربط الديناميكي. في بيئات Linux هذا هو الإعداد الافتراضي عادةً.

الآن يمكنك تنفيذ الملف الثنائي:

```bash
./example.o
```
الذي، إن كنت تستخدم مقطع الكود السابق، يجب أن يطبع

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```

## Windows {#windows}

يوفر هذا القسم تعليمات البناء لأنظمة Windows.

هناك طريقتان مستقلتان لاستخدام واجهة برمجة التطبيقات C على Windows:

* **بناء وحدات امتداد Python** التي تستخدم واجهة برمجة التطبيقات C الخاصة بـ Qiskit. اتبع الخطوات من 1 إلى 5. يستخدم هذا المسار ملفات ترويسة C المرفقة مع حزمة Python الخاصة بـ `qiskit` ولا يتطلب Rust أو cbindgen.

* **بناء مكتبة C المستقلة** للربط بها من برنامج C خالص، كما يتم في القسم [الشبيه بـ UNIX](#unix). أكمل الخطوة 1، ثم انتقل إلى [بناء المكتبة المستقلة](#build-the-standalone-library)، التي تسرد متطلباتها الإضافية.


### المتطلبات {#requirements-1}

- مطلوبة صلاحيات المسؤول لبعض الخطوات.

- مساحة قرص فارغة من 5 إلى 8 غيغابايت.

- مترجم C: Microsoft Visual C++‏ (MSVC)، مثبَّت في الخطوة 1.

- تثبيت Python 64-بت (3.10 أو أحدث)، تم تثبيته في الخطوة 1.


### قبل أن تبدأ {#before-you-begin}

أنشئ مساحة العمل الخاصة بك. يجب أن يكون هذا مساراً قصيراً على محرك أقراص محلي. لا تستخدم المجلدات المتزامنة مع OneDrive (مثل المستندات أو سطح المكتب)، أو محركات الأقراص الشبكية، أو المسارات التي تحتوي على مسافات أو أحرف غير ASCII. إذا كان اسم المستخدم الخاص بك يحتوي على أحرف غير إنجليزية، فلا تضعه ضمن مجلد المستخدم الخاص بك.

أمثلة على مسارات مساحة عمل جيدة: `C:\workspace`، `D:\workspace`، `C:\Users\john\workspace`

### الخطوة 3 - تحميل بيئة MSVC {#step-3-load-the-msvc-environment}

شغِّل الكود التالي في كل جلسة Python جديدة (على سبيل المثال، في كل مرة تعيد فيها تشغيل نواة Jupyter). يعثر على بيئة تطوير MSVC ويحمِّلها تلقائياً حتى لا تحتاج إلى موجه الأوامر المدمج x64.

يبني المثال في هذه الوثائق وحدات امتداد C باستخدام `setuptools` مع MSVC. بشكل عام، تعرِّف `QISKIT_PYTHON_EXTENSION`، وتضمِّن `qiskit.h`، وتستدعي `qk_import()` في دالة init الخاصة بك. تحتاج فقط إلى ترويسات من `qiskit.capi.get_include()` وقت البناء — لا يتم ربط أي مكتبة. راجع [Extend Qiskit in Python with C](/guides/c-extension-for-python) للتفاصيل.

<Accordion>
  <AccordionItem title="Load the MSVC environment">

```python
import os, sys, subprocess, glob, shutil

def load_msvc_env():
    if os.name != "nt":
        return "Not Windows — the system C compiler is used as-is."
    if shutil.which("cl"):
        return "cl.exe is already available in this kernel."

    pf86 = os.environ.get("ProgramFiles(x86)", r"C:\Program Files (x86)")
    pf = os.environ.get("ProgramFiles", r"C:\Program Files")
    vcvars = None

    vswhere = os.path.join(pf86, "Microsoft Visual Studio", "Installer", "vswhere.exe")
    if os.path.isfile(vswhere):
        # vswhere outputs UTF-8 regardless of system locale
        inst = subprocess.run(
            [vswhere, "-latest", "-products", "*",
             "-requires", "Microsoft.VisualStudio.Component.VC.Tools.x86.x64",
             "-property", "installationPath"],
            capture_output=True, text=True, encoding="utf-8").stdout.strip()
        if inst:
            cand = os.path.join(inst, "VC", "Auxiliary", "Build", "vcvars64.bat")
            if os.path.isfile(cand):
                vcvars = cand

    if not vcvars:
        pat = os.path.join("Microsoft Visual Studio", "*", "*",
                           "VC", "Auxiliary", "Build", "vcvars64.bat")
        hits = glob.glob(os.path.join(pf86, pat)) + glob.glob(os.path.join(pf, pat))
        if hits:
            vcvars = sorted(hits)[-1]

    if not vcvars:
        return ("Could not find vcvars64.bat. Install MSVC Build Tools (Step 1.3), "
                "or launch Jupyter from the x64 Native Tools Command Prompt.")

    # cmd.exe outputs in the OEM codepage (cp437/cp850/etc.), not the ANSI codepage
    out = subprocess.run(f'"{vcvars}" >nul 2>&1 && set',
                         capture_output=True, text=True, encoding="oem", shell=True).stdout
    for line in out.splitlines():
        if "=" in line:
            k, _, v = line.partition("=")
            os.environ[k] = v

    return ("Loaded MSVC from:\n  " + vcvars) if shutil.which("cl") \
        else "Ran vcvars64.bat but cl.exe is still not found — check your MSVC install."

print(load_msvc_env())
print("cl.exe on PATH:", shutil.which("cl") is not None)
```
</AccordionItem>

```python
import importlib.util, shutil

checks = {
    "setuptools": importlib.util.find_spec("setuptools") is not None,
    "wheel":      importlib.util.find_spec("wheel") is not None,
    "cl.exe":     shutil.which("cl") is not None,
}
for name, ok in checks.items():
    print(f"  [{'PASS' if ok else 'FAIL':>4}] {name}")

if not checks["cl.exe"]:
    print("\n  cl.exe is not on PATH. rerun the cell above to load the MSVC environment.")
elif all(checks.values()):
    print("\n  Toolchain ready. Continue to the smoke test.")
```
</AccordionItem>

### الخطوة 4 - اختبار سريع: بناء امتداد C {#step-4-smoke-test-build-a-c-extension}

شغِّل الكود التالي. يكتب ملفات المصدر إلى `_smoke_pkg/`، ويبني امتداد C مقابل واجهة برمجة Qiskit C API، ويستورد النتيجة. إذا طُبع "SMOKE TEST PASSED"، فسلسلة أدواتك جاهزة.

تتبع الحزمة عملية [Extend Qiskit in Python with C](/guides/c-extension-for-python) وتستخدم دوال من [مرجع Qiskit C API](https://docs.quantum.ibm.com/api/qiskit-c).

<Accordion>
  <AccordionItem title="Smoke test code">

```python
import sys, subprocess, pathlib, importlib

root = pathlib.Path("_smoke_pkg")
pkg = root / "src" / "qgss_smoke"
pkg.mkdir(parents=True, exist_ok=True)

(root / "pyworkspace.toml").write_text("""
[build-system]
requires = ["setuptools", "qiskit>=2.4.2"]
build-backend = "setuptools.build_meta"

[workspace]
name = "qgss_smoke"
version = "0.0.1"
dependencies = ["qiskit>=2.4.2"]

[tool.setuptools]
package-dir = {"" = "src"}
""".lstrip())

(root / "setup.py").write_text("""
import qiskit
from setuptools import setup, Extension

core_ext = Extension(
    name="qgss_smoke._core",
    sources=["src/qgss_smoke/_coremodule.c"],
    include_dirs=[qiskit.capi.get_include()],
)
setup(ext_modules=[core_ext])
""".lstrip())

(pkg / "__init__.py").write_text("from . import _core\nbuild_demo = _core.build_demo\n")

(pkg / "_coremodule.c").write_text("""
#define QISKIT_PYTHON_EXTENSION
#include <Python.h>
#include <qiskit.h>
#include <stdint.h>

static PyObject *build_demo(PyObject *self, PyObject *args) {
    QkCircuit *qc = qk_circuit_new(2, 0);
    uint32_t q0[1] = {0};
    qk_circuit_gate(qc, QkGate_H, q0, NULL);
    uint32_t q1[1] = {1};
    qk_circuit_gate(qc, QkGate_X, q1, NULL);
    return qk_circuit_to_python_full(qc);
}

static PyMethodDef core_methods[] = {
    {"build_demo", build_demo, METH_NOARGS, "Build a 2-qubit demo circuit in C."},
    {NULL, NULL, 0, NULL},
};
static struct PyModuleDef core_module = {
    .m_base = PyModuleDef_HEAD_INIT,
    .m_name = "_core",
    .m_methods = core_methods,
};
PyMODINIT_FUNC PyInit__core(void) {
    if (qk_import() < 0) {
        return NULL;
    }
    return PyModuleDef_Init(&core_module);
}
""".lstrip())

# On Windows, an imported .pyd is file-locked by the OS. Drop the module from
# sys.modules BEFORE pip install --force-reinstall, otherwise pip fails with
# WinError 32 ("file in use") trying to overwrite the locked .pyd.
if "qgss_smoke._core" in sys.modules:
    del sys.modules["qgss_smoke._core"]
if "qgss_smoke" in sys.modules:
    del sys.modules["qgss_smoke"]

r = subprocess.run(
    [sys.executable, "-m", "pip", "install", "--no-build-isolation",
     "--force-reinstall", "--quiet", str(root.resolve())],
    capture_output=True, text=True,
)
if r.returncode != 0:
    output = (r.stderr + r.stdout).strip()
    print("BUILD FAILED:\n")
    print(output)
    if "WinError 32" in output or "being used by another process" in output:
        print("\n--- TIP ---")
        print("The .pyd file is locked because it was previously imported in this kernel.")
        print("Restart the kernel (Ctrl+Shift+P → 'Jupyter: Restart Kernel'), then rerun")
        print("the Step 3 MSVC cell first, then this cell again.")
    elif "cl.exe" in output.lower() or "vcvars" in output.lower() or "cannot find" in output.lower():
        print("\n--- TIP ---")
        print("The compiler was not found. rerun the Step 3 cell to load the MSVC environment.")
else:
    importlib.invalidate_caches()
    import qgss_smoke
    from qiskit import QuantumCircuit

    qc = qgss_smoke.build_demo()
    ops = dict(qc.count_ops())
    ok = isinstance(qc, QuantumCircuit) and ops.get("h") == 1 and ops.get("x") == 1

    print("Returned object is a QuantumCircuit:", isinstance(qc, QuantumCircuit))
    print("Gates built in C:", ops)
    print("\nSMOKE TEST PASSED — your Windows toolchain can build Qiskit C extensions."
          if ok else "\nSomething is off — check the gates above.")
```
</AccordionItem>
</Accordion>

### بناء المكتبة المستقلة {#build-the-standalone-library}

يبني هذا القسم مكتبة C المستقلة، وهي مطلوبة فقط إذا كنت تريد تجميع وربط برامج C خالصة، كما هو موضح في قسم [UNIX-like](#unix). بالإضافة إلى متطلبات الخطوة 1، يتطلب هذا الأدوات التالية:

* مترجم Rust: راجع مثلاً [دليل تثبيت Qiskit من المصدر](https://github.com/Qiskit/qiskit/blob/main/CONTRIBUTING.md#installing-qiskit-from-source)

* [`cbindgen`](https://github.com/mozilla/cbindgen): أداة لإنشاء ترويسة C، يمكنك تثبيتها باستخدام `cargo install cbindgen`.
    يجب تفعيل تشغيل الأداة من سطر الأوامر، وهو ما قد يتطلب تحديث متغير `PATH` الخاص بك ليشمل مسار cargo.
* تثبيت Python مع إمكانية الوصول إلى كل من ``python3.lib`` و``python3.dll``
* استنساخ [مستودع Qiskit](https://github.com/Qiskit/qiskit) (`git clone https://github.com/Qiskit/qiskit.git`)
<Accordion>
<AccordionItem title="Build the standalone library">
أولاً، جمِّع مكتبة `qiskit_cext` الديناميكية، بتشغيل ما يلي في طرفية VS Code (PowerShell) في جذر Qiskit:

```powershell
$env:PATH = "\path\to\pythonlib;" + $env:PATH
cargo rustc --release --crate-type cdylib -p qiskit-cext
```
سيولّد هذا الأمر المكتبة الديناميكية ``.dll`` وملف ``.dll.lib`` المرفق في `target/release`.
بعد ذلك، أنشئ الرأس بتشغيل

```powershell
cbindgen --crate qiskit-cext --output dist\c\include\qiskit.h
```
يكتب هذا الرأس المتوافق مع MSVC في ``dist\c\include``.

الآن يمكنك استخدام `cl` لتصريف برنامج C. لضمان أن المُصرِّف يجد مكتبة qiskit، أدرج `target\release` في متغير `PATH`.

```powershell
$env:PATH = "\path\to\target\release;" + $env:PATH
cl example.c qiskit_cext.dll.lib -I\path\to\dist\c\include
```

قبل التشغيل، ضمِّن المسار إلى ``python3.dll`` الخاصة بك.

```powershell
$env:PATH = "\path\to\python3-dll;" + $env:PATH
.\example.exe
```
يجب بعد ذلك أن يطبع

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```
</AccordionItem>
</Accordion>

### استكشاف الأخطاء وإصلاحها {#troubleshooting}
<Accordion>
<AccordionItem title="`winget` is not recognized">
حدِّث [App Installer](https://apps.microsoft.com/detail/9nblggh4nns1) من متجر Microsoft، أو استخدم روابط التنزيل اليدوي ذات الصلة
</AccordionItem>
<AccordionItem title="`cl` is not recognized">
أعد تشغيل خلية تحميل MSVC (الخطوة 3)، أو استخدم x64 Native Tools Command Prompt
</AccordionItem>
<AccordionItem title="`python` opens Microsoft Store">
اذهب إلى Settings ← Apps ← Advanced app settings ← App execution aliases وأوقف تشغيل `python.exe`
</AccordionItem>
<AccordionItem title="`.ps1 cannot be loaded` / scripts disabled">
شغِّل `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` ثم أعد المحاولة
</AccordionItem>
<AccordionItem title="`cannot open file 'qiskit.h'`">
شغِّل `python -c "import qiskit.capi; print(qiskit.capi.get_include())"` وتأكد من وجود المسار
</AccordionItem>
<AccordionItem title="`qiskit.capi` not found">
شغِّل `pip install "qiskit[visualization]~=2.4.2"`
</AccordionItem>
<AccordionItem title="`qiskit-aer` build fails">
شغِّل `pip install qiskit-aer --only-binary=:all:`. إذا فشل ذلك أيضاً، استخدم Python 3.12 أو تخطَّ aer، وهو اختياري
</AccordionItem>
<AccordionItem title="Build runs but import fails with a version error">
يجب أن يكون امتداد Qiskit C المبني وإصدار Qiskit المثبت بنفس الإصدار. أعد تثبيت Qiskit باستخدام `pip install "qiskit~=2.4.2"`
</AccordionItem>
<AccordionItem title="I rebuilt the C but the circuit did not change">
لا يمكن إعادة استيراد امتداد C أثناء التشغيل. أعد تشغيل النواة، وأعد تشغيل أوامر MSVC (الخطوة 3)، ثم أعد البناء
</AccordionItem>
<AccordionItem title="PowerShell script was blocked">
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
</AccordionItem>
<AccordionItem title="Path length errors">
استخدم مساراً جذرياً قصيراً على C:\ (على سبيل المثال، `C:\workspace`، أو المسار الذي حددته في خطوة الإعداد)، أو فعِّل Long Paths: Settings ← System ← For developers ← Long Paths
</AccordionItem>
<AccordionItem title="Conda is active (the prompt shows `(base)`) or builds behave oddly after using Anaconda">
شغِّل `conda deactivate` حتى تختفي كل من `CONDA_DEFAULT_ENV` و`CONDA_PREFIX` من البيئة. تحقق باستخدام `$env:CONDA_PREFIX`. إذا استمرت، افتح PowerShell جديدة (وليست موجه Anaconda) وأعد المحاولة من الخطوة 2.
</AccordionItem>
<AccordionItem title="The virtual environment was created from a conda-managed Python (check the `home =` line in `.venv\pyvenv.cfg`)">
ورثت البيئة الافتراضية بيئة تشغيل C الخاصة بـ conda ولا يمكن إصلاحها في مكانها. احذفها، ونزِّل Python 3.12 من موقع [Python](https://www.python.org/downloads/)، وأعد البناء. شغِّل `Remove-Item -Recurse -Force .venv`، ثم أعد تشغيل مقتطف اكتشاف Python في الخطوة 1 لتعيين `$PYTHON_EXE`، ثم أعد إنشاء البيئة الافتراضية (الخطوة 2).
</AccordionItem>
<AccordionItem title="`DLL load failed` on import">
من المرجح أن conda تتسرب إلى البيئة الافتراضية. تحقق من كلتا المشكلتين أعلاه مباشرة. تحقق أيضاً من أن Python هو 64-بت: `python -c "import platform; print(platform.architecture())"`
</AccordionItem>
<AccordionItem title="Build fails with garbled paths or `C1083`">
يحتوي اسم المستخدم أو مسار مساحة العمل الخاص بك على أحرف غير ASCII. انقل مساحة العمل إلى مسار قصير بأحرف ASCII فقط (على سبيل المثال، `C:\workspace`)
</AccordionItem>
<AccordionItem title="Build or import randomly fails, works on retry">
مجلد مساحة العمل متزامن مع OneDrive. انقله إلى مسار محلي مثل `C:\workspace`
</AccordionItem>
<AccordionItem title="Build interrupted midway (for example, there was a power loss)">
احذف مجلد `_smoke_pkg` في مساحة العمل الخاصة بك، وأعد تشغيل خلية تحميل MSVC، ثم أعد تشغيل خلية الاختبار السريع
</AccordionItem>
<AccordionItem title="`pip install` fails with SSL certificate error">
تستخدم شبكتك وكيلاً يعترض HTTPS. جرِّب تشغيل `pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org qiskit` أو اطلب من مسؤول الشبكة شهادة CA الخاصة بالوكيل
</AccordionItem>
<AccordionItem title="Windows Defender quarantines the `.pyd` file">
أضف مجلدي `.venv` و`_smoke_pkg` في مساحة العمل الخاصة بك إلى استثناءات Defender بالانتقال إلى Windows Security ← Virus & threat protection ← Manage settings ← Exclusions
</AccordionItem>
<AccordionItem title="VS Build Tools cannot be installed (no admin rights)">
مطلوب وصول المسؤول. اطلب من قسم تقنية المعلومات لديك الوصول
</AccordionItem>
<AccordionItem title="`WinError 32` / file in use during rebuild">
ملف .pyd مقفل من قبل النواة قيد التشغيل. أعد تشغيل النواة (Ctrl+Shift+P ← Jupyter: Restart Kernel)، وأعد تشغيل الخطوة 3، ثم أعد البناء
</AccordionItem>
<AccordionItem title="Commands silently do nothing (no error, no output)">
قد تكون في cmd.exe بدلاً من PowerShell. تحقق من موجه الأوامر الخاص بك: يظهر PowerShell `PS C:\>`، ويظهر cmd `C:\>`. افتح PowerShell من قائمة Start أو Win+X
</AccordionItem>
<AccordionItem title="MSVC install appears stuck">
تحجب علامتا `--passive --wait` PowerShell أثناء تشغيل المثبِّت في الخلفية. تحقق من شريط المهام الخاص بك بحثاً عن نافذة "Visual Studio Installer". قد يستغرق التثبيت 10-30 دقيقة
</AccordionItem>
</Accordion>
