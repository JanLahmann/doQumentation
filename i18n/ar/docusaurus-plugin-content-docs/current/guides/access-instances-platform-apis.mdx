# استخدام IBM Cloud Resource Controller API لإدارة النسخ {#use-ibm-cloud-resource-controller-api-for-instance-management}

يمكنك استخدام IBM Cloud&reg; Resource Controller REST API لجلب [النسخ](/guides/instances) وإنشائها وتحديثها برمجياً.

تتطلب جميع نقاط نهاية Resource Controller المصادقة عبر تمرير رأس يُسمى `Authorization` يحتوي على رمز الحامل (bearer token). راجع [دليل إعداد REST API](/guides/cloud-setup-rest-api).

## الحصول على نسخة {#get-an-instance}

استخدم نقطة النهاية [`GET /v2/resource_instances/{crn}`](https://cloud.ibm.com/apidocs/resource-controller/resource-controller#get-resource-instance) للحصول على معلومات حول نسخة معينة. يجب ترميز [CRN](/guides/instances) لعنوان URL في المسار.

بالإضافة إلى حقول Resource Controller القياسية، تتضمن الاستجابة حقولاً خاصة بالحوسبة الكمية في كل من `parameters` و`extensions`. يخزّن `extensions` البيانات الوصفية الموحدة للنسخة، بينما يخزّن `parameters` فقط أحدث طلب لتعديل النسخة. لذلك، ينبغي أن تقرأ من `extensions` بدلاً من `parameters`.

يتضمن الكائن `extensions` هذه الحقول:

- `instance_limit_seconds` — عدد صحيح، أو `null`. حد وقت الاستخدام للنسخة. راجع [تعيين حدود تخصيص النسخة](/guides/allocation-limits).

- `usage_allocation_seconds` — عدد صحيح، أو `null`. الوقت المخصص لهذه النسخة، يستخدمه [جدولة التوزيع العادل](/guides/fair-share-scheduler) لتحديد أولوية قائمة الانتظار. راجع [تعيين حدود تخصيص النسخة](/guides/allocation-limits).

- `backends` — مصفوفة من السلاسل النصية. القائمة المسموح بها لأسماء الـ backends المتاحة لهذه النسخة. `["ANY"]` تعني أن جميع الـ backends في الخطة متاحة (القيمة الافتراضية). `[]` تعني عدم توفر أي backend.


<Admonition type="caution" title="قد يكون حقل backends قديماً">
  قد يكون الحقل `backends` في الكائن `extensions` قديماً. يمكن أن يحدث ذلك عندما يغيّر دعم IBM Quantum حسابك بطريقة تؤثر على النسخ. على سبيل المثال، عند إزالة backend من حساب، سيتم تحديث `backends` الخاصة بالنسخة، لكن هذا التغيير لا ينعكس حالياً بعد في Resource Controller API.

  بدلاً من ذلك، الحل البديل الحالي هو استخدام [IBM Quantum Compute Service REST API](https://docs.quantum.ibm.com/api/qiskit-runtime-rest) مع نقطة النهاية [`GET /v1/backends`](https://docs.quantum.ibm.com/api/qiskit-runtime-rest/tags/backends#tags__backends__operations__list_backends). (تأكد من تعيين الرأس `Service-CRN` إلى CRN الخاص بنسختك.)
</Admonition>

<Tabs>
  <TabItem value="curl" label="cURL">
    يجب ترميز CRN لعنوان URL في المسار. استبدل كل `:` بـ `%3A` وكل `/` بـ `%2F`. على سبيل المثال، تصبح `crn:v1:bluemix:...` هي `crn%3Av1%3Abluemix%3A...`.

    ```bash
    curl \
      --request GET \
      --url 'https://resource-controller.cloud.ibm.com/v2/resource_instances/<YOUR_INSTANCE_CRN_URL_ENCODED>' \
      --header 'Authorization: Bearer <YOUR_BEARER_TOKEN>'
    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
    import urllib.parse
    import requests

    crn = "<YOUR_INSTANCE_CRN>"
    # We use urllib.parse.quote to URL-encode the CRN.
    url = (
        "https://resource-controller.cloud.ibm.com/v2/resource_instances/"
        + urllib.parse.quote(crn, safe="")
    )

    resp = requests.get(
        url,
        headers={"Authorization": f"Bearer {token}"},
        timeout=30,
    )
    resp.raise_for_status()
    print(resp.json())
    ```
  </TabItem>
</Tabs>

## تحديث نسخة {#update-an-instance}

استخدم نقطة النهاية [`PATCH /v2/resource_instances/{crn}`](https://cloud.ibm.com/apidocs/resource-controller/resource-controller#update-resource-instance) لتحديث الحد والتخصيص والـ backends المسموح بها لنسخة. يجب ترميز [CRN](/guides/instances) لعنوان URL في المسار.

مرّر كائن JSON باسم `parameters` في نص الطلب يحتوي على الحقول التي تريد تغييرها، مع الرأس `"Content-Type: application/json"`. تبقى الحقول المحذوفة دون تغيير.

- `instance_limit_seconds` — عدد صحيح، أو `null`. حد وقت الاستخدام للنسخة. راجع [تعيين حدود تخصيص النسخة](/guides/allocation-limits).

- `usage_allocation_seconds` — عدد صحيح، أو `null`. الوقت المخصص لهذه النسخة، يستخدمه [جدولة التوزيع العادل](/guides/fair-share-scheduler) لتحديد أولوية قائمة الانتظار. راجع [تعيين حدود تخصيص النسخة](/guides/allocation-limits). لا ينطبق على نسخ Pay-As-You-Go.

- `backends` — مصفوفة من السلاسل النصية. القائمة المسموح بها لأسماء الـ backends المتاحة لهذه النسخة. `["ANY"]` تعني أن جميع الـ backends في الخطة متاحة. `[]` تعني عدم توفر أي backend.


<Admonition type="caution" title="احرص دائماً على تضمين طابع زمني فريد">
  تتجاهل واجهة برمجة التطبيقات الطلب بصمت إذا كانت `parameters` مطابقة للطلب السابق. في الكائن `parameters`، ضمّن دائماً حقل `timestamp` مضبوطاً على الوقت الحالي حتى تتم معاملة كل طلب بوصفه فريداً.
</Admonition>

استجابة نقطة النهاية مشابهة لـ [الحصول على نسخة](#get-an-instance)، بما في ذلك طريقة تعاملها مع الكائن `extensions`.

<Tabs>
  <TabItem value="curl" label="cURL">
    يجب ترميز CRN لعنوان URL في المسار. استبدل كل `:` بـ `%3A` وكل `/` بـ `%2F`. على سبيل المثال، تصبح `crn:v1:bluemix:...` هي `crn%3Av1%3Abluemix%3A...`.

    ```bash
    curl \
    --request PATCH \
    --url 'https://resource-controller.cloud.ibm.com/v2/resource_instances/<YOUR_INSTANCE_CRN_URL_ENCODED>' \
    --header 'Authorization: Bearer <YOUR_BEARER_TOKEN>' \
    --header 'Content-Type: application/json' \
    --data "{
        \"parameters\": {
            \"timestamp\": \"$(date -u +"%Y-%m-%dT%H:%M:%SZ")\",
            \"usage_allocation_seconds\": 220
        }
    }"
    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
    import urllib.parse
    import datetime
    import requests

    crn = "<YOUR_INSTANCE_CRN>"
    # We use urllib.parse.quote to URL-encode the CRN.
    url = (
        "https://resource-controller.cloud.ibm.com/v2/resource_instances/"
        + urllib.parse.quote(crn, safe="")
    )

    timestamp = datetime.datetime.now(datetime.timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
    body = {
        "parameters": {
            "timestamp": timestamp,
            "usage_allocation_seconds": 220,
        }
    }

    resp = requests.patch(
        url,
        headers={
            "Authorization": f"Bearer {token}",
            "Content-Type": "application/json",
        },
        json=body,
        timeout=30,
    )
    resp.raise_for_status()
    print(resp.json())
    ```
  </TabItem>
</Tabs>

## إنشاء نسخة جديدة {#create-a-new-instance}

استخدم نقطة النهاية [`POST /v2/resource_instances`](https://cloud.ibm.com/apidocs/resource-controller/resource-controller#create-resource-instance) لإنشاء (تزويد) نسخة جديدة. مرّر نص JSON مع الرأس `"Content-Type: application/json"`.

الحقول المطلوبة:

- `name` — اسم يمكن للإنسان قراءته للنسخة.

- `target` — المنطقة، مثل `us-east` أو `eu-de`.

- `resource_plan_id` — الخطة لهذه النسخة. راجع [جدول معرّفات الخطط](#get-a-list-of-all-instances).

- `resource_group` — [مجموعة الموارد](https://cloud.ibm.com/docs/account?topic=account-rgs) التي ستُستخدم.


يمكنك أيضاً تضمين كائن `parameters` لتعيين قيم خاصة بالحوسبة الكمية:

- `instance_limit_seconds` — عدد صحيح، أو `null`. حد وقت الاستخدام للنسخة. راجع [تعيين حدود تخصيص النسخة](/guides/allocation-limits).

- `usage_allocation_seconds` — عدد صحيح، أو `null`. الوقت المخصص لهذه النسخة، يستخدمه [جدولة التوزيع العادل](/guides/fair-share-scheduler) لتحديد أولوية قائمة الانتظار. راجع [تعيين حدود تخصيص النسخة](/guides/allocation-limits). لا ينطبق على نسخ Pay-As-You-Go.

- `backends` — مصفوفة من السلاسل النصية. القائمة المسموح بها لأسماء الـ backends المتاحة لهذه النسخة. `["ANY"]` تعني أن جميع الـ backends في الخطة متاحة. `[]` تعني عدم توفر أي backend.

    ```bash
          "name": "my-new-instance",
    ```

## تكوين الوصول إلى Qiskit Functions على نسخة {#configure-qiskit-functions-access-on-an-instance}

استخدم هذه التعليمات لتكوين الوصول إلى Qiskit Functions على نسخة IBM Quantum Compute Service موجودة باستخدام IBM Cloud Resource Controller API. اتبع التعليمات بالترتيب، حيث تبني الأوامر على بعضها البعض. فمثلاً، تُعيَّن متغيرات مثل الرمز وعنوان URL في خطوة واحدة ويُعاد استخدامها في الخطوات اللاحقة.

### المتطلبات الأساسية {#prerequisites}

- مفتاح IBM Cloud API (يُسمى أيضاً رمزاً). إذا لزم الأمر، أنشئ مفتاح API الخاص بك على [لوحة التحكم](https://quantum.cloud.ibm.com).

- CRN الخاص بالنسخة التي تريد تكوينها. تظهر CRN الخاصة بالنسخة على صفحة [النسخ](https://quantum.cloud.ibm.com/instances) الخاصة بك.


### الخطوة 1: الحصول على رمز حامل {#step-1-get-a-bearer-token}

استبدل مفتاح API الخاص بك برمز حامل. ستمرر هذا الرمز في رأس التخويل لجميع طلبات وحدة تحكم الموارد. شغّل الشيفرة التالية لإنشاء رمز حامل:

<Tabs>
  <TabItem value="curl" label="cURL">

    ```bash
curl --request POST \
  --url 'https://iam.cloud.ibm.com/identity/token' \
  --header 'Content-Type: application/x-www-form-urlencoded' \
  --data 'apikey=<YOUR_API_KEY>&grant_type=urn%3Aibm%3Aparams%3Aoauth%3Agrant-type%3Aapikey'
  --silent | jq .
    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
import requests

api_key = "<YOUR_API_KEY>"

resp = requests.post(
    "https://iam.cloud.ibm.com/identity/token",
    headers={"Content-Type": "application/x-www-form-urlencoded"},
    params={
        "apikey": api_key,
        "grant_type": "urn:ibm:params:oauth:grant-type:apikey",
    },
    timeout=30,
)
resp.raise_for_status()
token = resp.json()["access_token"]
print(token) 
    ```
  </TabItem>
</Tabs>

تتضمن الاستجابة حقل `access_token`، وهو رمز الحامل الخاص بك. انسخ هذه القيمة.

### الخطوة 2: التحقق من الوصول {#step-2-verify-access}

قبل إجراء أي تغييرات، تأكد من أن رمزك يعمل وافحص تكوين النسخة الحالي.

<Tabs>
  <TabItem value="curl" label="cURL">
<Admonition type="note" title="مهم">
يجب ترميز CRN يدوياً لعنوان URL في المسار. استبدل كل `:` بـ `%3A` وكل `/` بـ `%2F`. على سبيل المثال، تصبح `crn:v1:bluemix:...` هي `crn%3Av1%3Abluemix%3A...`.
</Admonition>

    ```bash
curl --request GET \
  --url 'https://resource-controller.cloud.ibm.com/v2/resource_instances/<YOUR_INSTANCE_CRN_URL_ENCODED>' \
  --header 'Authorization: Bearer <YOUR_BEARER_TOKEN>'

    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
import urllib.parse

crn = "<YOUR_INSTANCE_CRN>"
# سيتم ترميز CRN لعنوان URL في المسار.
instance_url = (
    "https://resource-controller.cloud.ibm.com/v2/resource_instances/"
    + urllib.parse.quote(crn, safe="")
)
headers = {"Authorization": f"Bearer {token}", "Content-Type": "application/json"}

resp = requests.get(instance_url, headers=headers, timeout=30)
resp.raise_for_status()
print(resp.json()["extensions"])

    ```
  </TabItem>
</Tabs>

تؤكد الاستجابة `200 OK` أن رمزك صالح. تكوين النسخة الحالي موجود في حقل extensions من الاستجابة. استخدم هذا بدلاً من parameters، والتي قد تكون قديمة.

### الخطوة 3: البحث عن تكوين الدوال على مستوى الحساب {#step-3-look-up-the-account-level-functions-configuration}

لا يمكن منح نسخة الوصول إلا لما يستحقه الحساب. قبل تكوين النسخة، ابحث عن تكوين الحساب حتى تعرف الدوال ونماذج الأعمال والأذونات المتاحة للمنح. هذا هو مصدر الحقيقة للقيم التي سترسلها في الخطوة 4.

استدعِ `GET /accounts/{id}` على Qiskit Runtime API باستخدام مفتاح API الخاص بك. `{id}` هو معرّف حسابك بدون بادئة `a/`. يمكنك إيجاده من CRN الخاص بالنسخة (`crn:v1:bluemix:public:quantum-computing:...:a/<ACCOUNT_ID>:...`).

<Tabs>
  <TabItem value="curl" label="cURL">

    ```bash
curl --request GET \
  --url 'https://quantum.cloud.ibm.com/api/v1/accounts/<ACCOUNT_ID>' \
  --header 'Authorization: apikey <YOUR_API_KEY>'

    ```
  </TabItem>

  <TabItem value="python" label="Python">

    ```python
account_id = "<ACCOUNT_ID>"  # from the CRN: crn:...:a/<ACCOUNT_ID>:...

resp = requests.get(
    f"https://quantum.cloud.ibm.com/api/v1/accounts/{account_id}",
    headers={"Authorization": f"apikey {api_key}"},
    timeout=30,
)
resp.raise_for_status()
for plan in resp.json()["plans"]:
    print(plan["plan_id"], plan.get("functions"), plan.get("custom_functions"))

    ```
  </TabItem>
</Tabs>

تتضمن كل خطة في الاستجابة مصفوفة functions وكائن `custom_functions` إن كان مُكوَّناً. تسرد هذه القيم الاسم الدقيق والمزود ونموذج الأعمال والأذونات التي يمكنك منحها لنسخة تحت تلك الخطة.

<Admonition type="note">
`GET /accounts/{id}` shows what is available to grant at the account level. `GET /functions` (see [Verify the result](#verify-result)) shows what a specific instance has already been granted. Use the **account** endpoint to discover valid values, and the **functions** endpoint to confirm the result.
</Admonition>

### الخطوة 4: تكوين الوصول إلى الدوال {#step-4-configure-functions-access}

حدّث النسخة لمنح الوصول إلى Catalog Functions وCustom Functions.

<Admonition type="note" title="ملاحظات مهمة">
- يجب أن تطابق قيم `name` و`provider` و`business_model` في functions تماماً الإدخالات المكوَّنة على مستوى الحساب (راجع [الخطوة السابقة](#step-3)). يجب أن تكون الأذونات مجموعة جزئية غير فارغة من أذونات الحساب لتلك الدالة. وبالمثل، يجب أن تكون `custom_functions.permissions` مجموعة جزئية غير فارغة من أذونات `custom_functions` الخاصة بالحساب.
- ضمّن طابعاً زمنياً في parameters في كل عملية PATCH. يزيل Resource Controller التكرار في طلبات PATCH عن طريق مقارنة parameters الواردة بآخر قيمة قام بتخزينها. إذا تطابقت، يُسقط الطلب بصمت مع `200 OK` دون الوصول إلى الخدمة. ضمّن قيمة طابع زمني متغيرة لمنع ذلك.
</Admonition>

<Tabs>
  <TabItem value="curl" label="cURL">

    ```bash
curl --request PATCH \
  --url 'https://resource-controller.cloud.ibm.com/v2/resource_instances/<YOUR_INSTANCE_CRN_URL_ENCODED>' \
  --header 'Authorization: Bearer <YOUR_BEARER_TOKEN>' \
  --header 'Content-Type: application/json' \
  --data '{
    "parameters": {
      "timestamp": "2026-06-30T00:00:00Z",
      "functions": [
        {
          "name": "<FUNCTION_NAME>",
          "provider": "<PROVIDER>",
          "business_model": "<BUSINESS_MODEL>",
          "permissions": [
            "function.read",
            "function.run",
            "function-files.read",
            "function-files.write"
          ]
    ```
