# Instalace Qiskit C API {#install-the-qiskit-c-api}

Tento průvodce popisuje, jak nainstalovat a používat Qiskit C API. Po dokončení instalace si přečti [Rozšíření Pythonu pomocí Qiskit C API](/guides/c-extension-for-python).

Následující příklad sestavuje observable v C:

```c
// file: example.c
#include <stdio.h>
#include <stdint.h>
#include <qiskit.h>

int main(int argc, char *argv[]) {
    // build a 100-qubit empty observable
    uint32_t num_qubits = 100;
    QkObs *obs = qk_obs_zero(num_qubits);

    // add the term 2 * (X0 Y1 Z2) to the observable
    QkComplex64 coeff = {2, 0};
    QkBitTerm bit_terms[3] = {QkBitTerm_X, QkBitTerm_Y, QkBitTerm_Z}; 
    // bit terms: X Y Z
    uint32_t indices[3] = {0, 1, 2};  // indices: 0 1 2
    QkObsTerm term = {coeff, 3, bit_terms, indices, num_qubits};
    qk_obs_add_term(obs, &term);  // append the term

    // print some properties and the observable itself
    printf("num_qubits: %i\n", qk_obs_num_qubits(obs));
    printf("num_terms: %lu\n", qk_obs_num_terms(obs));
    printf("observable: %s\n", qk_obs_str(obs));

    // free the memory allocated for the observable
    qk_obs_free(obs);

    return 0;
}
```

## UNIX-like {#unix-like}

Tato sekce obsahuje pokyny pro sestavení na systémech podobných UNIXu.

### Požadavky {#requirements}

Kompilace vyžaduje následující nástroje:
* Kompilátor Rust: viz například [průvodce instalací Qiskitu ze zdrojového kódu](/guides/install-qiskit-source)
* Kompilátor C: například GCC na Linuxu a Clang na MacOS. Qiskit C API je kompatibilní s kompilátorem splňujícím standard [C11](https://en.wikipedia.org/wiki/C11_(C_standard_revision)).
* [`cbindgen`](https://github.com/mozilla/cbindgen): nástroj pro vytvoření hlavičkového souboru C, který lze nainstalovat pomocí `cargo install cbindgen`
    Spouštění nástroje z příkazové řádky by mělo být povoleno, což může vyžadovat přidání `/path/to/.cargo/bin` do proměnné `PATH`.
* Nainstalovaná Python knihovna (Python 3.9+): Python knihovna je vyžadována při dynamickém linkování. Vezmi na vědomí, že Python není používán za běhu a interpret není nikdy inicializován; je potřeba definovat pouze některé symboly z `libpython`. Více informací najdeš v [tomto issue](https://github.com/Qiskit/qiskit/issues/14240).
* (GNU) Make: tento nástroj je volitelný, ale doporučujeme ho používat pro automatizované instalační procesy.

Tento kód ověří, že vše bylo správně nainstalováno:

```bash
rustc --version
gcc --version
cbindgen --version
make --version  # optional, but recommended
```

### Sestavení {#build}

Pro sestavení hlavičkového souboru C a knihovny můžeš spustit následující příkaz Make[^1] v kořenovém adresáři Qiskitu,
[^1]: Pokud jsi nenainstaloval/a Make, podívej se do souboru `Makefile` v kořenovém adresáři Qiskitu pro potřebné příkazy – nebo prostě Make nainstaluj; není pozdě.)

```bash
make c
```
což poskytne zkompilovanou sdílenou knihovnu v `dist/c/lib` a hlavičkový soubor `qiskit.h` se všemi deklaracemi funkcí v `dist/c/include`. Vezmi na vědomí, že přesný název knihovny závisí na platformě; například `libqiskit.so` na UNIXu a `libqiskit.dylib` na MacOS.
(Upozorňujeme, že tento krok v současné době generuje velké množství varování, což je očekávané a není důvod k obavám. Budoucí verze tato varování odstraní.)

Poté můžeš zkompilovat program v C pomocí hlavičkového souboru a knihovny Qiskit:

```bash
gcc example.c -o example.o -I /path/to/dist/c/include -L /path/to/dist/c/lib -lqiskit
```
Aby bylo zajištěno, že knihovna Qiskit bude nalezena při linkování, nastav cestu ke knihovně za běhu tak, aby zahrnovala `/path/to/dist/c/lib`. Pokud Python knihovna není ve výchozím nastavení dostupná při dynamickém linkování, je třeba ji přidat také. Tyto příkazy závisí na platformě. Na Linuxu:

```bash
export LD_LIBRARY_PATH=/path/to/dist/c/lib:$LD_LIBRARY_PATH
# On Linux, the Python library is typically included 
# in the dynamic library path by default.
export LD_LIBRARY_PATH=/path/to/python/lib:$LD_LIBRARY_PATH
```
Na MacOS:

```bash
export DYLD_LIBRARY_PATH=/path/to/dist/c/lib:$DYLD_LIBRARY_PATH
export DYLD_LIBRARY_PATH=/path/to/python/lib:$DYLD_LIBRARY_PATH
```
Případně můžeš nastavit cestu ke knihovně za běhu během kompilace přidáním

```
-Wl,-rpath,/path/to/dist/c/lib
# same for Python
```
do příznaků kompilátoru.
Navíc musí být Python knihovna dostupná při dynamickém linkování. V prostředích Linux je to obvykle výchozí nastavení. 

Nyní můžeš spustit binární soubor:

```bash
./example.o
```
což by při použití výše uvedeného ukázkového fragmentu kódu mělo vypsat

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```

## Windows {#windows}

Tato sekce obsahuje pokyny pro sestavení na systémech Windows.

Existují dva nezávislé způsoby, jak používat C API na Windows:

* **Sestavit rozšiřující moduly Pythonu**, které používají Qiskit C API. Postupuj podle kroků 1-5. Tato cesta používá C hlavičky dodávané s Python balíčkem `qiskit` a nevyžaduje Rust ani cbindgen.

* **Sestavit samostatnou C knihovnu** pro linkování z čistě C programu, tak jak je to popsáno v sekci [UNIX-like](#unix). Dokonči krok 1 a poté přeskoč na [Sestavení samostatné knihovny](#build-the-standalone-library), kde jsou uvedeny její dodatečné požadavky.


### Požadavky {#requirements-1}

- Pro některé kroky jsou vyžadována administrátorská práva.

- 5-8 GB volného místa na disku.

- C kompilátor: Microsoft Visual C++ (MSVC), instalovaný v kroku 1.

- 64bitová instalace Pythonu (3.10 nebo novější), instalovaná v kroku 1.


### Než začneš {#before-you-begin}

Vytvoř svůj pracovní prostor. Měla by to být krátká cesta na lokálním disku. Nepoužívej složky synchronizované přes OneDrive (jako Documents nebo Desktop), síťové disky ani cesty s mezerami nebo znaky mimo ASCII. Pokud tvé uživatelské jméno obsahuje neanglické znaky, neumísťuj ho pod svou uživatelskou složku.

Příklady dobrých cest k pracovnímu prostoru: `C:\workspace`, `D:\workspace`, `C:\Users\john\workspace`

### Krok 3 - Načtení prostředí MSVC {#step-3-load-the-msvc-environment}

Spusť následující kód v každé nové Python session (například pokaždé, když restartuješ Jupyter kernel). Automaticky vyhledá a načte vývojářské prostředí MSVC, takže nepotřebuješ zabudovaný x64 příkazový řádek.

Příklad v této dokumentaci sestavuje rozšiřující moduly C pomocí `setuptools` s MSVC. Obecně definuješ `QISKIT_PYTHON_EXTENSION`, zahrneš `qiskit.h` a zavoláš `qk_import()` ve své init funkci. V době sestavení jsou potřeba pouze hlavičky z `qiskit.capi.get_include()` — žádná knihovna se nelinkuje. Podrobnosti najdeš v [Rozšíření Qiskit v Pythonu pomocí C](/guides/c-extension-for-python).

<Accordion>
  <AccordionItem title="Načtení prostředí MSVC">

```python
import os, sys, subprocess, glob, shutil

def load_msvc_env():
    if os.name != "nt":
        return "Not Windows — the system C compiler is used as-is."
    if shutil.which("cl"):
        return "cl.exe is already available in this kernel."

    pf86 = os.environ.get("ProgramFiles(x86)", r"C:\Program Files (x86)")
    pf = os.environ.get("ProgramFiles", r"C:\Program Files")
    vcvars = None

    vswhere = os.path.join(pf86, "Microsoft Visual Studio", "Installer", "vswhere.exe")
    if os.path.isfile(vswhere):
        # vswhere outputs UTF-8 regardless of system locale
        inst = subprocess.run(
            [vswhere, "-latest", "-products", "*",
             "-requires", "Microsoft.VisualStudio.Component.VC.Tools.x86.x64",
             "-property", "installationPath"],
            capture_output=True, text=True, encoding="utf-8").stdout.strip()
        if inst:
            cand = os.path.join(inst, "VC", "Auxiliary", "Build", "vcvars64.bat")
            if os.path.isfile(cand):
                vcvars = cand

    if not vcvars:
        pat = os.path.join("Microsoft Visual Studio", "*", "*",
                           "VC", "Auxiliary", "Build", "vcvars64.bat")
        hits = glob.glob(os.path.join(pf86, pat)) + glob.glob(os.path.join(pf, pat))
        if hits:
            vcvars = sorted(hits)[-1]

    if not vcvars:
        return ("Could not find vcvars64.bat. Install MSVC Build Tools (Step 1.3), "
                "or launch Jupyter from the x64 Native Tools Command Prompt.")

    # cmd.exe outputs in the OEM codepage (cp437/cp850/etc.), not the ANSI codepage
    out = subprocess.run(f'"{vcvars}" >nul 2>&1 && set',
                         capture_output=True, text=True, encoding="oem", shell=True).stdout
    for line in out.splitlines():
        if "=" in line:
            k, _, v = line.partition("=")
            os.environ[k] = v

    return ("Loaded MSVC from:\n  " + vcvars) if shutil.which("cl") \
        else "Ran vcvars64.bat but cl.exe is still not found — check your MSVC install."

print(load_msvc_env())
print("cl.exe on PATH:", shutil.which("cl") is not None)
```
</AccordionItem>

### Krok 4 - Smoke test: Sestavení rozšíření C {#step-4-smoke-test-build-a-c-extension}

Spusť následující kód. Zapíše zdrojové soubory do `_smoke_pkg/`, sestaví rozšíření C oproti Qiskit C API a importuje výsledek. Pokud vypíše "SMOKE TEST PASSED", tvůj toolchain je připraven.

Balíček se řídí procesem [Rozšíření Qiskit v Pythonu pomocí C](/guides/c-extension-for-python) a používá funkce z [referenční dokumentace Qiskit C API](https://docs.quantum.ibm.com/api/qiskit-c).

<Accordion>
  <AccordionItem title="Kód smoke testu">

```python
import sys, subprocess, pathlib, importlib

root = pathlib.Path("_smoke_pkg")
pkg = root / "src" / "qgss_smoke"
pkg.mkdir(parents=True, exist_ok=True)

(root / "pyworkspace.toml").write_text("""
[build-system]
requires = ["setuptools", "qiskit>=2.4.2"]
build-backend = "setuptools.build_meta"

[workspace]
name = "qgss_smoke"
version = "0.0.1"
dependencies = ["qiskit>=2.4.2"]

[tool.setuptools]
package-dir = {"" = "src"}
""".lstrip())

(root / "setup.py").write_text("""
import qiskit
from setuptools import setup, Extension

core_ext = Extension(
    name="qgss_smoke._core",
    sources=["src/qgss_smoke/_coremodule.c"],
    include_dirs=[qiskit.capi.get_include()],
)
setup(ext_modules=[core_ext])
""".lstrip())

(pkg / "__init__.py").write_text("from . import _core\nbuild_demo = _core.build_demo\n")

(pkg / "_coremodule.c").write_text("""
#define QISKIT_PYTHON_EXTENSION
#include <Python.h>
#include <qiskit.h>
#include <stdint.h>

static PyObject *build_demo(PyObject *self, PyObject *args) {
    QkCircuit *qc = qk_circuit_new(2, 0);
    uint32_t q0[1] = {0};
    qk_circuit_gate(qc, QkGate_H, q0, NULL);
    uint32_t q1[1] = {1};
    qk_circuit_gate(qc, QkGate_X, q1, NULL);
    return qk_circuit_to_python_full(qc);
}

static PyMethodDef core_methods[] = {
    {"build_demo", build_demo, METH_NOARGS, "Build a 2-qubit demo circuit in C."},
    {NULL, NULL, 0, NULL},
};
static struct PyModuleDef core_module = {
    .m_base = PyModuleDef_HEAD_INIT,
    .m_name = "_core",
    .m_methods = core_methods,
};
PyMODINIT_FUNC PyInit__core(void) {
    if (qk_import() < 0) {
        return NULL;
    }
    return PyModuleDef_Init(&core_module);
}
""".lstrip())

# On Windows, an imported .pyd is file-locked by the OS. Drop the module from
# sys.modules BEFORE pip install --force-reinstall, otherwise pip fails with
# WinError 32 ("file in use") trying to overwrite the locked .pyd.
if "qgss_smoke._core" in sys.modules:
    del sys.modules["qgss_smoke._core"]
if "qgss_smoke" in sys.modules:
    del sys.modules["qgss_smoke"]

r = subprocess.run(
    [sys.executable, "-m", "pip", "install", "--no-build-isolation",
     "--force-reinstall", "--quiet", str(root.resolve())],
    capture_output=True, text=True,
)
if r.returncode != 0:
    output = (r.stderr + r.stdout).strip()
    print("BUILD FAILED:\n")
    print(output)
    if "WinError 32" in output or "being used by another process" in output:
        print("\n--- TIP ---")
        print("The .pyd file is locked because it was previously imported in this kernel.")
        print("Restart the kernel (Ctrl+Shift+P → 'Jupyter: Restart Kernel'), then rerun")
        print("the Step 3 MSVC cell first, then this cell again.")
    elif "cl.exe" in output.lower() or "vcvars" in output.lower() or "cannot find" in output.lower():
        print("\n--- TIP ---")
        print("The compiler was not found. rerun the Step 3 cell to load the MSVC environment.")
else:
    importlib.invalidate_caches()
    import qgss_smoke
    from qiskit import QuantumCircuit

    qc = qgss_smoke.build_demo()
    ops = dict(qc.count_ops())
    ok = isinstance(qc, QuantumCircuit) and ops.get("h") == 1 and ops.get("x") == 1

    print("Returned object is a QuantumCircuit:", isinstance(qc, QuantumCircuit))
    print("Gates built in C:", ops)
    print("\nSMOKE TEST PASSED — your Windows toolchain can build Qiskit C extensions."
          if ok else "\nSomething is off — check the gates above.")
```

### Sestavení samostatné knihovny {#build-the-standalone-library}

Tato sekce sestavuje samostatnou C knihovnu, která je potřebná pouze pokud chceš kompilovat a linkovat čisté C programy, jak je popsáno v sekci [UNIX-like](#unix). Kromě předpokladů z kroku 1 to vyžaduje následující nástroje:

* Rust kompilátor: viz například [průvodce instalací Qiskit ze zdrojového kódu](https://github.com/Qiskit/qiskit/blob/main/CONTRIBUTING.md#installing-qiskit-from-source)

* [`cbindgen`](https://github.com/mozilla/cbindgen): nástroj pro vytvoření C hlavičkového souboru, který můžeš nainstalovat pomocí `cargo install cbindgen`.
    Spouštění nástroje z příkazové řádky by mělo být povoleno, což může vyžadovat aktualizaci proměnné `PATH` tak, aby zahrnovala cestu k cargo.
* Instalace Pythonu s přístupem k ``python3.lib`` i ``python3.dll``
* Klon [repozitáře Qiskit](https://github.com/Qiskit/qiskit) (`git clone https://github.com/Qiskit/qiskit.git`)
<Accordion>
<AccordionItem title="Sestavení samostatné knihovny">
Nejprve zkompiluj dynamickou knihovnu `qiskit_cext` spuštěním následujícího příkazu v terminálu VS Code (PowerShell) v kořenovém adresáři Qiskit:

```powershell
$env:PATH = "\path\to\pythonlib;" + $env:PATH
cargo rustc --release --crate-type cdylib -p qiskit-cext
```
Tím se vygeneruje dynamická knihovna ``.dll`` a související soubor ``.dll.lib`` v `target/release`.
Dále vygeneruj hlavičkový soubor pomocí

```powershell
cbindgen --crate qiskit-cext --output dist\c\include\qiskit.h
```
Tím se zapíše hlavičkový soubor kompatibilní s MSVC do ``dist\c\include``.

Nyní můžeš použít `cl` ke kompilaci C programu. Aby kompilátor našel knihovnu qiskit,
 zahrň `target\release` do proměnné `PATH`.

```powershell
$env:PATH = "\path\to\target\release;" + $env:PATH
cl example.c qiskit_cext.dll.lib -I\path\to\dist\c\include
```

Před spuštěním zahrň cestu ke svému souboru ``python3.dll``.

```powershell
$env:PATH = "\path\to\python3-dll;" + $env:PATH
.\example.exe
```
by pak mělo vypsat

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```
</AccordionItem>
</Accordion>

### Řešení problémů {#troubleshooting}
<Accordion>
<AccordionItem title="`winget` není rozpoznán">
Aktualizuj [App Installer](https://apps.microsoft.com/detail/9nblggh4nns1) z Microsoft Store, nebo použij příslušné odkazy pro ruční stažení
</AccordionItem>
<AccordionItem title="`cl` není rozpoznán">
Znovu spusť buňku pro načtení MSVC (Krok 3), nebo použij x64 Native Tools Command Prompt
</AccordionItem>
<AccordionItem title="`python` otevírá Microsoft Store">
Přejdi do Nastavení → Aplikace → Pokročilá nastavení aplikací → Aliasy pro spouštění aplikací a vypni `python.exe`
</AccordionItem>
<AccordionItem title="`.ps1 cannot be loaded` / skripty zakázány">
Spusť `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` a zkus to znovu
</AccordionItem>
<AccordionItem title="`cannot open file 'qiskit.h'`">
Spusť `python -c "import qiskit.capi; print(qiskit.capi.get_include())"` a ověř, že cesta existuje
</AccordionItem>
<AccordionItem title="`qiskit.capi` nenalezen">
Spusť `pip install "qiskit[visualization]~=2.4.2"`
</AccordionItem>
<AccordionItem title="Sestavení `qiskit-aer` selže">
Spusť `pip install qiskit-aer --only-binary=:all:`. Pokud to také selže, použij Python 3.12 nebo přeskoč aer, který je volitelný
</AccordionItem>
<AccordionItem title="Sestavení proběhne, ale import selže s chybou verze">
Sestavené C rozšíření Qiskit a nainstalovaná verze Qiskit musí mít stejnou verzi.  Přeinstaluj Qiskit pomocí `pip install "qiskit~=2.4.2"`
</AccordionItem>
<AccordionItem title="Přesestavil jsem C, ale obvod se nezměnil">
C rozšíření nelze znovu importovat za běhu. Restartuj kernel, znovu spusť příkazy MSVC (Krok 3) a poté znovu sestav
</AccordionItem>
<AccordionItem title="Skript PowerShellu byl zablokován">
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
</AccordionItem>
<AccordionItem title="Chyby délky cesty">
Použij krátkou kořenovou cestu na C:\ (například `C:\workspace`, nebo cestu, kterou jsi nastavil v kroku nastavení), nebo povol dlouhé cesty: Nastavení → Systém → Pro vývojáře → Dlouhé cesty
</AccordionItem>
<AccordionItem title="Conda je aktivní (příkazový řádek zobrazuje `(base)`) nebo se sestavení chová podivně po použití Anacondy">
Spusť `conda deactivate`, dokud `CONDA_DEFAULT_ENV` a `CONDA_PREFIX` nezmizí z prostředí. Ověř to pomocí `$env:CONDA_PREFIX`. Pokud přetrvávají, otevři nový PowerShell (ne příkazový řádek Anacondy) a zkus to znovu od Kroku 2.
</AccordionItem>
<AccordionItem title="Virtuální prostředí bylo vytvořeno z Pythonu spravovaného condou (zkontroluj řádek `home =` v souboru `.venv\pyvenv.cfg`)">
Virtuální prostředí zdědilo C runtime condy a nelze ho opravit na místě. Smaž ho, stáhni Python 3.12 z webu [Python](https://www.python.org/downloads/) a znovu sestav. Spusť `Remove-Item -Recurse -Force .venv`, poté znovu spusť úryvek pro detekci Pythonu z Kroku 1 pro nastavení `$PYTHON_EXE` a následně znovu vytvoř virtuální prostředí (Krok 2).
</AccordionItem>
<AccordionItem title="`DLL load failed` při importu">
Conda pravděpodobně proniká do virtuálního prostředí. Zkontroluj oba problémy uvedené bezprostředně výše. Také ověř, že Python je 64bitový: `python -c "import platform; print(platform.architecture())"`
</AccordionItem>
<AccordionItem title="Sestavení selže s poškozenými cestami nebo `C1083`">
Tvé uživatelské jméno nebo cesta k pracovnímu prostoru obsahuje jiné než ASCII znaky. Přesuň pracovní prostor na krátkou cestu obsahující pouze ASCII znaky (například `C:\workspace`)
</AccordionItem>
<AccordionItem title="Sestavení nebo import náhodně selže, při opakování funguje">
Složka pracovního prostoru je synchronizována pomocí OneDrive. Přesuň ji na lokální cestu, jako je `C:\workspace`
</AccordionItem>
<AccordionItem title="Sestavení přerušeno v polovině (například kvůli výpadku napájení)">
Smaž složku `_smoke_pkg` ve svém pracovním prostoru, znovu spusť buňku pro načtení MSVC a poté znovu spusť buňku s testem
</AccordionItem>
<AccordionItem title="`pip install` selže s chybou SSL certifikátu">
Tvá síť používá proxy, která zachytává HTTPS. Zkus spustit `pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org qiskit` nebo požádej svého správce sítě o CA certifikát proxy
</AccordionItem>
<AccordionItem title="Windows Defender umístí soubor `.pyd` do karantény">
Přidej složky `.venv` a `_smoke_pkg` svého pracovního prostoru do výjimek Defenderu tak, že přejdeš do Windows Security → Ochrana před viry a hrozbami → Spravovat nastavení → Výjimky
</AccordionItem>
<AccordionItem title="VS Build Tools nelze nainstalovat (chybí administrátorská práva)">
Je vyžadován přístup administrátora. Požádej své IT oddělení o přístup
</AccordionItem>
<AccordionItem title="`WinError 32` / soubor je používán během přesestavení">
Soubor .pyd je uzamčen běžícím kernelem. Restartuj kernel (Ctrl+Shift+P → Jupyter: Restart Kernel), znovu spusť Krok 3, a poté znovu sestav
</AccordionItem>
<AccordionItem title="Příkazy tiše nic nedělají (žádná chyba, žádný výstup)">
Možná jsi v cmd.exe místo v PowerShellu. Zkontroluj svůj příkazový řádek: PowerShell zobrazuje `PS C:\>`, cmd zobrazuje `C:\>`. Otevři PowerShell z nabídky Start nebo pomocí Win+X
</AccordionItem>
<AccordionItem title="Zdá se, že instalace MSVC uvízla">
Příznaky `--passive --wait` blokují PowerShell, zatímco instalátor běží na pozadí. Zkontroluj na hlavním panelu okno "Visual Studio Installer". Instalace může trvat 10-30 minut
</AccordionItem>
</Accordion>
