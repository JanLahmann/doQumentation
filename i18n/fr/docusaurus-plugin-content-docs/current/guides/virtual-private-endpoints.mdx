# Utiliser les points de terminaison privés virtuels pour VPC afin de se connecter en privé à IBM Quantum Platform {#use-virtual-private-endpoints-for-vpc-to-privately-connect-to-ibm-quantum-platform}

Utilise les Points de Terminaison Privés Virtuels (VPE) pour [Virtual Private Cloud (VPC)](https://cloud.ibm.com/docs/vpc) afin de te connecter à IBM Quantum&reg; depuis ton réseau VPC. La connexion utilise l'adresse IP que tu spécifies, allouée depuis un sous-réseau dans ton VPC.

Les VPE sont des interfaces IP virtuelles liées à une passerelle de point de terminaison créée sur une base par service. La passerelle de point de terminaison est une fonction virtualisée qui s'adapte horizontalement, est redondante et très disponible, et couvre toutes les zones de disponibilité de ton VPC. Les passerelles de point de terminaison permettent la communication entre les instances de serveurs virtuels au sein de ton VPC et le service IBM Cloud&reg; sur le réseau privé. VPE pour VPC te permet de contrôler tout l'adressage privé dans ton cloud. Pour plus d'informations, consulte [À propos des passerelles de point de terminaison privé virtuel](https://cloud.ibm.com/docs/vpc?topic=vpc-about-vpe).

Que tu utilises ou non des VPE, toute communication interne au sein du réseau d'IBM Quantum Platform utilise toujours des connexions privées plutôt que l'internet public.

Que ta connexion à IBM Quantum Platform elle-même soit publique ou privée dépend de l'utilisation ou non d'un VPE. Se connecter via les points de terminaison publics transmet toutes les données de requête et de réponse sur l'internet public. Se connecter via un VPE conserve ce trafic sur le réseau privé à la place.

Les VPE ne sont pris en charge que pour l'API et le SDK d'IBM Quantum Platform, comme décrit dans les sections suivantes. Le site web d'IBM Quantum Platform ne prend pas en charge les VPE et ne peut être accessible que via le réseau public.

## Avant de commencer {#before-you-begin}

Avant de cibler un VPE pour IBM Quantum Platform, effectue les étapes suivantes :

* [Crée un Virtual Private Cloud](https://cloud.ibm.com/docs/vpc?topic=vpc-getting-started).

* [Planifie la topologie réseau](https://cloud.ibm.com/docs/vpc?topic=vpc-vpe-planning-considerations) pour te connecter aux VPE.

* [Définis les contrôles d'accès](https://cloud.ibm.com/docs/vpc?topic=vpc-configure-acls-sgs-endpoint-gateways) pour ton VPE.

* Comprends les [restrictions de service](https://cloud.ibm.com/docs/vpc?topic=vpc-limitations).

* Comprends comment [consulter les détails d'un VPE](https://cloud.ibm.com/docs/vpc?topic=vpc-vpe-viewing-details-of-an-endpoint-gateway).


## Configurer un VPE pour IBM Quantum Platform {#set-up-a-vpe-for-ibm-quantum-platform}

Il existe plusieurs façons de créer une passerelle VPE. Si tu utilises le [CLI](https://cloud.ibm.com/docs/vpc?topic=vpc-vpc-reference&interface=cli#vpe-clis) ou l'[API](https://cloud.ibm.com/apidocs/vpc/latest#create-endpoint-gateway), tu dois spécifier le [Cloud Resource Name (CRN)](https://cloud.ibm.com/docs/account?topic=account-crn) de la région dans laquelle tu veux te connecter à IBM Quantum Platform. Consulte le tableau suivant pour les régions et CRN disponibles.

| Région | Plans   | Nom de domaine complet (FQDN) | Cloud Resource Name (CRN) |
|-----------------|-----------------|-----------------|-----------------|
| `us-east` | `Standard` | `private.us-east.quantum.cloud.ibm.com` | `crn:v1:bluemix:public:quantum-computing:us-east:::endpoint:private.us-east.quantum.cloud.ibm.com` |
| `eu-de` | `Standard` | `private.eu-de.quantum.cloud.ibm.com` | `crn:v1:bluemix:public:quantum-computing:eu-de:::endpoint:private.eu-de.quantum.cloud.ibm.com` |

### Configurer une passerelle de point de terminaison {#configuring-an-endpoint-gateway}

Pour configurer une passerelle VPE, suis ces étapes :

1. Liste les services disponibles, y compris les services d'infrastructure IBM Cloud disponibles (par défaut) pour tous les utilisateurs VPC.

1. [Crée une passerelle de point de terminaison](https://cloud.ibm.com/docs/vpc?topic=vpc-ordering-endpoint-gateway) pour IBM Quantum Platform que tu veux rendre accessible en privé au VPC.

1. [Associe une adresse IP réservée](https://cloud.ibm.com/docs/vpc?topic=vpc-bind-unbind-reserved-ip) à la passerelle de point de terminaison.

1. [Consulte les passerelles VPE créées](https://cloud.ibm.com/docs/vpc?topic=vpc-vpe-viewing-details-of-an-endpoint-gateway) associées à IBM Quantum Platform.


Tes instances de serveurs virtuels dans le VPC peuvent désormais accéder à ton instance IBM Quantum Platform en privé.

## Utiliser ton VPE pour IBM Quantum Platform {#use-your-vpe-for-ibm-quantum-platform}

Après avoir créé une passerelle de point de terminaison pour IBM Quantum Platform, suis ces étapes :

### Utiliser le VPE avec `qiskit-ibm-runtime` (SDK Python) {#use-the-vpe-with-qiskit-ibm-runtime-python-sdk}

<Admonition type="note">
La prise en charge du VPE nécessite `qiskit-ibm-runtime` v0.24.0 ou version ultérieure.
</Admonition>

Lors de l'instanciation de `QiskitRuntimeService`, spécifie `private_endpoint=True`.

```python
# For `token`, use the 44-character API_KEY you created 
# and saved from the IBM Quantum Platform Home dashboard
service = QiskitRuntimeService(token="your-API_KEY", 
                              instance="INSTANCE_CRN",
                              channel="ibm_cloud",
                              private_endpoint=True)
```

### Utiliser le VPE avec l'API IBM Quantum {#use-the-vpe-with-the-ibm-quantum-api}

Après avoir créé une passerelle de point de terminaison pour IBM Quantum Platform, utilise le nom de domaine pleinement qualifié (FQDN) du point de terminaison de service pour la région cible depuis [le tableau précédent](#set-up-a-vpe-for-ibm-quantum-platform).

```bash
  curl -X POST \
  https://private.us-east.quantum.cloud.ibm.com/api/v1/jobs \
  -H "Authorization: Bearer $BEARER_TOKEN" \
  -H "Service-CRN: $SERVICE_INSTANCE_CRN" \
  -d '{
    "backend": "backend",
    "program_id": "sampler"
  }'
```
