# Installare la C API di Qiskit {#install-the-qiskit-c-api}

Questa guida descrive come installare e utilizzare la C API di Qiskit. Dopo aver completato l'installazione, leggi [Estendere Python con la C API di Qiskit](/guides/c-extension-for-python).

Il seguente esempio costruisce un observable in C:

```c
// file: example.c
#include <stdio.h>
#include <stdint.h>
#include <qiskit.h>

int main(int argc, char *argv[]) {
    // build a 100-qubit empty observable
    uint32_t num_qubits = 100;
    QkObs *obs = qk_obs_zero(num_qubits);

    // add the term 2 * (X0 Y1 Z2) to the observable
    QkComplex64 coeff = {2, 0};
    QkBitTerm bit_terms[3] = {QkBitTerm_X, QkBitTerm_Y, QkBitTerm_Z}; 
    // bit terms: X Y Z
    uint32_t indices[3] = {0, 1, 2};  // indices: 0 1 2
    QkObsTerm term = {coeff, 3, bit_terms, indices, num_qubits};
    qk_obs_add_term(obs, &term);  // append the term

    // print some properties and the observable itself
    printf("num_qubits: %i\n", qk_obs_num_qubits(obs));
    printf("num_terms: %lu\n", qk_obs_num_terms(obs));
    printf("observable: %s\n", qk_obs_str(obs));

    // free the memory allocated for the observable
    qk_obs_free(obs);

    return 0;
}
```

## Sistemi UNIX-like {#unix-like}

Questa sezione fornisce le istruzioni di compilazione per i sistemi UNIX-like.

### Requisiti {#requirements}

La compilazione richiede i seguenti strumenti:
* Un compilatore Rust: consulta ad esempio la [guida all'installazione di Qiskit dal sorgente](/guides/install-qiskit-source)
* Un compilatore C: ad esempio GCC su Linux e Clang su MacOS. La C API di Qiskit è compatibile con un compilatore conforme allo standard [C11](https://en.wikipedia.org/wiki/C11_(C_standard_revision)).
* [`cbindgen`](https://github.com/mozilla/cbindgen): uno strumento per generare l'header C, installabile con `cargo install cbindgen`
   Esegui lo strumento dalla riga di comando dovrebbe essere abilitato, il che potrebbe richiedere di esportare la variabile `PATH` per includere `/path/to/.cargo/bin`.
* Libreria Python installata (Python 3.9+): la libreria Python è necessaria durante il collegamento dinamico. Tieni presente che Python non viene utilizzato a runtime e l'interprete non viene mai inizializzato; è sufficiente che alcuni simboli di `libpython` siano definiti. Consulta [questa issue](https://github.com/Qiskit/qiskit/issues/14240) per ulteriori dettagli.
* (GNU) Make: opzionale, ma consigliato per automatizzare il processo di installazione.

Questo codice verifica che tutto sia stato installato correttamente:

```bash
rustc --version
gcc --version
cbindgen --version
make --version  # optional, but recommended
```

### Compilazione {#build}

Per compilare l'header C e la libreria, puoi eseguire il seguente comando Make[^1] nella root di Qiskit:
[^1]: Se non hai installato Make, controlla il `Makefile` nella root di Qiskit per i comandi necessari — oppure installa Make; non è mai troppo tardi.)

```bash
make c
```
che fornirà la libreria condivisa compilata in `dist/c/lib` e l'header `qiskit.h` con tutte le dichiarazioni delle funzioni in `dist/c/include`. Tieni presente che il nome esatto della libreria dipende dalla piattaforma; ad esempio `libqiskit.so` su UNIX e `libqiskit.dylib` su MacOS.
(Nota che questo passaggio attualmente emette molti warning, il che è previsto e non è motivo di preoccupazione. Le versioni future rimuoveranno i warning.)

Puoi quindi compilare un programma C utilizzando l'header e la libreria C di Qiskit:

```bash
gcc example.c -o example.o -I /path/to/dist/c/include -L /path/to/dist/c/lib -lqiskit
```
Per assicurarti che la libreria Qiskit venga trovata durante il collegamento, imposta il percorso della libreria a runtime in modo che includa `/path/to/dist/c/lib`. Se la libreria Python non è disponibile di default durante il collegamento dinamico, anche questa deve essere aggiunta. I comandi dipendono dalla piattaforma. Su Linux:

```bash
export LD_LIBRARY_PATH=/path/to/dist/c/lib:$LD_LIBRARY_PATH
# On Linux, the Python library is typically included 
# in the dynamic library path by default.
export LD_LIBRARY_PATH=/path/to/python/lib:$LD_LIBRARY_PATH
```
Su MacOS:

```bash
export DYLD_LIBRARY_PATH=/path/to/dist/c/lib:$DYLD_LIBRARY_PATH
export DYLD_LIBRARY_PATH=/path/to/python/lib:$DYLD_LIBRARY_PATH
```
In alternativa, puoi impostare il percorso della libreria a runtime durante la compilazione aggiungendo

```
-Wl,-rpath,/path/to/dist/c/lib
# same for Python
```
ai flag del compilatore.
Inoltre, la libreria Python deve essere disponibile durante il collegamento dinamico. Negli ambienti Linux questo è tipicamente il comportamento predefinito.

Ora puoi eseguire il binario:

```bash
./example.o
```
che, usando il frammento di esempio mostrato in precedenza, dovrebbe stampare

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```

## Windows {#windows}

Questa sezione fornisce le istruzioni di compilazione per i sistemi Windows.

Esistono due modi indipendenti per usare la C API su Windows:

* **Costruire moduli di estensione Python** che usano la C API di Qiskit. Segui i passi 1-5. Questo percorso usa gli header C forniti con il pacchetto Python `qiskit` e non richiede Rust o cbindgen.

* **Costruire la libreria C standalone** da collegare a un programma C puro, come avviene nella sezione [UNIX-like](#unix). Completa il passo 1, poi salta a [Build the standalone library](#build-the-standalone-library), che elenca i suoi requisiti aggiuntivi.


### Requisiti {#requirements-1}

- Sono richiesti i diritti di amministratore per alcuni passi.

- 5-8 GB di spazio libero su disco.

- Un compilatore C: Microsoft Visual C++ (MSVC), installato al passo 1.

- Un'installazione Python a 64 bit (3.10 o successiva), installata al Passaggio 1.


### Prima di iniziare {#before-you-begin}

Crea il tuo workspace. Dovrebbe essere un percorso breve su un'unità locale. Non usare cartelle sincronizzate con OneDrive (come Documenti o Desktop), unità di rete o percorsi con spazi o caratteri non ASCII. Se il tuo nome utente contiene caratteri non inglesi, non metterlo sotto la tua cartella utente.

Esempi di percorsi di workspace validi: `C:\workspace`, `D:\workspace`, `C:\Users\john\workspace`

### Passaggio 3 - Carica l'ambiente MSVC {#step-3-load-the-msvc-environment}

Esegui il seguente codice in ogni nuova sessione Python (per esempio, ogni volta che riavvii un kernel Jupyter). Individua e carica automaticamente l'ambiente per sviluppatori MSVC così non hai bisogno del prompt dei comandi integrato x64.

L'esempio in questa documentazione compila moduli di estensione C usando `setuptools` con MSVC. In generale, definisci `QISKIT_PYTHON_EXTENSION`, includi `qiskit.h` e chiami `qk_import()` nella tua funzione init. Al momento della compilazione sono necessarie solo le intestazioni da `qiskit.capi.get_include()` — non viene collegata alcuna libreria. Consulta [Extend Qiskit in Python with C](/guides/c-extension-for-python) per i dettagli.

<Accordion>
  <AccordionItem title="Carica l'ambiente MSVC">

```python
import os, sys, subprocess, glob, shutil

def load_msvc_env():
    if os.name != "nt":
        return "Not Windows — the system C compiler is used as-is."
    if shutil.which("cl"):
        return "cl.exe is already available in this kernel."

    pf86 = os.environ.get("ProgramFiles(x86)", r"C:\Program Files (x86)")
    pf = os.environ.get("ProgramFiles", r"C:\Program Files")
    vcvars = None

    vswhere = os.path.join(pf86, "Microsoft Visual Studio", "Installer", "vswhere.exe")
    if os.path.isfile(vswhere):
        # vswhere outputs UTF-8 regardless of system locale
        inst = subprocess.run(
            [vswhere, "-latest", "-products", "*",
             "-requires", "Microsoft.VisualStudio.Component.VC.Tools.x86.x64",
             "-property", "installationPath"],
            capture_output=True, text=True, encoding="utf-8").stdout.strip()
        if inst:
            cand = os.path.join(inst, "VC", "Auxiliary", "Build", "vcvars64.bat")
            if os.path.isfile(cand):
                vcvars = cand

    if not vcvars:
        pat = os.path.join("Microsoft Visual Studio", "*", "*",
                           "VC", "Auxiliary", "Build", "vcvars64.bat")
        hits = glob.glob(os.path.join(pf86, pat)) + glob.glob(os.path.join(pf, pat))
        if hits:
            vcvars = sorted(hits)[-1]

    if not vcvars:
        return ("Could not find vcvars64.bat. Install MSVC Build Tools (Step 1.3), "
                "or launch Jupyter from the x64 Native Tools Command Prompt.")

    # cmd.exe outputs in the OEM codepage (cp437/cp850/etc.), not the ANSI codepage
    out = subprocess.run(f'"{vcvars}" >nul 2>&1 && set',
                         capture_output=True, text=True, encoding="oem", shell=True).stdout
    for line in out.splitlines():
        if "=" in line:
            k, _, v = line.partition("=")
            os.environ[k] = v

    return ("Loaded MSVC from:\n  " + vcvars) if shutil.which("cl") \
        else "Ran vcvars64.bat but cl.exe is still not found — check your MSVC install."

print(load_msvc_env())
print("cl.exe on PATH:", shutil.which("cl") is not None)
```
</AccordionItem>

### Passaggio 4 - Smoke test: compila un'estensione C {#step-4-smoke-test-build-a-c-extension}

Esegui il seguente codice. Scrive file sorgente in `_smoke_pkg/`, compila un'estensione C rispetto all'API C di Qiskit e importa il risultato. Se stampa "SMOKE TEST PASSED", la tua toolchain è pronta.

Il pacchetto segue il processo [Extend Qiskit in Python with C](/guides/c-extension-for-python) e utilizza funzioni dal [riferimento API C di Qiskit](https://docs.quantum.ibm.com/api/qiskit-c).

<Accordion>
  <AccordionItem title="Codice dello smoke test">

```python
import sys, subprocess, pathlib, importlib

root = pathlib.Path("_smoke_pkg")
pkg = root / "src" / "qgss_smoke"
pkg.mkdir(parents=True, exist_ok=True)

(root / "pyworkspace.toml").write_text("""
[build-system]
requires = ["setuptools", "qiskit>=2.4.2"]
build-backend = "setuptools.build_meta"

[workspace]
name = "qgss_smoke"
version = "0.0.1"
dependencies = ["qiskit>=2.4.2"]

[tool.setuptools]
package-dir = {"" = "src"}
""".lstrip())

(root / "setup.py").write_text("""
import qiskit
from setuptools import setup, Extension

core_ext = Extension(
    name="qgss_smoke._core",
    sources=["src/qgss_smoke/_coremodule.c"],
    include_dirs=[qiskit.capi.get_include()],
)
setup(ext_modules=[core_ext])
""".lstrip())

(pkg / "__init__.py").write_text("from . import _core\nbuild_demo = _core.build_demo\n")

(pkg / "_coremodule.c").write_text("""
#define QISKIT_PYTHON_EXTENSION
#include <Python.h>
#include <qiskit.h>
#include <stdint.h>

static PyObject *build_demo(PyObject *self, PyObject *args) {
    QkCircuit *qc = qk_circuit_new(2, 0);
    uint32_t q0[1] = {0};
    qk_circuit_gate(qc, QkGate_H, q0, NULL);
    uint32_t q1[1] = {1};
    qk_circuit_gate(qc, QkGate_X, q1, NULL);
    return qk_circuit_to_python_full(qc);
}

static PyMethodDef core_methods[] = {
    {"build_demo", build_demo, METH_NOARGS, "Build a 2-qubit demo circuit in C."},
    {NULL, NULL, 0, NULL},
};
static struct PyModuleDef core_module = {
    .m_base = PyModuleDef_HEAD_INIT,
    .m_name = "_core",
    .m_methods = core_methods,
};
PyMODINIT_FUNC PyInit__core(void) {
    if (qk_import() < 0) {
        return NULL;
    }
    return PyModuleDef_Init(&core_module);
}
""".lstrip())

# On Windows, an imported .pyd is file-locked by the OS. Drop the module from
# sys.modules BEFORE pip install --force-reinstall, otherwise pip fails with
# WinError 32 ("file in use") trying to overwrite the locked .pyd.
if "qgss_smoke._core" in sys.modules:
    del sys.modules["qgss_smoke._core"]
if "qgss_smoke" in sys.modules:
    del sys.modules["qgss_smoke"]

r = subprocess.run(
    [sys.executable, "-m", "pip", "install", "--no-build-isolation",
     "--force-reinstall", "--quiet", str(root.resolve())],
    capture_output=True, text=True,
)
if r.returncode != 0:
    output = (r.stderr + r.stdout).strip()
    print("BUILD FAILED:\n")
    print(output)
    if "WinError 32" in output or "being used by another process" in output:
        print("\n--- TIP ---")
        print("The .pyd file is locked because it was previously imported in this kernel.")
        print("Restart the kernel (Ctrl+Shift+P → 'Jupyter: Restart Kernel'), then rerun")
        print("the Step 3 MSVC cell first, then this cell again.")
    elif "cl.exe" in output.lower() or "vcvars" in output.lower() or "cannot find" in output.lower():
        print("\n--- TIP ---")
        print("The compiler was not found. rerun the Step 3 cell to load the MSVC environment.")
else:
    importlib.invalidate_caches()
    import qgss_smoke
    from qiskit import QuantumCircuit

    qc = qgss_smoke.build_demo()
    ops = dict(qc.count_ops())
    ok = isinstance(qc, QuantumCircuit) and ops.get("h") == 1 and ops.get("x") == 1

    print("Returned object is a QuantumCircuit:", isinstance(qc, QuantumCircuit))
    print("Gates built in C:", ops)
    print("\nSMOKE TEST PASSED — your Windows toolchain can build Qiskit C extensions."
          if ok else "\nSomething is off — check the gates above.")
```
</AccordionItem>
</Accordion>

### Passaggio 5 — Configura VS Code (opzionale) {#step-5-configure-vs-code-optional}

### Compila la libreria standalone {#build-the-standalone-library}

Questa sezione compila la libreria C standalone, necessaria solo se vuoi compilare e collegare programmi C puri, come descritto nella sezione [UNIX-like](#unix). Oltre ai prerequisiti del Passaggio 1, sono necessari i seguenti strumenti:

* Un compilatore Rust: vedi per esempio la [guida sull'installazione di Qiskit dal sorgente](https://github.com/Qiskit/qiskit/blob/main/CONTRIBUTING.md#installing-qiskit-from-source)

* [`cbindgen`](https://github.com/mozilla/cbindgen): uno strumento per creare l'intestazione C, che puoi installare con `cargo install cbindgen`.
    L'esecuzione dello strumento dalla riga di comando dovrebbe essere abilitata, il che potrebbe richiedere l'aggiornamento della variabile `PATH` per includere il percorso di cargo.
* Un'installazione Python con accesso sia a ``python3.lib`` che a ``python3.dll``
* Un clone del [repository Qiskit](https://github.com/Qiskit/qiskit) (`git clone https://github.com/Qiskit/qiskit.git`)
<Accordion>
<AccordionItem title="Compila la libreria standalone">
Innanzitutto, compila la libreria dinamica `qiskit_cext`, eseguendo quanto segue nel terminale VS Code (PowerShell) nella root di Qiskit:

```powershell
$env:PATH = "\path\to\pythonlib;" + $env:PATH
cargo rustc --release --crate-type cdylib -p qiskit-cext
```
Questo genererà la libreria dinamica ``.dll`` e il file ``.dll.lib`` associato in `target/release`.
Successivamente, genera l'header con:

```powershell
cbindgen --crate qiskit-cext --output dist\c\include\qiskit.h
```
Questo scrive l'header compatibile con MSVC in ``dist\c\include``.

Ora puoi usare `cl` per compilare il programma C. Per assicurarti che il compilatore trovi la libreria qiskit, includi `target\release` nella variabile `PATH`.

```powershell
$env:PATH = "\path\to\target\release;" + $env:PATH
cl example.c qiskit_cext.dll.lib -I\path\to\dist\c\include
```

Prima di eseguire il programma, includi il percorso del tuo ``python3.dll``.

```powershell
$env:PATH = "\path\to\python3-dll;" + $env:PATH
.\example.exe
```
che dovrebbe stampare

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```
</AccordionItem>
</Accordion>

### Risoluzione dei problemi {#troubleshooting}
<Accordion>
<AccordionItem title="`winget` non viene riconosciuto">
Aggiorna [App Installer](https://apps.microsoft.com/detail/9nblggh4nns1) dal Microsoft Store, oppure usa i link di download manuale pertinenti
</AccordionItem>
<AccordionItem title="`cl` non viene riconosciuto">
Riesegui la cella di caricamento MSVC (Passaggio 3), oppure usa l'x64 Native Tools Command Prompt
</AccordionItem>
<AccordionItem title="`python` apre il Microsoft Store">
Vai su Impostazioni → App → Impostazioni avanzate app → Alias di esecuzione delle app e disattiva `python.exe`
</AccordionItem>
<AccordionItem title="`.ps1 cannot be loaded` / script disabilitati">
Esegui `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` poi riprova
</AccordionItem>
<AccordionItem title="`cannot open file 'qiskit.h'`">
Esegui `python -c "import qiskit.capi; print(qiskit.capi.get_include())"` e conferma che il percorso esista
</AccordionItem>
<AccordionItem title="`qiskit.capi` non trovato">
Esegui `pip install "qiskit[visualization]~=2.4.2"`
</AccordionItem>
<AccordionItem title="La compilazione di `qiskit-aer` fallisce">
Esegui `pip install qiskit-aer --only-binary=:all:`. Se anche questo fallisce, usa Python 3.12 oppure salta aer, che è opzionale
</AccordionItem>
<AccordionItem title="La compilazione riesce ma l'importazione fallisce con un errore di versione">
L'estensione C di Qiskit compilata e la versione di Qiskit installata devono avere la stessa versione. Reinstalla Qiskit con `pip install "qiskit~=2.4.2"`
</AccordionItem>
<AccordionItem title="Ho ricompilato il C ma il circuito non è cambiato">
Un'estensione C non può essere reimportata a runtime. Riavvia il kernel, riesegui i comandi MSVC (Passaggio 3), poi ricompila
</AccordionItem>
<AccordionItem title="Lo script PowerShell è stato bloccato">
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
</AccordionItem>
<AccordionItem title="Errori di lunghezza del percorso">
Usa un percorso radice breve su C:\ (per esempio, `C:\workspace`, o il percorso impostato nel passaggio di configurazione), oppure abilita i percorsi lunghi: Impostazioni → Sistema → Per sviluppatori → Percorsi lunghi
</AccordionItem>
<AccordionItem title="Conda è attivo (il prompt mostra `(base)`) oppure le compilazioni si comportano in modo strano dopo aver usato Anaconda">
Esegui `conda deactivate` finché `CONDA_DEFAULT_ENV` e `CONDA_PREFIX` non scompaiono entrambi dall'ambiente. Controlla con `$env:CONDA_PREFIX`. Se persistono, apri un nuovo PowerShell (non un prompt Anaconda) e riprova dal Passaggio 2.
</AccordionItem>
<AccordionItem title="L'ambiente virtuale è stato creato da un Python gestito da conda (controlla la riga `home =` in `.venv\pyvenv.cfg`)">
L'ambiente virtuale ha ereditato il runtime C di conda e non può essere corretto sul posto. Eliminalo, scarica Python 3.12 dal sito [Python](https://www.python.org/downloads/) e ricompila. Esegui `Remove-Item -Recurse -Force .venv`, poi riesegui lo snippet di rilevamento Python nel Passaggio 1 per impostare `$PYTHON_EXE`, poi ricrea l'ambiente virtuale (Passaggio 2).
</AccordionItem>
<AccordionItem title="`DLL load failed` durante l'importazione">
È probabile che Conda stia interferendo con l'ambiente virtuale. Controlla entrambi i problemi appena sopra. Verifica anche che Python sia a 64 bit: `python -c "import platform; print(platform.architecture())"`
</AccordionItem>
<AccordionItem title="La compilazione fallisce con percorsi corrotti o `C1083`">
Il tuo nome utente o percorso del workspace contiene caratteri non ASCII. Sposta il workspace in un percorso breve solo ASCII (per esempio, `C:\workspace`)
</AccordionItem>
<AccordionItem title="La compilazione o l'importazione falliscono casualmente, funzionano al riavvio">
La cartella del workspace è sincronizzata da OneDrive. Spostala in un percorso locale come `C:\workspace`
</AccordionItem>
<AccordionItem title="Compilazione interrotta a metà (per esempio, c'è stata un'interruzione di corrente)">
Elimina la cartella `_smoke_pkg` nel tuo workspace, riesegui la cella di caricamento MSVC, poi riesegui la cella dello smoke test
</AccordionItem>
<AccordionItem title="`pip install` fallisce con un errore di certificato SSL">
La tua rete usa un proxy che intercetta HTTPS. Prova a eseguire `pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org qiskit` oppure chiedi al tuo amministratore di rete il certificato CA del proxy
</AccordionItem>
<AccordionItem title="Windows Defender mette in quarantena il file `.pyd`">
Aggiungi le cartelle `.venv` e `_smoke_pkg` del tuo workspace alle esclusioni di Defender andando su Sicurezza di Windows → Protezione da virus e minacce → Gestisci impostazioni → Esclusioni
</AccordionItem>
<AccordionItem title="Impossibile installare VS Build Tools (nessun diritto di amministratore)">
È richiesto l'accesso come amministratore. Chiedi accesso al tuo reparto IT
</AccordionItem>
<AccordionItem title="`WinError 32` / file in uso durante la ricompilazione">
Il .pyd è bloccato dal kernel in esecuzione. Riavvia il kernel (Ctrl+Shift+P → Jupyter: Restart Kernel), riesegui il Passaggio 3, poi ricompila
</AccordionItem>
<AccordionItem title="I comandi non fanno silenziosamente nulla (nessun errore, nessun output)">
Potresti trovarti in cmd.exe invece che in PowerShell. Controlla il tuo prompt: PowerShell mostra `PS C:\>`, cmd mostra `C:\>`. Apri PowerShell dal menu Start o con Win+X
</AccordionItem>
<AccordionItem title="L'installazione MSVC sembra bloccata">
I flag `--passive --wait` bloccano PowerShell mentre l'installer viene eseguito in background. Controlla la barra delle applicazioni per una finestra "Visual Studio Installer". L'installazione può richiedere 10-30 minuti
</AccordionItem>
</Accordion>
