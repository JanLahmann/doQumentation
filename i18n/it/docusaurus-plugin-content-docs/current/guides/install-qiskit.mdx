# Installare Qiskit {#install-qiskit}

Che tu lavori in locale o in un ambiente cloud, il primo passo per tutti gli utenti è installare Qiskit.

<span id="local"></span>

## Installa Qiskit SDK {#install-the-qiskit-sdk}

1. Installa Python. Controlla la sezione "Programming Language" nella [pagina del progetto Qiskit su PyPI](https://pypi.org/project/qiskit/) per sapere quali versioni di Python sono supportate dall'ultima release. Per le istruzioni di download, consulta la [Guida per principianti di Python](https://wiki.python.org/moin/BeginnersGuide/Download).


    È consigliato usare [ambienti virtuali Python](https://docs.python.org/3.10/tutorial/venv.html) per separare Qiskit da altre applicazioni.

    <Admonition type="note">
    These instructions use the standard Python distribution from [pypi.org](https://pypi.org/). However, you can use other Python distributions, such as [Anaconda](https://docs.anaconda.com/anaconda/) or [miniconda](https://docs.anaconda.com/miniconda/), along with other dependency management workflows like [Poetry](https://python-poetry.org/docs/).
    </Admonition>

    <Accordion>
    <AccordionItem title="Se sei nuovo agli ambienti virtuali, fai clic per espandere e ottenere maggiori informazioni.">
    Un ambiente virtuale Python è uno spazio isolato per lavorare con Python per uno scopo specifico — così puoi installare i pacchetti che desideri e configurare librerie, dipendenze e così via, senza influire sull'ambiente Python "base" della tua macchina.

    Scegli una posizione preferita in cui conservare le informazioni sui tuoi ambienti virtuali. Di norma vengono salvati in una directory chiamata `.venv` all'interno di ogni directory di progetto su cui stai lavorando.

    Scegli una posizione preferita in cui archiviare le informazioni sui tuoi ambienti virtuali. Tipicamente vengono archiviate in una directory chiamata `.venv` all'interno di ogni directory di progetto in cui stai lavorando.
    </AccordionItem>
    </Accordion>

    Per prima cosa, vai nella directory del progetto e crea un ambiente minimale con solo Python installato.

        <OperatingSystemTabs>
          <TabItem value="mac" label="macOS">

            ```shell
            python3 -m venv .venv
            ```
          </TabItem>

          <TabItem value="linux" label="Linux">

            ```shell
            python3 -m venv .venv
            ```
          </TabItem>

          <TabItem value="win" label="Windows">

            ```text
            python -m venv .venv
            ```
          </TabItem>
         </OperatingSystemTabs>

    Quindi, attiva il nuovo ambiente.

         <OperatingSystemTabs>
           <TabItem value="mac" label="macOS">

             ```shell
             source .venv/bin/activate
             ```
           </TabItem>

           <TabItem value="linux" label="Linux">

             ```shell
             source .venv/bin/activate
             ```
           </TabItem>

           <TabItem value="win" label="Windows">
              Se usi PowerShell:

             ```text
             .venv\Scripts\Activate.ps1
             ```
             Se usi Git Bash:

             ```text
             source .venv/scripts/activate
             ```
              Se usi il prompt dei comandi:

             ```text
             .venv\Scripts\activate
             ```
           </TabItem>
         </OperatingSystemTabs>

1. [Installa pip](https://pip.pypa.io/en/stable/installation/) se non è già presente nel tuo ambiente. Pip è un gestore di pacchetti Python che usi per installare Qiskit e altri pacchetti Python. Usa `pip list` per vedere cosa è presente nel tuo ambiente virtuale. Nella maggior parte degli ambienti Python, pip è già installato.


1. Installa Qiskit SDK.


      ```shell
      pip install qiskit
      ```

      <Admonition type="tip" title="Aggiungi il supporto per la visualizzazione">
      Se intendi usare funzionalità di visualizzazione o notebook Jupyter, installa anche il modulo `qiskit.visualization`. Consulta il [riferimento API per le visualizzazioni](https://docs.quantum.ibm.com/api/qiskit/visualization) per maggiori informazioni.
      </Admonition>

<span id="local-jupyter"></span>
1. Se vuoi eseguire un notebook Jupyter con i pacchetti Qiskit appena installati, devi installare Jupyter nel tuo ambiente.

      ```shell
      pip install jupyter
      ```
    Poi apri il notebook nel seguente modo:

      ```shell
      jupyter notebook <path/to/notebook.ipynb>
      ```

Se hai intenzione di lavorare in locale e usare i simulatori integrati in Qiskit, l'installazione è completata. Se vuoi eseguire job su QPU IBM, continua con la [configurazione del tuo account IBM Cloud](cloud-setup).

<Admonition type="note" title="Resta aggiornato con le ultime versioni">
Controlla periodicamente le [note di rilascio di Qiskit](https://docs.quantum.ibm.com/api/qiskit/release-notes) per conoscere le nuove versioni. Consigliamo di aggiornare frequentemente i requisiti per `qiskit` eseguendo `pip install -U qiskit`.
</Admonition>

## Risoluzione dei problemi {#troubleshooting}

<Accordion>
<AccordionItem title="Errore `No Module 'qiskit'` con Jupyter Notebook">
  Se hai usato ``pip install qiskit`` e configurato il tuo ambiente virtuale in
  Anaconda, potresti ottenere l'errore ``No Module 'qiskit'`` quando esegui un tutorial
  in Jupyter Notebook. Se non hai installato Qiskit o configurato il tuo
  ambiente virtuale, puoi seguire i passaggi di [installazione](#qiskit-install).

  L'errore è causato dal tentativo di importare il pacchetto Qiskit in un
  ambiente in cui Qiskit non è installato. Se hai avviato Jupyter Notebook
  dall'Anaconda-Navigator, è possibile che Jupyter Notebook sia in esecuzione
  nell'ambiente base (root), invece che nel tuo ambiente
  virtuale. Scegli un ambiente virtuale nell'Anaconda-Navigator dal
  menu a discesa **Applications on**. In questo menu, puoi vedere
  tutti gli ambienti virtuali all'interno di Anaconda, e puoi
  selezionare l'ambiente in cui hai installato Qiskit per avviare Jupyter
  Notebook.
</AccordionItem>

<AccordionItem title="Errori di compilazione durante l'installazione">
  Qiskit dipende da numerosi altri pacchetti Python open-source, che
  vengono installati automaticamente eseguendo ``pip install qiskit``. A seconda
  della piattaforma del tuo sistema e della versione di Python, è possibile che un particolare
  pacchetto non fornisca binari precompilati per il tuo sistema. Puoi fare riferimento
  a [Supporto del sistema operativo](#operating-system-support) per un elenco delle piattaforme supportate da Qiskit, alcune
  delle quali potrebbero richiedere un compilatore aggiuntivo. Nei casi in cui non sono
  disponibili binari precompilati, ``pip`` tenterà di compilare il pacchetto
  dal sorgente, il che a sua volta potrebbe richiedere alcune dipendenze aggiuntive che devono
  essere installate manualmente.

  Se l'output di ``pip install qiskit`` contiene righe simili a:

  ```
  Failed building wheel for SOME_PACKAGE
  ...
  build/temp.linux-x86_64-3.5/_openssl.c:498:30: fatal error
  compilation terminated.
  error: command 'x86_64-linux-gnu-gcc' failed with exit status 1
  ```

  controlla la documentazione del pacchetto che non è riuscito a installarsi (nell'
  esempio di codice, ``SOME_PACKAGE``) per informazioni su come installare le librerie
  necessarie per la compilazione dal sorgente.
</AccordionItem>
</Accordion>

## Supporto dei sistemi operativi {#operating-system-support}

Qiskit si impegna a supportare il maggior numero possibile di sistemi operativi, ma a causa dei limiti nelle risorse di test disponibili e nella disponibilità dei sistemi operativi, non tutti i sistemi operativi possono essere supportati. Il supporto dei sistemi operativi per Qiskit è suddiviso in tre livelli con diversi gradi di supporto per ciascun livello. Per le piattaforme al di fuori di queste, come FreeBSD o WebAssembly (WASI), Qiskit potrebbe comunque essere installabile, ma non è testato e dovrai compilare Qiskit (e probabilmente le sue dipendenze) dai sorgenti.

Inoltre, Qiskit supporta solo l'implementazione CPython del linguaggio Python. L'esecuzione con altri interpreti Python come PyPy non è supportata.

### Qiskit v2.x {#qiskit-v2x}

Nella serie di release Qiskit v2.x, le piattaforme supportate sono:

<Accordion>
<AccordionItem title="Livello 1">
  I sistemi operativi di Livello 1 sono completamente testati come parte dei processi di sviluppo per garantire che qualsiasi modifica proposta funzioni correttamente. I binari precompilati vengono creati, testati e pubblicati su PyPI come parte del processo di rilascio. In genere, finché è installato un ambiente Python funzionante, Qiskit può essere installato su questi sistemi operativi senza bisogno di installare ulteriori dipendenze.

  I sistemi operativi di Livello 1 sono completamente testati come parte del processo di sviluppo per garantire che qualsiasi modifica proposta funzioni correttamente. I binari precompilati vengono creati, testati e pubblicati su PyPI come parte del processo di rilascio. In genere, finché è installato un ambiente Python funzionante, Qiskit può essere installato su questi sistemi operativi senza dover installare ulteriori dipendenze.

  - Linux x86_64 (distribuzioni compatibili con la specifica di packaging [manylinux 2014](https://www.python.org/dev/peps/pep-0599/)).

  - Windows 64-bit (supportati Windows 10 e versioni successive)

  - Windows a 64 bit (supportato Windows 10 e successivi)

  - Linux AArch64 (distribuzioni compatibili con la specifica di packaging [manylinux 2014](https://www.python.org/dev/peps/pep-0599/))
</AccordionItem>
<AccordionItem title="Livello 2">
  I sistemi operativi di Livello 2 non vengono testati come parte del processo di sviluppo. Tuttavia, i binari precompilati vengono creati, testati e pubblicati su PyPI come parte del processo di rilascio, e questi pacchetti possono essere installati con solo un ambiente Python funzionante.
  Potrebbe esserci un ritardo nel rilascio dei pacchetti per questi sistemi, poiché i fallimenti dei test potrebbero non essere rilevati fino a molto più tardi, e i fallimenti durante la pubblicazione non bloccheranno la pubblicazione del pacchetto per i sistemi di Livello 1.

  I sistemi operativi di Livello 2 non vengono testati come parte del processo di sviluppo. Tuttavia, i binari precompilati vengono creati, testati e pubblicati su PyPI come parte del processo di rilascio, e ci si aspetta che questi pacchetti possano essere installati con solo un ambiente Python funzionante.
  Potrebbe esserci un ritardo nel rilascio dei pacchetti per questi sistemi, poiché i fallimenti dei test potrebbero non essere rilevati fino a molto più tardi, e i fallimenti durante la pubblicazione non bloccheranno la pubblicazione del pacchetto per i sistemi di Livello 1.

  - macOS x86_64 (10.12 o successivo)
</AccordionItem>
<AccordionItem title="Livello 3">
  I sistemi operativi di Livello 3 non vengono testati come parte del processo di sviluppo. I binari precompilati vengono creati e pubblicati su PyPI come parte del processo di rilascio ma non vengono testati. Potrebbero non essere installabili con solo un ambiente Python funzionante e potrebbero richiedere un compilatore C/C++ o programmi aggiuntivi per compilare le dipendenze dal sorgente come parte del processo di installazione. Il supporto per questi sistemi operativi è solo su base best-effort.

  Sistemi operativi di Livello 3:

  - Linux ppc64le (distribuzioni compatibili con la specifica di packaging [manylinux 2014](https://www.python.org/dev/peps/pep-0599/))

  - Linux s390x (distribuzioni compatibili con la specifica di packaging [manylinux 2014](https://www.python.org/dev/peps/pep-0599/))
</AccordionItem>
</Accordion>

A partire da Qiskit v2.0.0, sono supportate solo piattaforme a 64 bit e le piattaforme a 32 bit non sono supportate. Non sarà possibile compilare dal sorgente
neanche su piattaforme a 32 bit, poiché internamente il codice Rust di Qiskit assume una larghezza del puntatore di 64 bit.
