# Qiskit SDK v2.3 {#qiskit-sdk-v23}

## Gennaio 2026 {#january-2026}
- Costruendo sullo slancio stabilito lungo la serie v2.x, che si è concentrata sul posizionamento di Qiskit come piattaforma leader per i workflow ibridi quantum-HPC, [Qiskit SDK v2.3](https://www.ibm.com/quantum/blog/qiskit-2-3-release-summary) offre una significativa espansione della C API insieme a strumenti più veloci e flessibili per costruire e ottimizzare i circuiti quantistici.


  I principali aggiornamenti includono:

  - **Passaggi di transpiler personalizzati in C** - Scrivi passaggi di transpiler personalizzati tramite la C API di Qiskit utilizzando il nuovo oggetto `QkDag` e un oggetto `QkTarget` esteso, che consentono l'ispezione, la modifica e l'estensione passo passo del processo di compilazione — senza ricostruire l'intera pipeline del compilatore.


  - **Selezione più veloce del layout hardware** - Aggiornamenti e miglioramenti delle prestazioni basati su Rust per `VF2Layout` e `VF2PostLayout` migliorano la velocità e la scalabilità della selezione del layout circuito-hardware, riducendo l'overhead di compilazione e migliorando la fedeltà sull'hardware quantistico.


  - **Nuova misurazione di Pauli multi-qubit** - La nuova istruzione `PauliProductMeasurement` consente la misurazione proiettiva congiunta su più qubit in un'unica operazione, sbloccando la compilazione verso il calcolo basato su Pauli - una rappresentazione comune nel calcolo quantistico fault-tolerant.


  - **Miglioramenti nella transpilazione early fault-tolerant** - Miglioramenti delle prestazioni e delle funzionalità per la transpilazione verso target early fault-tolerant - in particolare i target Clifford+T - aiutano gli utenti a costruire in modo più efficiente pipeline di transpilazione per i futuri QPU.


  Queste funzionalità offrono agli sviluppatori maggiore flessibilità per personalizzare le ottimizzazioni dei circuiti quantistici e integrarsi con i workflow HPC esistenti. [Visita il blog](https://www.ibm.com/quantum/blog/qiskit-2-3-release-summary) per il riepilogo tecnico completo.

Ti chiedi cosa è cambiato? Leggi il [changelog](https://github.com/Qiskit/qiskit/releases/tag/2.3.0) e le [note di rilascio della v2.3](https://docs.quantum.ibm.com/api/qiskit/release-notes/2.3).

## Aprile 2026 {#april-2026}

<span id="executor-primitive"></span>
- **Introducing the Executor primitive**: We're excited to announce the release of the new `Executor` primitive and a new version of the noise-learning helper class, `NoiseLearnerV3`, both of which were first previewed at QDC 2025.

  Insieme a [Samplomatic](https://qiskit.github.io/samplomatic/index.html), costituiscono il [directed execution model](/guides/directed-execution-model), che fornisce piena trasparenza e controllo per mettere a punto il tuo workflow di mitigazione degli errori. Il tutorial [Probabilistic error cancellation with shaded lightcones](https://qiskit.github.io/qiskit-addon-slc/tutorials/01_getting_started.html), ad esempio, dimostra come questo modello viene utilizzato per combinare tecniche avanzate, tra cui shaded lightcones, probabilistic error cancellation (PEC), Twirled Readout Error eXtinction (TREX) e [post-selezione basata sulla misurazione](/guides/post-selection), per migliorare ulteriormente la qualità del risultato.

  Se preferisci un livello di astrazione più alto, [`EstimatorV2`](/guides/estimator-noise-management) in Qiskit Runtime continua a fornire diverse tecniche integrate di mitigazione e soppressione degli errori, che puoi facilmente regolare utilizzando l'opzione [`resilience_level`](/guides/estimator-noise-management#resilience-level).

  Per saperne di più, consulta le seguenti guide:

    - [Guida rapida a Executor](/guides/get-started-with-executor)

    - [Noise learning helper](/guides/noise-learning)


  Entrambe queste nuove funzionalità sono attualmente in beta e richiedono `qiskit-ibm-runtime` versione 0.47.0 o superiore.
