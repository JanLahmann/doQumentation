# SDK de Qiskit v2.3 {#qiskit-sdk-v23}

## Enero de 2026 {#january-2026}
- Basándose en el impulso establecido a lo largo de la serie v2.x, que se ha centrado en posicionar a Qiskit como la plataforma líder para flujos de trabajo híbridos de cuántica-HPC, [Qiskit SDK v2.3](https://www.ibm.com/quantum/blog/qiskit-2-3-release-summary) ofrece una expansión significativa de la API en C junto con herramientas más rápidas y flexibles para construir y optimizar circuitos cuánticos.


  Las actualizaciones principales incluyen:

  - **Pasadas de transpilador personalizadas en C** - Escribe pasadas de transpilador personalizadas a través de la API en C de Qiskit usando el nuevo objeto `QkDag` y un objeto `QkTarget` ampliado, que permiten la inspección, modificación y extensión paso a paso del proceso de compilación, sin reconstruir todo el pipeline del compilador.


  - **Selección de disposición de hardware más rápida** - Las mejoras y las optimizaciones de rendimiento impulsadas por Rust en `VF2Layout` y `VF2PostLayout` mejoran la velocidad y la escalabilidad de la selección de disposición de circuito a hardware, reduciendo la sobrecarga de compilación y mejorando la fidelidad en el hardware cuántico.


  - **Nueva medición de Pauli multi-qubit** - La nueva instrucción `PauliProductMeasurement` permite la medición proyectiva conjunta en múltiples qubits en una sola operación, desbloqueando la compilación a computación basada en Pauli, una representación común en la computación cuántica tolerante a fallos.


  - **Mejoras en la transpilación temprana tolerante a fallos** - Las mejoras de rendimiento y funcionalidad para la transpilación a objetivos tempranos tolerantes a fallos, especialmente los objetivos Clifford+T, ayudan a los usuarios a construir pipelines de transpilación de forma más eficiente para futuros QPU.


  Estas capacidades brindan a los desarrolladores mayor flexibilidad para personalizar las optimizaciones de circuitos cuánticos e integrarse con los flujos de trabajo de HPC existentes. [Visita el blog](https://www.ibm.com/quantum/blog/qiskit-2-3-release-summary) para ver el resumen técnico completo.

## Abril de 2026 {#april-2026}

<span id="executor-primitive"></span>
- **Introducing the Executor primitive**: We're excited to announce the release of the new `Executor` primitive and a new version of the noise-learning helper class, `NoiseLearnerV3`, both of which were first previewed at QDC 2025.

  Junto con [Samplomatic](https://qiskit.github.io/samplomatic/index.html), conforman el [modelo de ejecución dirigida](/guides/directed-execution-model), que proporciona total transparencia y control para ajustar tu flujo de trabajo de mitigación de errores. El tutorial [Cancelación probabilística de errores con conos de luz sombreados](https://qiskit.github.io/qiskit-addon-slc/tutorials/01_getting_started.html), por ejemplo, muestra cómo se utiliza este modelo para combinar técnicas avanzadas, incluidos los conos de luz sombreados, la cancelación probabilística de errores (PEC), la extinción de errores de lectura trenzada (Twirled Readout Error eXtinction, TREX) y la [postselección basada en mediciones](/guides/post-selection), para mejorar aún más la calidad del resultado.

  Si prefieres un nivel de abstracción más alto, [`EstimatorV2`](/guides/estimator-noise-management) en Qiskit Runtime sigue ofreciendo varias técnicas integradas de mitigación y supresión de errores, que puedes ajustar fácilmente con la opción [`resilience_level`](/guides/estimator-noise-management#resilience-level).

  Para obtener más información, consulta las siguientes guías:

    - [Guía rápida de Executor](/guides/get-started-with-executor)

    - [Ayudante de aprendizaje de ruido](/guides/noise-learning)


  Ambas funciones nuevas se encuentran actualmente en beta y requieren `qiskit-ibm-runtime` versión 0.47.0 o superior.
