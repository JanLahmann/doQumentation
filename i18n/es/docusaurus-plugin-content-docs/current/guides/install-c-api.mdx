# Instalar la API C de Qiskit {#install-the-qiskit-c-api}

Esta guía describe cómo instalar y usar la API C de Qiskit. Después de completar la instalación, lee [Extender Python con la API C de Qiskit](/guides/c-extension-for-python).

El siguiente ejemplo construye un observable con C:

```c
// file: example.c
#include <stdio.h>
#include <stdint.h>
#include <qiskit.h>

int main(int argc, char *argv[]) {
    // build a 100-qubit empty observable
    uint32_t num_qubits = 100;
    QkObs *obs = qk_obs_zero(num_qubits);

    // add the term 2 * (X0 Y1 Z2) to the observable
    QkComplex64 coeff = {2, 0};
    QkBitTerm bit_terms[3] = {QkBitTerm_X, QkBitTerm_Y, QkBitTerm_Z}; 
    // bit terms: X Y Z
    uint32_t indices[3] = {0, 1, 2};  // indices: 0 1 2
    QkObsTerm term = {coeff, 3, bit_terms, indices, num_qubits};
    qk_obs_add_term(obs, &term);  // append the term

    // print some properties and the observable itself
    printf("num_qubits: %i\n", qk_obs_num_qubits(obs));
    printf("num_terms: %lu\n", qk_obs_num_terms(obs));
    printf("observable: %s\n", qk_obs_str(obs));

    // free the memory allocated for the observable
    qk_obs_free(obs);

    return 0;
}
```

## Sistemas tipo UNIX {#unix-like}

Esta sección proporciona instrucciones de compilación para sistemas tipo UNIX.

### Requisitos {#requirements}

La compilación requiere las siguientes herramientas:
* Un compilador de Rust: consulta, por ejemplo, la [guía para instalar Qiskit desde el código fuente](/guides/install-qiskit-source)
* Un compilador de C: por ejemplo, GCC en Linux y Clang en MacOS. La API C de Qiskit es compatible con compiladores que cumplan el estándar [C11](https://en.wikipedia.org/wiki/C11_(C_standard_revision)).
* [`cbindgen`](https://github.com/mozilla/cbindgen): una herramienta para crear el encabezado C, que puedes instalar con `cargo install cbindgen`
   Ejecutar la herramienta desde la línea de comandos debe estar habilitado, lo que puede requerir exportar tu variable `PATH` para incluir `/path/to/.cargo/bin`.
* Biblioteca de Python instalada (Python 3.9+): La biblioteca de Python es necesaria durante el enlazado dinámico. Ten en cuenta que Python no se usa en tiempo de ejecución y el intérprete nunca se inicializa; solo algunos símbolos de `libpython` necesitan estar definidos. Consulta [este issue](https://github.com/Qiskit/qiskit/issues/14240) para más detalles.
* (GNU) Make: esto es opcional pero se recomienda para usar procesos de instalación automatizados.

Este código verifica que todo esté instalado correctamente:

```bash
rustc --version
gcc --version
cbindgen --version
make --version  # optional, but recommended
```

### Compilación {#build}

Para compilar el encabezado C y la biblioteca, puedes ejecutar el siguiente comando Make[^1] en la raíz de Qiskit,
[^1]: Si no instalaste Make, revisa el `Makefile` en la raíz de Qiskit para ver los comandos necesarios — o simplemente instala Make; todavía estás a tiempo.)

```bash
make c
```
lo que proporcionará la biblioteca compartida compilada en `dist/c/lib` y el encabezado `qiskit.h` con
todas las declaraciones de funciones en `dist/c/include`. Ten en cuenta que el nombre exacto de la biblioteca depende
de la plataforma; por ejemplo, `libqiskit.so` en UNIX y `libqiskit.dylib` en MacOS.
(Ten en cuenta que este paso actualmente emite muchas advertencias, lo cual es esperado y no es motivo de alarma. Las versiones futuras eliminarán estas advertencias.)

Luego puedes compilar un programa en C usando el encabezado y la biblioteca C de Qiskit:

```bash
gcc example.c -o example.o -I /path/to/dist/c/include -L /path/to/dist/c/lib -lqiskit
```
Para asegurarte de que la biblioteca de Qiskit se encuentre durante el enlazado, establece la ruta de la biblioteca en tiempo de ejecución para
incluir `/path/to/dist/c/lib`. Si la biblioteca de Python no está disponible por defecto durante el enlazado dinámico,
también es necesario agregarla. Estos comandos dependen de la plataforma. En Linux:

```bash
export LD_LIBRARY_PATH=/path/to/dist/c/lib:$LD_LIBRARY_PATH
# On Linux, the Python library is typically included 
# in the dynamic library path by default.
export LD_LIBRARY_PATH=/path/to/python/lib:$LD_LIBRARY_PATH
```
En MacOS:

```bash
export DYLD_LIBRARY_PATH=/path/to/dist/c/lib:$DYLD_LIBRARY_PATH
export DYLD_LIBRARY_PATH=/path/to/python/lib:$DYLD_LIBRARY_PATH
```
Alternativamente, puedes establecer la ruta de la biblioteca en tiempo de ejecución durante la compilación agregando

```
-Wl,-rpath,/path/to/dist/c/lib
# same for Python
```
a los flags del compilador.
Además, la biblioteca de Python debe estar disponible durante el enlazado dinámico. En entornos Linux
esto suele ser el comportamiento por defecto.

Ahora puedes ejecutar el binario:

```bash
./example.o
```
que, si usas el fragmento de ejemplo mostrado anteriormente, debería imprimir

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```

## Windows {#windows}

Esta sección proporciona instrucciones de compilación para sistemas Windows.

Hay dos formas independientes de usar la API C en Windows:

* **Construir módulos de extensión de Python** que usen la API C de Qiskit. Sigue los pasos 1-5. Esta ruta usa las cabeceras C incluidas con el paquete Python `qiskit` y no requiere Rust ni cbindgen.

* **Construir la biblioteca C independiente** para enlazarla desde un programa C puro, como se hace en la sección [tipo UNIX](#unix). Completa el paso 1, luego pasa a [Construir la biblioteca independiente](#build-the-standalone-library), que enumera sus requisitos adicionales.


### Requisitos {#requirements-1}

- Se requieren permisos de administrador para algunos pasos.

- 5-8 GB de espacio libre en disco.

- Un compilador de C: Microsoft Visual C++ (MSVC), instalado en el paso 1.

- Una instalación de Python de 64 bits (3.10 o posterior), instalada en el paso 1.


### Antes de empezar {#before-you-begin}

Crea tu espacio de trabajo. Esto debe ser una ruta corta en una unidad local. No uses carpetas sincronizadas con OneDrive (como Documents o Desktop), unidades de red, ni rutas con espacios o caracteres no ASCII. Si tu nombre de usuario contiene caracteres no ingleses, no lo pongas dentro de tu carpeta de usuario.

Ejemplos de buenas rutas de espacio de trabajo: `C:\workspace`, `D:\workspace`, `C:\Users\john\workspace`

### Paso 3 - Carga el entorno de MSVC {#step-3-load-the-msvc-environment}

Ejecuta el siguiente código en cada nueva sesión de Python (por ejemplo, cada vez que reinicies un kernel de Jupyter). Localiza y carga automáticamente el entorno de desarrollo de MSVC para que no necesites el símbolo del sistema integrado x64.

El ejemplo de esta documentación crea módulos de extensión en C usando `setuptools` con MSVC. En general, defines `QISKIT_PYTHON_EXTENSION`, incluyes `qiskit.h` y llamas a `qk_import()` en tu función de inicialización. Solo se necesitan los encabezados de `qiskit.capi.get_include()` en el momento de la compilación; no se enlaza ninguna biblioteca. Consulta [Extender Qiskit en Python con C](/guides/c-extension-for-python) para más detalles.

<Accordion>
  <AccordionItem title="Cargar el entorno de MSVC">

```python
import os, sys, subprocess, glob, shutil

def load_msvc_env():
    if os.name != "nt":
        return "Not Windows — the system C compiler is used as-is."
    if shutil.which("cl"):
        return "cl.exe is already available in this kernel."

    pf86 = os.environ.get("ProgramFiles(x86)", r"C:\Program Files (x86)")
    pf = os.environ.get("ProgramFiles", r"C:\Program Files")
    vcvars = None

    vswhere = os.path.join(pf86, "Microsoft Visual Studio", "Installer", "vswhere.exe")
    if os.path.isfile(vswhere):
        # vswhere outputs UTF-8 regardless of system locale
        inst = subprocess.run(
            [vswhere, "-latest", "-products", "*",
             "-requires", "Microsoft.VisualStudio.Component.VC.Tools.x86.x64",
             "-property", "installationPath"],
            capture_output=True, text=True, encoding="utf-8").stdout.strip()
        if inst:
            cand = os.path.join(inst, "VC", "Auxiliary", "Build", "vcvars64.bat")
            if os.path.isfile(cand):
                vcvars = cand

    if not vcvars:
        pat = os.path.join("Microsoft Visual Studio", "*", "*",
                           "VC", "Auxiliary", "Build", "vcvars64.bat")
        hits = glob.glob(os.path.join(pf86, pat)) + glob.glob(os.path.join(pf, pat))
        if hits:
            vcvars = sorted(hits)[-1]

    if not vcvars:
        return ("Could not find vcvars64.bat. Install MSVC Build Tools (Step 1.3), "
                "or launch Jupyter from the x64 Native Tools Command Prompt.")

    # cmd.exe outputs in the OEM codepage (cp437/cp850/etc.), not the ANSI codepage
    out = subprocess.run(f'"{vcvars}" >nul 2>&1 && set',
                         capture_output=True, text=True, encoding="oem", shell=True).stdout
    for line in out.splitlines():
        if "=" in line:
            k, _, v = line.partition("=")
            os.environ[k] = v

    return ("Loaded MSVC from:\n  " + vcvars) if shutil.which("cl") \
        else "Ran vcvars64.bat but cl.exe is still not found — check your MSVC install."

print(load_msvc_env())
print("cl.exe on PATH:", shutil.which("cl") is not None)
```
</AccordionItem>

### Paso 4 - Prueba de humo: Compilar una extensión en C {#step-4-smoke-test-build-a-c-extension}

Ejecuta el siguiente código.  Escribe archivos fuente en `_smoke_pkg/`, compila una extensión en C contra la API C de Qiskit e importa el resultado. Si imprime "SMOKE TEST PASSED", tu cadena de herramientas está lista.

El paquete sigue el proceso de [Extender Qiskit en Python con C](/guides/c-extension-for-python) y usa funciones de la [referencia de la API C de Qiskit](https://docs.quantum.ibm.com/api/qiskit-c).

<Accordion>
  <AccordionItem title="Código de la prueba de humo">

```python
import sys, subprocess, pathlib, importlib

root = pathlib.Path("_smoke_pkg")
pkg = root / "src" / "qgss_smoke"
pkg.mkdir(parents=True, exist_ok=True)

(root / "pyworkspace.toml").write_text("""
[build-system]
requires = ["setuptools", "qiskit>=2.4.2"]
build-backend = "setuptools.build_meta"

[workspace]
name = "qgss_smoke"
version = "0.0.1"
dependencies = ["qiskit>=2.4.2"]

[tool.setuptools]
package-dir = {"" = "src"}
""".lstrip())

(root / "setup.py").write_text("""
import qiskit
from setuptools import setup, Extension

core_ext = Extension(
    name="qgss_smoke._core",
    sources=["src/qgss_smoke/_coremodule.c"],
    include_dirs=[qiskit.capi.get_include()],
)
setup(ext_modules=[core_ext])
""".lstrip())

(pkg / "__init__.py").write_text("from . import _core\nbuild_demo = _core.build_demo\n")

(pkg / "_coremodule.c").write_text("""
#define QISKIT_PYTHON_EXTENSION
#include <Python.h>
#include <qiskit.h>
#include <stdint.h>

static PyObject *build_demo(PyObject *self, PyObject *args) {
    QkCircuit *qc = qk_circuit_new(2, 0);
    uint32_t q0[1] = {0};
    qk_circuit_gate(qc, QkGate_H, q0, NULL);
    uint32_t q1[1] = {1};
    qk_circuit_gate(qc, QkGate_X, q1, NULL);
    return qk_circuit_to_python_full(qc);
}

static PyMethodDef core_methods[] = {
    {"build_demo", build_demo, METH_NOARGS, "Build a 2-qubit demo circuit in C."},
    {NULL, NULL, 0, NULL},
};
static struct PyModuleDef core_module = {
    .m_base = PyModuleDef_HEAD_INIT,
    .m_name = "_core",
    .m_methods = core_methods,
};
PyMODINIT_FUNC PyInit__core(void) {
    if (qk_import() < 0) {
        return NULL;
    }
    return PyModuleDef_Init(&core_module);
}
""".lstrip())

# On Windows, an imported .pyd is file-locked by the OS. Drop the module from
# sys.modules BEFORE pip install --force-reinstall, otherwise pip fails with
# WinError 32 ("file in use") trying to overwrite the locked .pyd.
if "qgss_smoke._core" in sys.modules:
    del sys.modules["qgss_smoke._core"]
if "qgss_smoke" in sys.modules:
    del sys.modules["qgss_smoke"]

r = subprocess.run(
    [sys.executable, "-m", "pip", "install", "--no-build-isolation",
     "--force-reinstall", "--quiet", str(root.resolve())],
    capture_output=True, text=True,
)
if r.returncode != 0:
    output = (r.stderr + r.stdout).strip()
    print("BUILD FAILED:\n")
    print(output)
    if "WinError 32" in output or "being used by another process" in output:
        print("\n--- TIP ---")
        print("The .pyd file is locked because it was previously imported in this kernel.")
        print("Restart the kernel (Ctrl+Shift+P → 'Jupyter: Restart Kernel'), then rerun")
        print("the Step 3 MSVC cell first, then this cell again.")
    elif "cl.exe" in output.lower() or "vcvars" in output.lower() or "cannot find" in output.lower():
        print("\n--- TIP ---")
        print("The compiler was not found. rerun the Step 3 cell to load the MSVC environment.")
else:
    importlib.invalidate_caches()
    import qgss_smoke
    from qiskit import QuantumCircuit

    qc = qgss_smoke.build_demo()
    ops = dict(qc.count_ops())
    ok = isinstance(qc, QuantumCircuit) and ops.get("h") == 1 and ops.get("x") == 1

    print("Returned object is a QuantumCircuit:", isinstance(qc, QuantumCircuit))
    print("Gates built in C:", ops)
    print("\nSMOKE TEST PASSED — your Windows toolchain can build Qiskit C extensions."
          if ok else "\nSomething is off — check the gates above.")
```

### Compilar la biblioteca independiente {#build-the-standalone-library}

Esta sección compila la biblioteca C independiente, que solo se necesita si quieres compilar y enlazar programas en C puro, como se describe en la sección [tipo UNIX](#unix). Además de los requisitos previos del Paso 1, esto requiere las siguientes herramientas:

* Un compilador de Rust: consulta, por ejemplo, la [guía sobre instalar Qiskit desde el código fuente](https://github.com/Qiskit/qiskit/blob/main/CONTRIBUTING.md#installing-qiskit-from-source)

* [`cbindgen`](https://github.com/mozilla/cbindgen): una herramienta para crear el encabezado C, que puedes instalar con `cargo install cbindgen`.
    Ejecutar la herramienta desde la línea de comandos debería estar habilitado, lo que podría requerir actualizar tu variable `PATH` para incluir la ruta de cargo.
* Una instalación de Python con acceso tanto a ``python3.lib`` como a ``python3.dll``
* Un clon del [repositorio de Qiskit](https://github.com/Qiskit/qiskit) (`git clone https://github.com/Qiskit/qiskit.git`)
<Accordion>
<AccordionItem title="Compilar la biblioteca independiente">
Primero, compila la biblioteca dinámica `qiskit_cext`, ejecutando lo siguiente en la terminal de VS Code (PowerShell) en la raíz de Qiskit:

```powershell
$env:PATH = "\path\to\pythonlib;" + $env:PATH
cargo rustc --release --crate-type cdylib -p qiskit-cext
```
Esto generará la biblioteca dinámica ``.dll`` y el archivo ``.dll.lib`` asociado en `target/release`.
A continuación, genera el encabezado con:

```powershell
cbindgen --crate qiskit-cext --output dist\c\include\qiskit.h
```
Esto escribe el encabezado compatible con MSVC en ``dist\c\include``.

Ahora puedes usar `cl` para compilar el programa en C. Para asegurarte de que el compilador encuentre la biblioteca de Qiskit,
incluye `target\release` en la variable `PATH`.

```powershell
$env:PATH = "\path\to\target\release;" + $env:PATH
cl example.c qiskit_cext.dll.lib -I\path\to\dist\c\include
```

Antes de ejecutarlo, incluye la ruta a tu ``python3.dll``.

```powershell
$env:PATH = "\path\to\python3-dll;" + $env:PATH
.\example.exe
```
debería entonces imprimir

```
num_qubits: 100
num_terms: 1
observable: SparseObservable { num_qubits: 100, 
coeffs: [Complex { re: 2.0, im: 0.0 }], 
bit_terms: [X, Y, Z], 
indices: [0, 1, 2], 
boundaries: [0, 3] }
```
</AccordionItem>
</Accordion>

### Solución de problemas {#troubleshooting}
<Accordion>
<AccordionItem title="`winget` is not recognized">
Actualiza el [App Installer](https://apps.microsoft.com/detail/9nblggh4nns1) desde la Microsoft Store, o usa los enlaces de descarga manual correspondientes
</AccordionItem>
<AccordionItem title="`cl` is not recognized">
Vuelve a ejecutar la celda de carga de MSVC (Paso 3), o usa el x64 Native Tools Command Prompt
</AccordionItem>
<AccordionItem title="`python` opens Microsoft Store">
Ve a Configuración → Aplicaciones → Configuración avanzada de aplicaciones → Alias de ejecución de aplicaciones y desactiva `python.exe`
</AccordionItem>
<AccordionItem title="`.ps1 cannot be loaded` / scripts disabled">
Ejecuta `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` y vuelve a intentarlo
</AccordionItem>
<AccordionItem title="`cannot open file 'qiskit.h'`">
Ejecuta `python -c "import qiskit.capi; print(qiskit.capi.get_include())"` y confirma que la ruta existe
</AccordionItem>
<AccordionItem title="`qiskit.capi` not found">
Ejecuta `pip install "qiskit[visualization]~=2.4.2"`
</AccordionItem>
<AccordionItem title="`qiskit-aer` build fails">
Ejecuta `pip install qiskit-aer --only-binary=:all:`. Si eso también falla, usa Python 3.12 u omite aer, que es opcional
</AccordionItem>
<AccordionItem title="Build runs but import fails with a version error">
La extensión C de Qiskit compilada y la versión de Qiskit instalada deben tener la misma versión.  Reinstala Qiskit con `pip install "qiskit~=2.4.2"`
</AccordionItem>
<AccordionItem title="I rebuilt the C but the circuit did not change">
Una extensión C no se puede volver a importar en caliente. Reinicia el kernel, vuelve a ejecutar los comandos de MSVC (Paso 3) y luego recompila
</AccordionItem>
<AccordionItem title="PowerShell script was blocked">
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
</AccordionItem>
<AccordionItem title="Path length errors">
Usa una ruta raíz corta en C:\ (por ejemplo, `C:\workspace`, o la ruta que configuraste en el paso de instalación), o habilita Long Paths: Configuración → Sistema → Para desarrolladores → Long Paths
</AccordionItem>
<AccordionItem title="Conda is active (the prompt shows `(base)`) or builds behave oddly after using Anaconda">
Ejecuta `conda deactivate` hasta que `CONDA_DEFAULT_ENV` y `CONDA_PREFIX` desaparezcan del entorno. Comprueba con `$env:CONDA_PREFIX`. Si persisten, abre una PowerShell nueva (no un Anaconda prompt) y vuelve a intentarlo desde el Paso 2.
</AccordionItem>
<AccordionItem title="The virtual environment was created from a conda-managed Python (check the `home =` line in `.venv\pyvenv.cfg`)">
El entorno virtual heredó el runtime C de conda y no se puede arreglar en el lugar. Elimínalo, descarga Python 3.12 desde el sitio web de [Python](https://www.python.org/downloads/) y vuelve a compilar. Ejecuta `Remove-Item -Recurse -Force .venv`, luego vuelve a ejecutar el fragmento de detección de Python del Paso 1 para configurar `$PYTHON_EXE`, y luego vuelve a crear el entorno virtual (Paso 2).
</AccordionItem>
<AccordionItem title="`DLL load failed` on import">
Es probable que conda esté filtrándose en el entorno virtual. Revisa ambos problemas inmediatamente anteriores a este. También verifica que Python sea de 64 bits: `python -c "import platform; print(platform.architecture())"`
</AccordionItem>
<AccordionItem title="Build fails with garbled paths or `C1083`">
Tu nombre de usuario o la ruta del espacio de trabajo contiene caracteres no ASCII. Mueve el espacio de trabajo a una ruta corta que use solo ASCII (por ejemplo, `C:\workspace`)
</AccordionItem>
<AccordionItem title="Build or import randomly fails, works on retry">
La carpeta del espacio de trabajo se sincroniza con OneDrive. Muévela a una ruta local como `C:\workspace`
</AccordionItem>
<AccordionItem title="Build interrupted midway (for example, there was a power loss)">
Elimina la carpeta `_smoke_pkg` en tu espacio de trabajo, vuelve a ejecutar la celda de carga de MSVC y luego vuelve a ejecutar la celda de la prueba de humo
</AccordionItem>
<AccordionItem title="`pip install` fails with SSL certificate error">
Tu red usa un proxy que intercepta HTTPS. Intenta ejecutar `pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org qiskit` o pide a tu administrador de red el certificado CA del proxy
</AccordionItem>
<AccordionItem title="Windows Defender quarantines the `.pyd` file">
Agrega las carpetas `.venv` y `_smoke_pkg` de tu espacio de trabajo a las exclusiones de Defender yendo a Seguridad de Windows → Protección contra virus y amenazas → Administrar configuración → Exclusiones
</AccordionItem>
<AccordionItem title="VS Build Tools cannot be installed (no admin rights)">
Se requiere acceso de administrador. Pide acceso a tu departamento de TI
</AccordionItem>
<AccordionItem title="`WinError 32` / file in use during rebuild">
El .pyd está bloqueado por el kernel en ejecución. Reinicia el kernel (Ctrl+Shift+P → Jupyter: Restart Kernel), vuelve a ejecutar el Paso 3 y luego recompila
</AccordionItem>
<AccordionItem title="Commands silently do nothing (no error, no output)">
Es posible que estés en cmd.exe en lugar de PowerShell. Comprueba tu prompt: PowerShell muestra `PS C:\>`, cmd muestra `C:\>`. Abre PowerShell desde el menú Inicio o Win+X
</AccordionItem>
<AccordionItem title="MSVC install appears stuck">
Los indicadores `--passive --wait` bloquean PowerShell mientras el instalador se ejecuta en segundo plano. Comprueba tu barra de tareas para ver una ventana de "Visual Studio Installer". Puede tardar de 10 a 30 minutos en instalarse
</AccordionItem>
</Accordion>
