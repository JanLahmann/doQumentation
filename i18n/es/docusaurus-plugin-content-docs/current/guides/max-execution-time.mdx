Para garantizar la equidad, existe un tiempo máximo de ejecución [aplicado por el servicio](#max-QPU) para cada trabajo. Si un trabajo supera este límite de tiempo, se cancela forzosamente y se lanza una excepción `RuntimeJobMaxTimeoutError`. También puedes [establecer un tiempo máximo de ejecución](#max-job) en tus trabajos para ayudar a controlar los costos.

 <Admonition type="note">
   La sesión o el batch se terminan inmediatamente cuando se alcanza el límite de costo. Los trabajos que se estén ejecutando actualmente en esa sesión o batch continuarán hasta completarse, pero los trabajos pendientes serán cancelados.
</Admonition>

<span id="max-job"></span>

## Establecer un tiempo máximo de ejecución {#set-a-maximum-execution-time}

El tiempo máximo de ejecución para un trabajo es el menor de estos valores:

- El valor establecido para `max_execution_time`

- El valor máximo de tiempo de espera del servicio (tres horas)


El valor de `max_execution_time` se basa en el *uso de la QPU* (solo el uso cuántico), no en el tiempo de reloj.

Establece el tiempo máximo de ejecución (en segundos) en las opciones del trabajo, como se muestra en el siguiente ejemplo. Consulta las guías de [opciones del Estimator](/guides/estimator-options), [opciones del Sampler](/guides/sampler-options) u [opciones del Executor](/guides/executor-options) para obtener información sobre cómo configurar opciones.

```python
from qiskit_ibm_runtime import QiskitRuntimeService
from qiskit_ibm_runtime import EstimatorV2 as Estimator

service = QiskitRuntimeService()
backend = service.least_busy(operational=True, simulator=False)

estimator = Estimator(mode=backend)

estimator.options.max_execution_time = 2500
```

También puedes averiguar cuánto uso han consumido los trabajos completados recuperando las métricas del trabajo de la siguiente manera:

```python
# Find QPU usage of a specific job
print(f"QPU usage of job {job.job_id()} was {job.metrics()['usage']['quantum_seconds']} seconds")
```

<span id="max-QPU"></span>

## Tiempo máximo de ejecución impuesto por el servicio {#service-enforced-maximum-execution-time}

El servicio impone un límite máximo de tiempo de ejecución de tres horas para garantizar un uso equitativo del dispositivo. Si también se especifica un `max_execution_time` para el trabajo, se utiliza el menor de los dos valores.

Por ejemplo, si especificas `max_execution_time=5000` (aproximadamente 83 minutos), entonces el trabajo se cancela después de aproximadamente 83 minutos, aunque el servicio podría permitirle ejecutarse durante tres horas.

<span id="batch-max-time"></span>

## Tiempo máximo de ejecución del batch {#batch-maximum-execution-time}

Cuando se inicia un batch, se le asigna un valor de tiempo de vida máximo (TTL máximo). Una vez alcanzado este TTL, el batch se termina, los trabajos que ya están en ejecución continúan ejecutándose y los trabajos en cola que permanecen en el batch pasan a un estado de error.

Los batches también tienen un valor de tiempo de vida interactivo (TTL interactivo) entre trabajos que no puede configurarse. Si no cierras explícitamente un batch, se desactiva una vez que expira el TTL interactivo y puede reactivarse en cualquier momento hasta que alcance su TTL máximo.

Para obtener instrucciones sobre cómo trabajar con estos valores, consulta [Ejecutar trabajos en un batch](/guides/run-jobs-batch).

<span id="session-max-time"></span>

## Tiempo máximo de ejecución de la sesión {#session-maximum-execution-time}

Cuando se inicia una sesión, se le asigna un valor de TTL máximo que determina cuánto tiempo puede ejecutarse. Una vez alcanzado este TTL, la sesión se termina, los trabajos que ya están en ejecución continúan ejecutándose y los trabajos en cola que permanecen en la sesión pasan a un estado de error.

También existe un valor de TTL interactivo que no puede configurarse. Si no se ponen en cola trabajos de la sesión dentro de esa ventana de tiempo, la sesión se desactiva temporalmente.

Para obtener instrucciones sobre cómo trabajar con estos valores, consulta [Ejecutar trabajos en una sesión](/guides/run-jobs-session).

## Otras limitaciones {#other-limitations}

Con el Plan Open, puedes usar hasta 10 minutos en una QPU por ventana continua de 28 días. Puedes ver el uso de una instancia en la página [Instancias](https://quantum.cloud.ibm.com/instances).
