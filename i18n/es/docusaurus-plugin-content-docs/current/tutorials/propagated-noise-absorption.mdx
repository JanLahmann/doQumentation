## Contexto {#background}

En este tutorial, demostramos cómo aprovechar herramientas avanzadas de mitigación de errores en Qiskit para mejorar la estimación de valores de expectativa en experimentos cuánticos ruidosos.

### ¿Qué es la absorción de ruido propagado (PNA)? {#what-is-propagated-noise-absorption-pna}

*La absorción de ruido propagado es una técnica para mitigar errores de puertas propagando el observable a través del canal de ruido inverso que afecta a las puertas de dos qubits, dando como resultado un observable que mitiga el ruido.*

Podemos usar la mitigación de errores cuánticos para extraer valores de expectativa útiles de hardware cuántico ruidoso sin requerir tolerancia a fallos completa. PNA se enfoca específicamente en absorber los efectos del ruido en el propio observable en lugar de modificar las operaciones del circuito.

Cada puerta ruidosa en un circuito cuántico se puede modelar como una puerta ideal seguida de un canal de ruido. PNA aprende o caracteriza estos canales de ruido y define sus inversos. En lugar de insertar las operaciones inversas en la ejecución del hardware (lo cual normalmente es inviable), PNA propaga los canales de ruido inverso hacia adelante a través del circuito y los aplica al observable. Este proceso transforma el observable $O$ en un nuevo operador $\tilde{O}$, de tal manera que medir $\tilde{O}$ en el circuito ruidoso produce el mismo valor de expectativa que medir $O$ en un circuito ideal sin ruido.

Esto se puede resumir así:
1. Modela cada puerta ruidosa $u_i$ como una operación ideal seguida de un canal de ruido $\Lambda_i$.
2. Aprende o estima cada $\Lambda_i$ usando herramientas de caracterización de ruido.
3. Define y propaga los mapas de ruido inverso $\Lambda_i^{-1}$ hacia adelante a través del circuito usando técnicas de transferencia de Pauli.
4. Absorbe estos inversos en el observable, dando como resultado un operador mitigado de ruido $\tilde{O}$.

Cuando el ruido se describe como un canal de Pauli (o, más generalmente, como un canal de Pauli-Lindblad disperso), esta propagación se puede realizar de manera eficiente utilizando propagación de Pauli. La propagación de Pauli proporciona un marco para aproximar cómo se transforman los canales de ruido inverso a medida que pasan a través de capas de operaciones de Clifford y no Clifford, controlando al mismo tiempo la complejidad computacional.

Al trasladar la mitigación al observable, PNA evita la gran sobrecarga de muestreo que de otro modo provendría de insertar operaciones de corrección físicas en el circuito. En cambio, se ejecuta el circuito ruidoso original, mientras que el observable se transforma en un nuevo operador $\tilde{O}$ cuyo valor de expectativa cancela los efectos del ruido.

### Mitigación modular de errores con Samplomatic y Executor {#modular-error-mitigation-with-samplomatic-and-executor}

El enfoque PNA se basa en una arquitectura modular de mitigación de errores en Qiskit. Esta arquitectura usa la librería [`samplomatic`](https://github.com/Qiskit/samplomatic) junto con las clases `QuantumProgram` y `Executor` (añadidas a Qiskit Runtime en `qiskit-ibm-runtime` v0.47.0) para hacer que técnicas como la absorción de ruido propagado y el Pauli twirling sean componibles y reutilizables en diferentes experimentos.

En lugar de incrustar la lógica de mitigación dentro de la propia definición del circuito, la mitigación se expresa de forma declarativa mediante anotaciones de `samplomatic` y se gestiona de forma programática a través de `Executor`, que controla cómo se generan, ejecutan y post-procesan los circuitos aleatorizados.

En este tutorial implementamos un [patrón de Qiskit](/guides/intro-to-patterns) para demostrar cómo PNA puede propagar canales de ruido de Pauli inversos y modificar el observable en consecuencia, para mejorar la estimación de valores de expectativa en QPUs ruidosos.

### Descripción general del flujo de trabajo {#workflow-overview}

- **Paso 1: Mapear al problema cuántico**

    - Construir un modelo de Ising pateado (kicked-Ising) trotterizado en espejo y un observable objetivo.

- **Paso 2: Caracterizar y propagar el ruido**

    - Usar `samplomatic` para identificar y anotar capas de dos qubits únicas y mediciones en el circuito.

    - Aprender el ruido que afecta a cada capa única usando `NoiseLearnerV3`.

    - Mapear cada anotación `InjectNoise` a su modelo de ruido aprendido correspondiente.

    - Usar `qiskit-addon-pna` para propagar los canales de ruido inverso hacia adelante a través del circuito y absorberlos en el observable objetivo.

- **Paso 3: Ejecutar experimentos cuánticos**

    - Definir un `QuantumProgram` para especificar el muestreo aleatorizado mediante `samplex` y ejecutar los experimentos en el backend usando el `Executor`.

- **Paso 4: Reconstruir y analizar resultados**

    - Comparar estrategias de mitigación (PNA, PNA+TREX, PNA+PS, PNA+PS+TREX) y visualizar la mejora respecto a los resultados sin mitigar.

```python
# Selects a connected chain of low-error qubits on the target backend.
# The mirrored kicked-Ising circuit is a 1D chain, so we only need a line
# of connected physical qubits; the helper walks the backend's coupling map
# and grows a chain along the lowest-error two-qubit edges, so it works for
# any backend rather than relying on a hardcoded layout.
def find_qubit_chain(backend, length):
    """Find a connected chain of ``length`` physical qubits on ``backend``.

    The chain is grown greedily along the lowest-error two-qubit edges, so it
    favors better-performing qubits. Because the mirrored kicked-Ising circuit
    is a 1D chain, a connected line is all we need.
    """
    target = backend.target

    # Identify the native two-qubit gate and build a per-edge error lookup.
    two_qubit_gate = next(
        name
        for name in target.operation_names
        if target[name]
        and all(q is not None and len(q) == 2 for q in target[name])
    )
    edge_error = {
        frozenset(qargs): (
            1.0 if props is None or props.error is None else props.error
        )
        for qargs, props in target[two_qubit_gate].items()
    }

    graph = backend.coupling_map.graph.to_undirected(multigraph=False)
    neighbors = {n: list(graph.neighbors(n)) for n in graph.node_indices()}

    def first_chain_from(start):
        path, visited = [start], {start}

        def grow():
            if len(path) == length:
                return True
            node = path[-1]
            order = sorted(
                neighbors[node],
                key=lambda m: edge_error.get(frozenset((node, m)), 1.0),
            )
            for nxt in order:
                if nxt not in visited:
                    visited.add(nxt)
                    path.append(nxt)
                    if grow():
                        return True
                    path.pop()
                    visited.remove(nxt)
            return False

        return path if grow() else None

    def chain_cost(path):
        return sum(
            edge_error.get(frozenset((path[i], path[i + 1])), 1.0)
            for i in range(len(path) - 1)
        )

    # Try low-degree qubits first (the natural ends of long chains) and keep
    # the lowest-error chain found.
    best_path, best_cost = None, float("inf")
    for start in sorted(neighbors, key=lambda n: len(neighbors[n])):
        chain = first_chain_from(start)
        if chain is not None and (cost := chain_cost(chain)) < best_cost:
            best_path, best_cost = chain, cost

    if best_path is None:
        raise ValueError(
            f"Could not find a connected chain of {length} qubits "
            f"on '{backend.name}'."
        )
    return best_path
```

## Ejemplo de simulador a pequeña escala {#small-scale-simulator-example}

PNA mitiga el ruido *físico* de las puertas de dos qubits de un procesador cuántico específico. El flujo de trabajo depende de dos servicios de hardware que no tienen un equivalente significativo en un simulador ideal:

- La primitiva `Executor` muestrea los circuitos aleatorizados y con twirling generados por `samplomatic` en un backend.

## Ejemplo de hardware a gran escala {#large-scale-hardware-example}

Ahora ejecutamos el flujo de trabajo completo de PNA en un modelo de Ising pateado de 30 sitios ejecutado en hardware de IBM Quantum&reg;, siguiendo los cuatro pasos de un patrón de Qiskit.

### Paso 1: Mapear a un problema cuántico {#step-1-map-to-a-quantum-problem}

**Generar el circuito de Trotter en espejo y el observable**

Para este experimento, estudiaremos la dinámica temporal de un modelo de Ising pateado de 30 sitios en una cadena de espines 1D. El Hamiltoniano considerado es:

$H = -J\sum\limits_{\langle i,j \rangle} Z_iZ_j + h\sum\limits_iX_i$,

donde $J>0$ describe el acoplamiento de espines vecinos más cercanos, $i<j$, y el campo transversal global, $h$, se establece en $\frac{\pi}{8}$. Cuanto más se aleja $h$ de un ángulo de Clifford (es decir, $\theta=n\frac{\pi}{2}, n \in \mathbb{Z}$), más difícil resulta propagar los generadores de anti-ruido a través del circuito.

Para la elección del observable, consideraremos la magnetización promedio de un solo sitio, $\frac{1}{N} \sum_{i=1}^{N} \langle z_i \rangle$, donde $N$ es el número de sitios.

```python
num_qubits = 30
num_trotter_steps = 10
rx_angle = np.pi / 8

# Avg single-site magnetization
id_pauli = Pauli("I" * num_qubits)
observable = (
    SparsePauliOp([id_pauli.dot(Pauli("Z"), [i]) for i in range(num_qubits)])
    / num_qubits
)

# Implement Trotterized kicked-Ising model
circuit = QuantumCircuit(num_qubits)
for _step in range(num_trotter_steps):
    circuit.rx(rx_angle, range(num_qubits))
    for first_qubit in (1, 2):
        for idx in range(first_qubit, num_qubits, 2):
            # equivalent to Rzz(-pi/2):
            circuit.sdg([idx - 1, idx])
            circuit.cz(idx - 1, idx)
# Append the inverse circuit to complete the mirroring
circuit.compose(circuit.inverse(), inplace=True)
circuit.measure_active()
circuit.draw("mpl", fold=-1)
```

### Paso 2: Optimizar el problema para la ejecución en hardware {#step-2-optimize-the-problem-for-hardware-execution}

El siguiente paso es preparar nuestro circuito de Trotter en espejo para su ejecución en hardware real de IBM Quantum. Ejecutar en un QPU requiere más que simplemente construir el circuito abstracto, ya que necesitamos optimizarlo para que:

1. **Respete el conjunto de puertas nativo y la conectividad del backend.**
   La transpilación mapea el circuito lógico a un circuito ISA compatible con el backend objetivo. Esto asegura que cada puerta e interacción de qubits sea físicamente realizable.


2. **Podamos caracterizar el ruido a nivel de las capas del circuito.**
   PNA depende de aprender y propagar canales de ruido inverso. Para hacerlo de manera eficiente, dividimos el circuito transpilado en capas únicas de dos qubits "encajonadas" (boxed). Estas cajas nos permiten asociar cada capa del circuito con su propio modelo de ruido aprendido.


3. **Podamos alimentar a PNA con modelos de ruido realistas.**
   Una vez que el circuito ha sido encajonado, usamos el servicio `NoiseLearnerV3` para aprender experimentalmente los canales de ruido de Pauli que afectan a cada capa única de dos qubits. Estos modelos aprendidos luego se vinculan de nuevo al circuito a través de las anotaciones de Samplomatic.


En conjunto, este paso conecta la brecha entre un circuito en espejo idealizado y un circuito listo para hardware con modelos de ruido aprendidos. Con esta configuración, PNA puede propagar canales de ruido inverso a través del circuito y ajustar el observable en consecuencia.

### Aplicar twirling a las capas de puertas de dos qubits y a las mediciones, y encontrar capas únicas {#twirl-the-two-qubit-gate-layers-and-measurements-and-find-unique-layers}

Usamos `samplomatic` para encajonar el circuito e identificar capas únicas de dos qubits. Una caja es una construcción que agrupa instrucciones para que intenciones o anotaciones específicas puedan aplicarse posteriormente de manera uniforme a todas las puertas dentro de la misma caja.

Aquí, llamamos al método `generate_boxing_pass_manager`, que va más allá de simplemente identificar capas de dos qubits. Realiza varias tareas clave:

- Agrupa todas las capas de dos qubits en el circuito,

- Aplica las anotaciones `Twirl` y `ChangeBasis` a esas capas,

- Agrupa las operaciones de medición en sus propias secciones encajonadas, y

- Aplica la anotación `InjectNoise` a cada capa de dos qubits.


Estas anotaciones definen cómo se manejan el ruido, los cambios de base y el twirling a lo largo del circuito. También establecen la estructura utilizada más adelante para aprender y mitigar el ruido.

Las opciones de configuración clave son:

- `enable_gates`/`enable_measures: True`: Encajona todas las capas de puertas de dos qubits y las mediciones terminales. Las puertas de un solo qubit se dejan vestidas (left-dressed) dentro de las cajas.

- `measure_annotations: all`: Incluye las anotaciones `Twirl` y `ChangeBasis` en la caja de medición.

- `twirling_strategy: active`: Aplica twirling a todos los qubits activos en cada caja que contiene puertas de entrelazamiento.

- `inject_noise_targets: gates`: Añade anotaciones `InjectNoise` a todas las cajas anotadas con `Twirl` que contienen puertas de entrelazamiento.

- `inject_noise_strategy: uniform_modification`: Escala todas las capas de ruido de manera equivalente en todo el circuito.


```python
# Box up circuit with Twirl and InjectNoise annotations
pm = generate_boxing_pass_manager(
    enable_gates=True,
    enable_measures=True,
    measure_annotations="all",
    twirling_strategy="active",
    inject_noise_targets="gates",
    inject_noise_strategy="uniform_modification",
)
boxed_circuit = pm.run(isa_circuit)
```

### Aprender el ruido usando `NoiseLearnerV3` {#learn-the-noise-using-noiselearnerv3}

Antes de poder aplicar PNA para la mitigación de errores, primero necesitamos caracterizar el ruido que actúa en cada capa única de dos qubits y en la capa de medición de nuestro circuito. Para ello, usamos el programa `NoiseLearnerV3` para aprender experimentalmente modelos de ruido para cada capa identificada anteriormente. El learner realiza experimentos de estilo benchmarking que estiman el canal de ruido que afecta a cada capa y devuelve un objeto de resultado que contiene el modelo aprendido.

Comenzamos identificando las capas únicas de nuestro circuito usando `find_unique_box_instructions` de `samplomatic`. Esto asegura que solo aprendamos el ruido una vez por cada tipo de capa distinto, minimizando el número de experimentos y el costo total de disparos (shots). La lista resultante de capas se pasa al learner de ruido.

Hay algunos parámetros clave que controlan cómo se aprende el ruido:

- `num_randomizations`: Número de circuitos aleatorios usados por configuración de aprendizaje.

- `shots_per_randomization`: Número de disparos (shots) tomados por cada circuito de aprendizaje aleatorio.

- `layer_pair_depths`: Las profundidades del circuito (medidas en número de pares) que se usarán en los experimentos de aprendizaje.

- `post_selection`: Habilita la post-selección basada en bordes usando puertas `rx` para aplicar pulsos posteriores a la medición.


```python
# Noise learning parameters
num_randomizations_nl = 64
shots_per_randomization_nl = 128

# Match the deepest noise-learning depth to the depth of the circuit being
# mitigated. ``layer_pair_depths`` are measured in layer pairs (a layer + its
# inverse), so the deepest value is half the circuits's two-qubit-layer depth.
# Learning to this depth improves the quality of the mitigation.

depth_2q = isa_circuit.depth(lambda instr: instr.operation.num_qubits == 2)
max_layer_pair_depth = depth_2q // 2

# Use a fixed schedule of learning depths, but drop any that exceed the circuit's
# depth and always cap the deepest value at ``max_layer_pair_depth`` so we never
# learn deeper than the circuit being mitigated
candidate_depths = [1, 2, 4, 8, 12, 16, 24, 32, 40, 48]
layer_pair_depths = sorted(
    {d for d in candidate_depths if d < max_layer_pair_depth}
    | {max_layer_pair_depth}
)

# Find the unique instructions (layers) from the boxed-up circuit
unique_2q_layers_and_meas = find_unique_box_instructions(
    boxed_circuit, normalize_annotations=None, undress_boxes=True
)

# Configure and run the noise learner on the unique layers.
# Options can be passed directly as a dictionary.
noise_learner_options = {
    "num_randomizations": num_randomizations_nl,
    "shots_per_randomization": shots_per_randomization_nl,
    "layer_pair_depths": layer_pair_depths,
    "post_selection": {
        "enable": True,
        "strategy": "edge",
        "x_pulse_type": "rx",
    },
    "environment": {"job_tags": ["TUT_PNA"]},
}

noise_learner = NoiseLearnerV3(backend, noise_learner_options)
noise_learner_job = noise_learner.run(unique_2q_layers_and_meas)
noise_learner_result = noise_learner_job.result()
```

### Asociar las cajas del circuito con el ruido aprendido {#associate-circuit-boxes-with-learned-noise}

Una vez que hemos obtenido modelos de ruido para cada capa única de dos qubits, necesitamos vincularlos a las anotaciones `InjectNoise` correspondientes dentro del circuito encajonado.

La directiva `InjectNoise` es una anotación de `samplomatic` que usa los dressers de un solo qubit para inyectar ruido en el circuito de manera controlada y configurable. Permite el modelado de ruido modular en diferentes capas.

Cada anotación `InjectNoise` incluye:
- `InjectNoise.ref` - un identificador único para la anotación. El objeto `samplex` lo usa para asignar correctamente el modelo de ruido correspondiente.
- `InjectNoise.modifier_ref` *(opcional)* - una referencia secundaria que permite escalar el modelo de ruido asignado mediante un factor multiplicativo.

En este paso, construimos un mapeo de cada `InjectNoise.ref` a su modelo de ruido aprendido correspondiente (`PauliLindbladMap`). Este mapeo asegura que cada capa de puertas de entrelazamiento en el circuito se empareje con el modelo de ruido apropiado, de modo que los efectos del ruido se apliquen con precisión durante el muestreo y los pasos posteriores de mitigación de ruido.

```python
# map inject noise refs to pauli lindblad maps
refs_to_noise_models = {}
for instruction, result in zip(
    unique_2q_layers_and_meas, noise_learner_result, strict=False
):
    if inject_noise_annot := get_annotation(
        instruction.operation, InjectNoise
    ):
        refs_to_noise_models[inject_noise_annot.ref] = (
            result.to_pauli_lindblad_map()
        )
```

### Propagar el observable a través del anti-ruido aprendido {#propagate-the-observable-through-the-learned-anti-noise}

Como se discutió anteriormente, esto se realiza en dos pasos. Primero, propagamos un generador de anti-ruido hasta el final del circuito. Después de eso, propagamos el observable a través de ese generador evolucionado. Este proceso se repite para cada generador de anti-ruido en el circuito. En esta implementación, cada generador en una capa dada se propaga hasta el final del circuito en paralelo. Además, se usa multiprocesamiento de Python para realizar tanto la propagación hacia adelante del anti-ruido como la retropropagación del observable en paralelo. Esto evita una acumulación de generadores evolucionados en la memoria y también maximiza los recursos de cómputo.

Al ejecutar PNA, siempre necesitas proporcionar un circuito ruidoso y un observable. Si tu circuito ruidoso es un circuito encajonado con anotaciones `InjectNoise`, necesitas proporcionar el mapeo que creamos en el paso anterior. También se puede pasar un circuito no encajonado que contenga instrucciones `PauliLindbladError` de `qiskit-aer`. En ese caso, no es necesario proporcionar `refs_to_noise_models`. Además de las entradas principales, también considera lo siguiente:

- `max_err_terms`: El número de términos que se mantienen en cada generador de anti-ruido a medida que se propaga hacia adelante. Permitir que este valor sea mayor generalmente aumenta la precisión, pero no se garantiza que este comportamiento sea monótono.

- `max_obs_terms`: El número de términos que se mantienen en el observable que mitiga el ruido, $\tilde{O}$, a medida que se retropropaga a través del anti-ruido evolucionado. Valores más grandes generalmente aumentan la precisión, pero no se garantiza que lo hagan de manera monótona.

- `num_processes`: El número de núcleos que se dedican al proceso. Recuerda, los generadores se propagan hacia adelante y se aplican al observable en paralelo.

- `search_step`: El paso de retropropagación usa un método voraz (greedy) para conjugar aproximadamente dos operadores en la base de Pauli. Este método se puede acelerar aumentando `search_step`. Consulta la [documentación de `pauli-prop`](https://qiskit.github.io/pauli-prop/) para más información.

- `num_to_measure`: Aunque esta variable no es una entrada de `generate_noise_mitigating_observable`, la usamos para controlar cuántos términos de $\tilde{O}$ queremos medir realmente. Aquí solo medimos los 30 términos principales, que son los términos originales de nuestro observable. Los términos ahora se han reescalado de tal manera que medirlos tiene el efecto de mitigar el ruido de puertas aprendido. Aunque solo medimos 30 términos de $\tilde{O}$, a menudo sigue siendo útil permitir que crezca mucho, ya que eso aumenta la precisión de los factores de escala de los términos principales.


```python
# PNA parameters
num_processes = 8
max_err_terms = 10_000
max_obs_terms = 10_000
num_to_measure = num_qubits

obs_tilde_isa = generate_noise_mitigating_observable(
    boxed_circuit,
    isa_observable,
    refs_to_noise_models,
    max_err_terms=max_err_terms,
    max_obs_terms=max_obs_terms,
    num_processes=num_processes,
    print_progress=True,
    search_step=8,
)
p_2_v = {p: v for v, p in enumerate(layout)}
obs_tilde_virtual = SparsePauliOp.from_sparse_list(
    [
        (pstr, [p_2_v[p] for p in p_qubits], coeff)
        for (pstr, p_qubits, coeff) in obs_tilde_isa.to_sparse_list()
    ],
    num_qubits=num_qubits,
)
obs_tilde_virtual = obs_tilde_virtual[
    np.argsort(np.abs(obs_tilde_virtual.coeffs))[::-1]
][:num_to_measure]
```

### Transformar las bases de medición a forma canónica {#transform-the-measurement-bases-to-canonical-form}

A continuación, encontramos un conjunto mínimo de bases a medir de manera que podamos cubrir completamente cada término de Pauli en el observable medido (*se pueden medir muchos observables simultáneamente si conmutan qubit a qubit*). Dado que solo estamos midiendo los términos de nuestro observable original, que es la suma de todos los Paulis `Z` individuales, se necesita una sola base: la base todo-`Z`.

Además de encontrar un conjunto de bases de medición de Pauli, necesitamos mapear estos términos de Pauli a la forma canónica esperada por el `Executor`. Para más información sobre el ordenamiento canónico de qubits, visita la [documentación de Samplomatic](https://qiskit.github.io/samplomatic/guides/samplex_io.html#qubit-ordering-convention).

```python
meas_box = boxed_circuit.data[-1]
canonical_qubits = [
    idx
    for idx, qubit in enumerate(boxed_circuit.qubits)
    if qubit in meas_box.qubits
]
c_2_p = {
    c: p for c, p in enumerate(canonical_qubits)
}  # canonical -> physical
p_2_v = {p: v for v, p in enumerate(layout)}  # physical -> virtual
c_2_v = {c: p_2_v[p] for c, p in c_2_p.items()}  # canonical -> virtual
meas_bases, bases_reverser = get_measurement_bases(obs_tilde_virtual)
meas_bases_canonical = [
    np.array([base[c_2_v[c]] for c in range(num_qubits)], dtype=np.uint8)
    for base in meas_bases
]
```

### Paso 3: Ejecutar experimentos cuánticos {#step-3-execute-quantum-experiments}

#### Especifica cómo muestrear en el `QuantumProgram` {#specify-how-to-sample-in-the-quantumprogram}

Ahora configuramos el `QuantumProgram`, que sirve como el contenedor central para todos los circuitos y configuraciones de muestreo que serán ejecutados por el `Executor`. Este objeto define cómo se generan, agrupan y ejecutan las instancias de circuitos aleatorizados para producir los resultados de medición utilizados en PNA.

Un `QuantumProgram` puede contener múltiples elementos, cada uno consistiendo en un circuito plantilla y un objeto `samplex` correspondiente que define cómo se aplican las aleatorizaciones. Esta abstracción permite que el `Executor` maneje todo el flujo de trabajo como un único programa modular &mdash; desde la generación de circuitos aleatorizados hasta la recolección y agregación de shots.

En este paso, creamos un `QuantumProgram` que ejecuta nuestro experimento PNA usando el circuito plantilla y el `samplex` que construimos anteriormente. La configuración incluye los siguientes elementos:

- `template_circuit`: El circuito que contiene todas las puertas necesarias para implementar todas las aleatorizaciones deseadas (a partir de aleatorizaciones de twirling, parámetros, etc.).

- `samplex`: Un objeto que define una distribución de probabilidad sobre todas las posibles aleatorizaciones de circuitos de las cuales muestrear.

- `samplex_arguments`: Vinculaciones necesarias para definir completamente el `samplex`

    - `basis_changes`: Aquí es donde especificamos un conjunto de bases a medir que cubrirá todos los términos de Pauli en el observable medido.

    - `noise_scales.ref`: Establecemos la escala de cada capa de ruido en `0.0` para evitar que se inyecte ruido adicional en nuestras muestras.

    - `pauli_lindblad_maps`: Requerido si se pasan `noise_scales`. Esto simplemente mapea las capas de ruido al modelo de ruido asociado.

- `shape`: Una tupla de forma para extender la forma implícita definida por `samplex_arguments`. Los ejes no triviales introducidos por esta extensión enumeran las aleatorizaciones.


```python
# Control the # of shots during execution
shots_per_randomization_exec = 64
num_randomizations_exec = 6144

# Zero out the noise to prevent noise from being injected during execution.
# We only added InjectNoise annotations so PNA could associate the noise
# to layers in the circuit
samplex_inputs = {f"noise_scales.{ref}": 0.0 for ref in refs_to_noise_models}
samplex_inputs |= {"pauli_lindblad_maps": refs_to_noise_models}

# Specify the bases to measure. The samplex exposes one basis-change input per
# ChangeBasis-annotated box; here a single all-Z basis covers every term. We
# look up the basis-change interface name rather than hardcoding an index, since
# the name depends on the circuit's box structure.
bases_broadcastable = np.expand_dims(np.array(meas_bases_canonical), axis=1)
samplex_inputs |= {
    spec.name: bases_broadcastable
    for spec in samplex.inputs().get_specs(r"^basis_changes\.")
}

# Convert samplex_inputs into a dict to pass to QuantumProgram
samplex_arguments = (
    samplex.inputs().make_broadcastable().bind(**samplex_inputs)
)

# Instantiate the QuantumProgram with the specified parameters
program = QuantumProgram(shots=shots_per_randomization_exec)
program.append_samplex_item(
    circuit=template_circuit,
    samplex=samplex,
    samplex_arguments=samplex_arguments,
    shape=(num_randomizations_exec,),
)
```

#### Muestrea el circuito usando el `Executor` {#sample-the-circuit-using-the-executor}

Ahora que hemos definido nuestro `QuantumProgram`, ejecutar el experimento es sencillo. Simplemente instanciamos el objeto `Executor`, le proporcionamos el backend y ejecutamos el programa.

```python
# Execute (sample) the circuit
executor = Executor(backend)
job_exec = executor.run(program)
exec_results = job_exec.result()
```

### Paso 4: Reconstruir y analizar resultados {#step-4-reconstruct-and-analyze-results}

Para calcular un valor esperado con mitigación de errores, hacemos lo siguiente:

- Calcular los factores de escala TREX basados en el ruido aprendido que afecta a las mediciones,

- Generar una máscara para conservar solo las muestras postseleccionadas, y

- Usar la función `executor_expectation_values` de `qiskit-addon-utils` para combinar todos los datos en un valor esperado con mitigación de errores.


```python
# Computing the TREX factors
measurement_noise_map = noise_learner_result[2].to_pauli_lindblad_map()
trex_rescale_factors = trex_factors(measurement_noise_map, bases_reverser)

# Post-select the results
post_selector = PostSelector.from_circuit(
    circuit=template_circuit, coupling_map=backend.coupling_map
)

# Compute the ps mask for filtering results
mask = post_selector.compute_mask(exec_results[0], strategy="edge")

# Compute expvals using post selected results
results = executor_expectation_values(
    exec_results[0]["meas"],
    bases_reverser,
    meas_basis_axis=0,
    avg_axis=1,
    measurement_flips=exec_results[0]["measurement_flips.meas"],
    pauli_signs=exec_results[0].get("pauli_signs", None),
    postselect_mask=mask,
    rescale_factors=trex_rescale_factors,
)
```
