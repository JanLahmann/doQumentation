## Monitoruj zadanie {#monitor-a-job}

Użyj tych metod, aby sprawdzić status wysłanych zadań, pobrać wyniki i wyświetlić szczegóły dotyczące zadania oraz jego wykonania.

<Tabs>
    <TabItem value="Qiskit" label="Monitor a job with Qiskit">
        Instancja zadania udostępnia kilka metod monitorowania:

        | Method | Description |
        | --- | --- |
        | `job.status()` | Check the current job status |
        | `job.job_id()` | Get the unique job identifier |
        | `job.result()` | Retrieve job results (blocking call until complete) |
        | `job.wait_for_final_state()` | Block until the job reaches a terminal state |

        
    </TabItem>
    <TabItem value="IQP" label="Monitor a job on IBM Quantum Platform">
        Przejdź do [strony Obciążenia](https://quantum.cloud.ibm.com/workloads) i sprawdź kolumnę Status. Status twojego zadania będzie jednym z poniższych:
        - **Pending**: zadanie oczekuje na uruchomienie na QPU
        - **In progress**: zadanie jest właśnie wykonywane
        - **Completed**: zadanie zakończyło się pomyślnie
        - **Failed**: podczas zadania wystąpił błąd
        - **Canceled**: użytkownik anulował zadanie

        Kliknij nazwę zadania lub wiersz, aby otworzyć widok szczegółowy, w którym możesz zobaczyć informacje takie jak wyniki i wszelkie komunikaty o błędach.

    </TabItem>
</Tabs>

### Dlaczego zadanie pozostaje w statusie „In progress” {#why-a-job-stays-in-progress}

Możesz zauważyć, że zadanie (korzystające z trybu zadania lub trybu wsadowego), które według oczekiwań powinno trwać zaledwie kilka sekund, pozostaje w statusie **In progress** (nazywanym `RUNNING` w Qiskit) znacznie dłużej. Jest to normalne i nie oznacza, że zadanie zużywa cały ten czas jako wykorzystanie. Dzieje się tak z powodu sposobu, w jaki zadania są planowane na QPU:

- Każde zadanie wymaga klasycznego przetwarzania wstępnego, zanim będzie mogło zostać uruchomione na QPU. Zadanie przechodzi do statusu **In progress** (`RUNNING`) w momencie rozpoczęcia tego klasycznego przetwarzania — nie wtedy, gdy zaczyna się wykonywać na QPU.

- Większość tego klasycznego przetwarzania odbywa się równolegle, więc wiele zadań może być jednocześnie w statusie **In progress**.

- Jednak tylko jedno zadanie na raz może być wykonywane na QPU. Gdy kilka zadań zakończy klasyczne przetwarzanie i będzie gotowych do wykonania, muszą czekać na swoją kolej do QPU. Nazywa się to *rywalizacją o QPU* (QPU contention). Gdy rywalizacja jest wysoka, zadanie może pozostawać w statusie **In progress** zauważalnie dłużej niż kilka sekund czasu QPU, których faktycznie potrzebuje.

- Rywalizacja może również wystąpić, gdy na QPU trwa zadanie konserwacji systemu, takie jak kalibracja. Twoje zadanie pozostaje w statusie **In progress**, dopóki zadanie konserwacji się nie zakończy i QPU nie stanie się dostępne.


Z tego powodu upływający czas rzeczywisty, który zadanie spędza w statusie **In progress**, nie jest tym samym co jego wykorzystanie. Zarówno [szacowane wykorzystanie](/guides/estimate-job-run-time), jak i [maksymalny czas wykonania](/guides/max-execution-time) opierają się wyłącznie na czasie, w którym QPU jest zablokowane do wykonania twojego zadania, a więc wykluczają opisane powyżej wielowątkowe przetwarzanie klasyczne. Długi czas w statusie **In progress** nie zwiększa zgłaszanego wykorzystania ani kosztu.

#### Tryb Session jest inny {#session-mode-is-different}

Poprzednio opisane zachowanie dotyczy [trybu zadania](/guides/execution-modes#job-mode) i [trybu wsadowego](/guides/execution-modes#batch-mode). W [trybie Session](/guides/execution-modes#session-mode), w oknie aktywności sesji, użytkownik ma wyłączny dostęp do backendu i żadne inne zadania nie mogą być wykonywane, w tym zadania kalibracyjne. Dlatego jakakolwiek rywalizacja o QPU zachodzi tylko wśród twoich własnych zadań w ramach sesji. Ponadto, ponieważ pojemność QPU jest zarezerwowana na czas trwania sesji, wykorzystanie sesji jest mierzone jako czas, który upłynął, gdy sesja pozostaje aktywna, niezależnie od tego, czy zadania są aktywnie wykonywane. Zobacz [Wykorzystanie obciążenia](/guides/estimate-job-run-time#usage), aby dowiedzieć się więcej.

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve a job by ID
job = service.job("<job_id>")

# Get job ID (useful for saving for later retrieval)
print(f"Job ID: {job.job_id()}")

# Check current status
print(f"Status: {job.status()}")

# Wait for job to complete (blocking call)
job.wait_for_final_state()
print("Job completed")

# Get results
results = job.result()
print(results)
```

## Sprawdź metryki zadań {#view-job-metrics}

Uzyskaj przegląd swoich zgłoszonych zadań, w tym metryki obciążeń wsadowych i sesyjnych.

<Tabs>
    <TabItem value="Qiskit" label="Get job metrics with Qiskit">
        Użyj metody [`service.jobs()`](https://docs.quantum.ibm.com/api/qiskit-ibm-runtime/qiskit-runtime-service#jobs) z filtrami, aby pobrać informacje o wysłanych zadaniach, takie jak liczba wysłanych zadań, ich statusy i czas utworzenia. Poniższy przykład pobiera wszystkie zadania wysłane w ciągu ostatnich siedmiu dni i oblicza całkowite wykorzystanie tych zadań.

        
    </TabItem>
    <TabItem value="IQP" label="View job metrics on IBM Quantum Platform">
        Przejdź do [strony Analityka](https://quantum.cloud.ibm.com/analytics), aby zobaczyć i pobrać dane, takie jak:
        - Całkowite wykorzystanie
        - Wykorzystanie filtrowane według instancji, komputera kwantowego i użytkownika
        - Liczba obciążeń typu zadanie, wsad i sesja

        **Uwaga**: możesz uzyskać dostęp do strony Analityka tylko dla kont, które posiadasz lub którymi zarządzasz.
    </TabItem>
</Tabs>

```python
from datetime import datetime, timedelta
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve all jobs in the last 7 days
seven_days_ago = datetime.now() - timedelta(days=7)
jobs = service.jobs(limit=None, created_after=seven_days_ago)

# To retrieve all jobs in a Session or Batch, use the session_id filter
# jobs = service.jobs(session_id="<session id>")

total_usage = 0
for job in jobs:
    total_usage += job.usage()

print(f"{len(jobs)} jobs were submitted in the last 7 days.")
print(f"Total usage was {total_usage} seconds")
```

## Pobierz właściwości backendu {#retrieve-backend-properties}

<Tabs>
    <TabItem value="Qiskit" label="Retrieve backend properties with Qiskit">
        Możesz użyć `job.properties()`, aby pobrać właściwości backendu, w tym współczynniki błędów, w momencie wykonania zadania.

        Ten przykład pokazuje, jak pobrać właściwości backendu aktualne w momencie wykonania zadania, w tym czasy $T_1$/$T_2$ i współczynniki błędów dla konkretnego kubitu (0).

        

        <Admonition type="note" title="Wycofane pakiety dostawców">
            `service.jobs()` zwraca również zadania uruchomione za pomocą wycofanego pakietu `qiskit-ibm-provider`. Zadania wysłane za pomocą starszego (również wycofanego) pakietu `qiskit-ibmq-provider` nie są już dostępne.
        </Admonition>
    </TabItem>
    <TabItem value="IQP" label="Retrieve backend properties on IBM Quantum Platform">

        1. Przejdź do [strony Obciążenia](https://quantum.cloud.ibm.com/workloads)
        2. Kliknij obciążenie, aby otworzyć jego stronę szczegółów

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Uncomment the next line to retrieve a specific job by ID
# job = service.job("<job_id>")

# Optionally retrieve multiple jobs with filters
# Use `limit` to retrieve a specific number of jobs. The default `limit` is 10.
my_backend = "<your-backend>"
recent_jobs = service.jobs(backend_name=my_backend, limit=10)

print(f"Retrieved {len(recent_jobs)} recent jobs from {my_backend}\n")

# Get results from all jobs
for job in recent_jobs:
    print(f"Job ID: {job.job_id()}")
    print(f"Status: {job.status()}")

    # Retrieve results if the job is complete
    if str(job.status()) == "DONE":
        try:
            results = job.result()
            print(f"Results: {results}")
        except Exception as e:
            print(f"Error retrieving results: {e}")
    else:
        print("Results: Not available (job still running or failed)")
    print()
```

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve a specific job by ID
job = service.job("<job_id>")

print(f"Job ID: {job.job_id()}")
print(f"Backend: {job.backend}\n")

# Fetch backend properties at the time of job execution
properties = job.properties()

if properties:
    print("Backend Properties at Job Execution Time:")
    print("=" * 60)

    # Get T1 (relaxation time) for qubit 0
    t1 = properties.t1(0)
    print(f"Qubit 0 T1 (relaxation time): {t1}")

    # Get T2 (dephasing time) for qubit 0
    t2 = properties.t2(0)
    print(f"Qubit 0 T2 (dephasing time): {t2}")

    # Get readout error for qubit 0
    readout_error = properties.readout_error(0)
    print(f"Qubit 0 readout error: {readout_error}")

    # Get all properties for a specific qubit
    print("All properties for qubit 0:")
    qubit_props = properties.qubit_property(0)
    for prop_name, prop_value in qubit_props.items():
        print(f"  {prop_name}: {prop_value}")
else:
    print("No properties available for this job")
```

## Anuluj zadanie {#cancel-a-job}

Anuluj zadanie, które jest w kolejce lub jest wykonywane. Po anulowaniu zadania nie można go wznowić.

<Tabs>
    <TabItem value="Qiskit" label="Cancel with Qiskit">
        Użyj metody `job.cancel()`, aby anulować zadanie programowo.

        
    </TabItem>
    <TabItem value="IQP" label="Cancel on IBM Quantum Platform">
        1. **Z tabeli obciążeń**: kliknij menu przepełnienia na końcu wiersza obciążenia, które chcesz anulować, i wybierz **Anuluj**.
        2. **Ze strony szczegółów zadania**: kliknij obciążenie, aby otworzyć jego stronę szczegółów, użyj listy rozwijanej **Akcje** u góry i wybierz **Anuluj**.
    </TabItem>
</Tabs>

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()

# Retrieve the job
job = service.job("<job_id>")

# Cancel the job
job.cancel()

print(f"Job {job.job_id()} has been canceled")
```
