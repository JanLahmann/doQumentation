### Czym jest propagowana absorpcja szumu (PNA)? {#what-is-propagated-noise-absorption-pna}

*Propagowana absorpcja szumu to technika korekcji błędów bramek poprzez propagowanie obserwabla przez odwrotny kanał szumu wpływający na bramki dwukubitowe, co skutkuje obserwablem korygującym szum.*

Możemy użyć kwantowej korekcji błędów, aby wydobyć użyteczne wartości oczekiwane z zaszumionego sprzętu kwantowego bez konieczności pełnej odporności na błędy. PNA koncentruje się szczególnie na absorbowaniu efektów szumu w samym obserwablu, zamiast modyfikować operacje obwodu.

Każdą zaszumioną bramkę w obwodzie kwantowym można modelować jako idealną bramkę, po której następuje kanał szumu. PNA uczy się lub charakteryzuje te kanały szumu i definiuje ich odwrotności. Zamiast wstawiać operacje odwrotne do wykonania na sprzęcie (co jest zazwyczaj niewykonalne), PNA propaguje odwrotne kanały szumu w przód przez obwód i stosuje je do obserwabla. Ten proces przekształca obserwabl $O$ w nowy operator $\tilde{O}$, taki że zmierzenie $\tilde{O}$ na zaszumionym obwodzie daje taką samą wartość oczekiwaną jak zmierzenie $O$ na idealnym, wolnym od szumu obwodzie.

Można to podsumować następująco:
1. Modeluj każdą zaszumioną bramkę $u_i$ jako idealną operację, po której następuje kanał szumu $\Lambda_i$.
2. Wyucz się lub oszacuj każdy $\Lambda_i$ za pomocą narzędzi charakteryzacji szumu.
3. Zdefiniuj i propaguj odwrotne mapy szumu $\Lambda_i^{-1}$ w przód przez obwód, wykorzystując techniki transferu Pauliego.
4. Zaabsorbuj te odwrotności w obserwablu, uzyskując operator skorygowany pod względem szumu $\tilde{O}$.

Gdy szum jest opisany jako kanał Pauliego (lub bardziej ogólnie jako rzadki kanał Pauliego-Lindblada), tę propagację można przeprowadzić efektywnie za pomocą propagacji Pauliego. Propagacja Pauliego zapewnia ramy do przybliżania sposobu, w jaki odwrotne kanały szumu przekształcają się podczas przechodzenia przez warstwy operacji Cliffordowskich i nie-Cliffordowskich, przy jednoczesnym kontrolowaniu złożoności obliczeniowej.

Przenosząc korekcję do obserwabla, PNA unika dużego narzutu próbkowania, który w przeciwnym razie wynikałby z wstawiania fizycznych operacji korygujących do obwodu. Zamiast tego wykonywany jest oryginalny zaszumiony obwód, podczas gdy obserwabl jest przekształcany w nowy operator $\tilde{O}$, którego wartość oczekiwana znosi efekty szumu.

```python
# Selects a connected chain of low-error qubits on the target backend.
# The mirrored kicked-Ising circuit is a 1D chain, so we only need a line
# of connected physical qubits; the helper walks the backend's coupling map
# and grows a chain along the lowest-error two-qubit edges, so it works for
# any backend rather than relying on a hardcoded layout.
def find_qubit_chain(backend, length):
    """Find a connected chain of ``length`` physical qubits on ``backend``.

    The chain is grown greedily along the lowest-error two-qubit edges, so it
    favors better-performing qubits. Because the mirrored kicked-Ising circuit
    is a 1D chain, a connected line is all we need.
    """
    target = backend.target

    # Identify the native two-qubit gate and build a per-edge error lookup.
    two_qubit_gate = next(
        name
        for name in target.operation_names
        if target[name]
        and all(q is not None and len(q) == 2 for q in target[name])
    )
    edge_error = {
        frozenset(qargs): (
            1.0 if props is None or props.error is None else props.error
        )
        for qargs, props in target[two_qubit_gate].items()
    }

    graph = backend.coupling_map.graph.to_undirected(multigraph=False)
    neighbors = {n: list(graph.neighbors(n)) for n in graph.node_indices()}

    def first_chain_from(start):
        path, visited = [start], {start}

        def grow():
            if len(path) == length:
                return True
            node = path[-1]
            order = sorted(
                neighbors[node],
                key=lambda m: edge_error.get(frozenset((node, m)), 1.0),
            )
            for nxt in order:
                if nxt not in visited:
                    visited.add(nxt)
                    path.append(nxt)
                    if grow():
                        return True
                    path.pop()
                    visited.remove(nxt)
            return False

        return path if grow() else None

    def chain_cost(path):
        return sum(
            edge_error.get(frozenset((path[i], path[i + 1])), 1.0)
            for i in range(len(path) - 1)
        )

    # Try low-degree qubits first (the natural ends of long chains) and keep
    # the lowest-error chain found.
    best_path, best_cost = None, float("inf")
    for start in sorted(neighbors, key=lambda n: len(neighbors[n])):
        chain = first_chain_from(start)
        if chain is not None and (cost := chain_cost(chain)) < best_cost:
            best_path, best_cost = chain, cost

    if best_path is None:
        raise ValueError(
            f"Could not find a connected chain of {length} qubits "
            f"on '{backend.name}'."
        )
    return best_path
```

## Przykład na sprzęcie na dużą skalę {#large-scale-hardware-example}

Uruchamiamy teraz pełny przepływ pracy PNA na 30-węzłowym modelu kicked Ising wykonywanym na sprzęcie IBM Quantum&reg;, zgodnie z czterema krokami wzorca Qiskit.

### Krok 1: Mapowanie na problem kwantowy {#step-1-map-to-a-quantum-problem}

**Wygeneruj lustrzany obwód Trottera i obserwabl**

Dla tego eksperymentu zbadamy dynamikę czasową 30-węzłowego modelu kicked Ising na jednowymiarowym łańcuchu spinowym. Rozważany hamiltonian to:

$H = -J\sum\limits_{\langle i,j \rangle} Z_iZ_j + h\sum\limits_iX_i$,

gdzie $J>0$ opisuje sprzężenie najbliższych sąsiadujących spinów, $i<j$, a globalne pole poprzeczne, $h$, jest ustawione na $\frac{\pi}{8}$. Im dalej $h$ jest od kąta Cliffordowskiego (to jest, $\theta=n\frac{\pi}{2}, n \in \mathbb{Z}$), tym trudniej jest propagować generatory antyszumu przez obwód.

W wyborze obserwabla rozważymy średnią magnetyzację jednowęzłową, $\frac{1}{N} \sum_{i=1}^{N} \langle z_i \rangle$, gdzie $N$ to liczba węzłów.

```python
num_qubits = 30
num_trotter_steps = 10
rx_angle = np.pi / 8

# Avg single-site magnetization
id_pauli = Pauli("I" * num_qubits)
observable = (
    SparsePauliOp([id_pauli.dot(Pauli("Z"), [i]) for i in range(num_qubits)])
    / num_qubits
)

# Implement Trotterized kicked-Ising model
circuit = QuantumCircuit(num_qubits)
for _step in range(num_trotter_steps):
    circuit.rx(rx_angle, range(num_qubits))
    for first_qubit in (1, 2):
        for idx in range(first_qubit, num_qubits, 2):
            # equivalent to Rzz(-pi/2):
            circuit.sdg([idx - 1, idx])
            circuit.cz(idx - 1, idx)
# Append the inverse circuit to complete the mirroring
circuit.compose(circuit.inverse(), inplace=True)
circuit.measure_active()
circuit.draw("mpl", fold=-1)
```

### Krok 2: Optymalizacja problemu pod kątem wykonania na sprzęcie {#step-2-optimize-the-problem-for-hardware-execution}

Kolejnym krokiem jest przygotowanie naszego lustrzanego obwodu Trottera do wykonania na rzeczywistym sprzęcie IBM Quantum. Uruchomienie na QPU wymaga czegoś więcej niż tylko skonstruowania abstrakcyjnego obwodu, ponieważ musimy go zoptymalizować, tak aby:

1. **Respektował natywny zestaw bramek i połączeń backendu.**
   Transpilacja mapuje obwód logiczny na obwód ISA obsługiwany przez docelowy backend. Zapewnia to, że każda bramka i interakcja kubitów są fizycznie realizowalne.


2. **Mogli scharakteryzować szum na poziomie warstw obwodu.**
   PNA opiera się na uczeniu się i propagowaniu odwrotnych kanałów szumu. Aby zrobić to efektywnie, dzielimy transpilowany obwód na unikalne dwukubitowe warstwy "w ramkach". Te ramki pozwalają nam powiązać każdą warstwę obwodu z jej własnym wyuczonym modelem szumu.


3. **Mogli wprowadzić realistyczne modele szumu do PNA.**
   Gdy obwód zostanie już ujęty w ramki, używamy usługi `NoiseLearnerV3`, aby eksperymentalnie wyuczyć kanały szumu Pauliego wpływające na każdą unikalną warstwę dwukubitową. Te wyuczone modele są następnie powiązane z powrotem z obwodem poprzez adnotacje Samplomatic.


Podsumowując, ten krok wypełnia lukę między wyidealizowanym lustrzanym obwodem a obwodem gotowym do pracy na sprzęcie z wyuczonymi modelami szumu. Dzięki tej konfiguracji PNA może propagować odwrotne kanały szumu przez obwód i odpowiednio dostosować obserwabl.

### Zawiruj warstwy bramek dwukubitowych i pomiary oraz znajdź unikalne warstwy {#twirl-the-two-qubit-gate-layers-and-measurements-and-find-unique-layers}

Używamy `samplomatic` do zapakowania obwodu w boxy i identyfikacji unikalnych warstw dwukubitowych. Box to konstrukcja grupująca instrukcje, dzięki czemu określone intencje lub adnotacje można później jednolicie zastosować do wszystkich bramek w tym samym boxie.

Tutaj wywołujemy metodę `generate_boxing_pass_manager`, która robi więcej niż tylko identyfikację warstw dwukubitowych. Wykonuje kilka kluczowych zadań:

- Grupuje wszystkie warstwy dwukubitowe w obwodzie,

- Stosuje adnotacje `Twirl` i `ChangeBasis` do tych warstw,

- Grupuje operacje pomiarowe we własne zapakowane sekcje, oraz

- Stosuje adnotację `InjectNoise` do każdej warstwy dwukubitowej.


Te adnotacje określają, jak w całym obwodzie obsługiwane są szum, zmiany bazy i twirling. Ustalają również strukturę używaną później do uczenia się i łagodzenia szumu.

Kluczowe opcje konfiguracji to:

- `enable_gates`/`enable_measures: True`: Zapakuj wszystkie warstwy bramek dwukubitowych i pomiary końcowe. Bramki jednokubitowe są ubierane wewnątrz boxów.

- `measure_annotations: all`: Uwzględnij adnotacje `Twirl` i `ChangeBasis` w boxie pomiarowym.

- `twirling_strategy: active`: Zawiruj wszystkie aktywne kubity w każdym boxie zawierającym bramki splątujące.

- `inject_noise_targets: gates`: Dodaj adnotacje `InjectNoise` do wszystkich boxów oznaczonych `Twirl`, zawierających bramki splątujące.

### Naucz się szumu za pomocą `NoiseLearnerV3` {#learn-the-noise-using-noiselearnerv3}

Zanim będziemy mogli zastosować PNA do łagodzenia błędów, musimy najpierw scharakteryzować szum wpływający na każdą unikalną warstwę dwukubitową oraz warstwę pomiarową w naszym obwodzie. W tym celu używamy programu `NoiseLearnerV3` do eksperymentalnego uczenia się modeli szumu dla każdej wcześniej zidentyfikowanej warstwy. Program uczący wykonuje eksperymenty w stylu benchmarkingu, które szacują kanał szumu wpływający na każdą warstwę i zwracają obiekt wyniku zawierający wyuczony model.

Zaczynamy od identyfikacji unikalnych warstw w naszym obwodzie za pomocą `find_unique_box_instructions` z `samplomatic`. Zapewnia to, że uczymy się szumu tylko raz dla każdego odrębnego typu warstwy, minimalizując liczbę eksperymentów i całkowity koszt strzałów. Wynikowa lista warstw jest przekazywana do modułu uczenia szumu.

Istnieje kilka kluczowych parametrów kontrolujących sposób uczenia się szumu:

- `num_randomizations`: Liczba losowych obwodów używanych na konfigurację uczenia.

- `shots_per_randomization`: Liczba strzałów wykonywanych na jeden losowy obwód uczący.

- `layer_pair_depths`: Głębokości obwodu (mierzone liczbą par) używane w eksperymentach uczenia.

- `post_selection`: Włącza post-selekcję opartą na krawędziach, wykorzystującą bramki `rx` do zastosowania impulsów po pomiarze.


```python
# Noise learning parameters
num_randomizations_nl = 64
shots_per_randomization_nl = 128

# Match the deepest noise-learning depth to the depth of the circuit being
# mitigated. ``layer_pair_depths`` are measured in layer pairs (a layer + its
# inverse), so the deepest value is half the circuits's two-qubit-layer depth.
# Learning to this depth improves the quality of the mitigation.

depth_2q = isa_circuit.depth(lambda instr: instr.operation.num_qubits == 2)
max_layer_pair_depth = depth_2q // 2

# Use a fixed schedule of learning depths, but drop any that exceed the circuit's
# depth and always cap the deepest value at ``max_layer_pair_depth`` so we never
# learn deeper than the circuit being mitigated
candidate_depths = [1, 2, 4, 8, 12, 16, 24, 32, 40, 48]
layer_pair_depths = sorted(
    {d for d in candidate_depths if d < max_layer_pair_depth}
    | {max_layer_pair_depth}
)

# Find the unique instructions (layers) from the boxed-up circuit
unique_2q_layers_and_meas = find_unique_box_instructions(
    boxed_circuit, normalize_annotations=None, undress_boxes=True
)

# Configure and run the noise learner on the unique layers.
# Options can be passed directly as a dictionary.
noise_learner_options = {
    "num_randomizations": num_randomizations_nl,
    "shots_per_randomization": shots_per_randomization_nl,
    "layer_pair_depths": layer_pair_depths,
    "post_selection": {
        "enable": True,
        "strategy": "edge",
        "x_pulse_type": "rx",
    },
    "environment": {"job_tags": ["TUT_PNA"]},
}

noise_learner = NoiseLearnerV3(backend, noise_learner_options)
noise_learner_job = noise_learner.run(unique_2q_layers_and_meas)
noise_learner_result = noise_learner_job.result()
```

### Powiąż boxy obwodu z wyuczonym szumem {#associate-circuit-boxes-with-learned-noise}

Po uzyskaniu modeli szumu dla każdej unikalnej warstwy dwukubitowej musimy powiązać je z odpowiadającymi adnotacjami `InjectNoise` w zapakowanym obwodzie.

Dyrektywa `InjectNoise` to adnotacja `samplomatic`, która wykorzystuje jednokubitowe ubierania (dressers), aby wstrzykiwać szum do obwodu w kontrolowany i konfigurowalny sposób. Umożliwia to modułowe modelowanie szumu w różnych warstwach.

Każda adnotacja `InjectNoise` zawiera:
- `InjectNoise.ref` - unikalny identyfikator adnotacji. Jest on używany przez obiekt `samplex` do poprawnego przypisania odpowiadającego modelu szumu.
- `InjectNoise.modifier_ref` *(opcjonalnie)* - drugorzędne odniesienie umożliwiające przeskalowanie przypisanego modelu szumu przez czynnik mnożący.

W tym kroku budujemy mapowanie z każdego `InjectNoise.ref` do odpowiadającego mu wyuczonego modelu szumu (`PauliLindbladMap`). To mapowanie zapewnia, że każda warstwa bramek splątujących w obwodzie jest sparowana z odpowiednim modelem szumu, dzięki czemu efekty szumu są dokładnie stosowane podczas próbkowania i kolejnych kroków łagodzenia szumu.

```python
# map inject noise refs to pauli lindblad maps
refs_to_noise_models = {}
for instruction, result in zip(
    unique_2q_layers_and_meas, noise_learner_result, strict=False
):
    if inject_noise_annot := get_annotation(
        instruction.operation, InjectNoise
    ):
        refs_to_noise_models[inject_noise_annot.ref] = (
            result.to_pauli_lindblad_map()
        )
```

### Propaguj obserwablę przez wyuczony anty-szum {#propagate-the-observable-through-the-learned-anti-noise}

Jak omówiono powyżej, odbywa się to w dwóch krokach. Najpierw propagujemy generator anty-szumu do końca obwodu. Następnie propagujemy obserwablę przez ten wyewoluowany generator. Proces ten jest powtarzany dla każdego generatora anty-szumu w obwodzie. W tej implementacji każdy generator w danej warstwie jest propagowany do końca obwodu równolegle. Dodatkowo wykorzystywane jest wieloprocesowe przetwarzanie w Pythonie do równoległego wykonywania zarówno propagacji naprzód anty-szumu, jak i propagacji wstecz obserwabli. Zapobiega to gromadzeniu się wyewoluowanych generatorów w pamięci, a także maksymalizuje wykorzystanie zasobów obliczeniowych.

Podczas uruchamiania PNA zawsze trzeba podać zaszumiony obwód oraz obserwablę. Jeśli twój zaszumiony obwód jest obwodem zapakowanym w boxy z adnotacjami `InjectNoise`, musisz podać mapowanie utworzone w kroku powyżej. Można też przekazać obwód niezapakowany, zawierający instrukcje `PauliLindbladError` z `qiskit-aer`. W takim przypadku nie trzeba podawać `refs_to_noise_models`. Oprócz podstawowych danych wejściowych rozważ również:

- `max_err_terms`: Liczba wyrazów zachowywanych w każdym generatorze anty-szumu podczas propagacji naprzód. Zwiększenie tej wartości zazwyczaj poprawia dokładność, ale to zachowanie nie musi być monotoniczne.

- `max_obs_terms`: Liczba wyrazów zachowywanych w obserwabli łagodzącej szum, $\tilde{O}$, podczas propagacji wstecz przez wyewoluowany anty-szum. Większe wartości zazwyczaj zwiększają dokładność, ale nie ma gwarancji, że dzieje się to monotonicznie.

- `num_processes`: Liczba rdzeni przeznaczonych do procesu. Pamiętaj, że generatory są propagowane naprzód i stosowane do obserwabli równolegle.

- `search_step`: Krok propagacji wstecznej wykorzystuje metodę zachłanną do przybliżonej koniugacji dwóch operatorów w bazie Pauliego. Metodę tę można przyspieszyć, zwiększając `search_step`. Więcej informacji znajdziesz w [dokumentacji `pauli-prop`](https://qiskit.github.io/pauli-prop/).

- `num_to_measure`: Chociaż ta zmienna nie jest danymi wejściowymi dla `generate_noise_mitigating_observable`, używamy jej do kontrolowania, ile wyrazów z $\tilde{O}$ faktycznie chcemy zmierzyć. Tutaj mierzymy tylko 30 najważniejszych wyrazów, które są oryginalnymi wyrazami naszej obserwabli. Wyrazy zostały teraz przeskalowane tak, że ich pomiar ma efekt łagodzenia wyuczonego szumu bramek. Chociaż mierzymy tylko 30 wyrazów z $\tilde{O}$, często nadal warto pozwolić mu urosnąć, ponieważ zwiększa to precyzję czynników skalujących wiodących wyrazów.


```python
# PNA parameters

max_obs_terms = 10_000

obs_tilde_isa = generate_noise_mitigating_observable(

    isa_observable,
    refs_to_noise_models,

    max_obs_terms=max_obs_terms,

p_2_v = {p: v for v, p in enumerate(layout)}
```

### Przekształć bazy pomiarowe do postaci kanonicznej {#transform-the-measurement-bases-to-canonical-form}

Następnie znajdujemy minimalny zestaw baz do zmierzenia, tak aby w pełni pokryć każdy wyraz Pauliego w mierzonej obserwabli (*wiele obserwabli może być mierzonych jednocześnie, jeśli komutują kubit po kubicie*). Ponieważ mierzymy tylko wyrazy w naszej oryginalnej obserwabli, będącej sumą wszystkich pojedynczych Paulich `Z`, potrzebna jest jedna baza: baza all-`Z`.

Oprócz znalezienia zestawu baz pomiarowych Pauliego musimy zmapować te wyrazy Pauliego na postać kanoniczną oczekiwaną przez `Executor`. Więcej informacji o kanonicznym porządkowaniu kubitów znajdziesz w [dokumentacji Samplomatic](https://qiskit.github.io/samplomatic/guides/samplex_io.html#qubit-ordering-convention).

```python
meas_box = boxed_circuit.data[-1]
canonical_qubits = [
    idx
    for idx, qubit in enumerate(boxed_circuit.qubits)
    if qubit in meas_box.qubits
]
c_2_p = {
    c: p for c, p in enumerate(canonical_qubits)
}  # canonical -> physical
p_2_v = {p: v for v, p in enumerate(layout)}  # physical -> virtual
c_2_v = {c: p_2_v[p] for c, p in c_2_p.items()}  # canonical -> virtual
meas_bases, bases_reverser = get_measurement_bases(obs_tilde_virtual)
meas_bases_canonical = [
    np.array([base[c_2_v[c]] for c in range(num_qubits)], dtype=np.uint8)
    for base in meas_bases
]
```

### Krok 3: Wykonaj eksperymenty kwantowe {#step-3-execute-quantum-experiments}

#### Określ sposób próbkowania w `QuantumProgram` {#specify-how-to-sample-in-the-quantumprogram}

Teraz konfigurujemy `QuantumProgram`, który służy jako centralny kontener dla wszystkich obwodów i konfiguracji próbkowania wykonywanych przez `Executor`. Ten obiekt określa, w jaki sposób generowane, grupowane w partie i wykonywane są zrandomizowane instancje obwodów, aby uzyskać wyniki pomiarowe używane w PNA.

`QuantumProgram` może zawierać wiele elementów, z których każdy składa się z obwodu szablonowego i odpowiadającego mu obiektu `samplex` określającego sposób stosowania randomizacji. Ta abstrakcja pozwala `Executor` obsłużyć cały przepływ pracy jako pojedynczy, modułowy program &mdash; od generowania zrandomizowanych obwodów po zbieranie i agregację strzałów.

W tym kroku tworzymy `QuantumProgram`, który uruchamia nasz eksperyment PNA przy użyciu obwodu szablonowego i `samplex` utworzonych wcześniej. Konfiguracja obejmuje następujące elementy:

- `template_circuit`: Obwód zawierający wszystkie bramki niezbędne do zaimplementowania wszystkich pożądanych randomizacji (z randomizacji twirlingu, parametrów itd.).

- `samplex`: Obiekt definiujący rozkład prawdopodobieństwa nad wszystkimi możliwymi randomizacjami obwodu, z których pobierane są próbki.

- `samplex_arguments`: Wiązania niezbędne do pełnego zdefiniowania `samplex`

    - `basis_changes`: Tutaj określamy zestaw baz do zmierzenia, który pokryje wszystkie wyrazy Pauliego w mierzonej obserwabli.

    - `noise_scales.ref`: Ustawiamy skalę każdej warstwy szumu na `0.0`, aby zapobiec wstrzyknięciu dodatkowego szumu do naszych próbek.

    - `pauli_lindblad_maps`: Wymagane, jeśli podano `noise_scales`. To po prostu mapuje warstwy szumu na powiązany model szumu.

- `shape`: Krotka kształtu rozszerzająca niejawny kształt zdefiniowany przez `samplex_arguments`. Nietrywialne osie wprowadzone przez to rozszerzenie wyliczają randomizacje.


```python
# Control the # of shots during execution
shots_per_randomization_exec = 64
num_randomizations_exec = 6144

# Zero out the noise to prevent noise from being injected during execution.
# We only added InjectNoise annotations so PNA could associate the noise
# to layers in the circuit
samplex_inputs = {f"noise_scales.{ref}": 0.0 for ref in refs_to_noise_models}
samplex_inputs |= {"pauli_lindblad_maps": refs_to_noise_models}

# Specify the bases to measure. The samplex exposes one basis-change input per
# ChangeBasis-annotated box; here a single all-Z basis covers every term. We
# look up the basis-change interface name rather than hardcoding an index, since
# the name depends on the circuit's box structure.
bases_broadcastable = np.expand_dims(np.array(meas_bases_canonical), axis=1)
samplex_inputs |= {
    spec.name: bases_broadcastable
    for spec in samplex.inputs().get_specs(r"^basis_changes\.")
}

# Convert samplex_inputs into a dict to pass to QuantumProgram
samplex_arguments = (
    samplex.inputs().make_broadcastable().bind(**samplex_inputs)
)

# Instantiate the QuantumProgram with the specified parameters
program = QuantumProgram(shots=shots_per_randomization_exec)
program.append_samplex_item(
    circuit=template_circuit,
    samplex=samplex,
    samplex_arguments=samplex_arguments,
    shape=(num_randomizations_exec,),
)
```

```python
    (bases_reverser, None, trex_rescale_factors),
    (bases_reverser, mask, None),
    (bases_reverser, mask, trex_rescale_factors),
]

evs = []
for reverser, postsel_mask, factors in args:
    # Compute expvals using post selected results
    res_ps = executor_expectation_values(
        exec_results[0]["meas"],
        reverser,
        meas_basis_axis=0,
        avg_axis=1,
        measurement_flips=exec_results[0]["measurement_flips.meas"],
        pauli_signs=exec_results[0].get("pauli_signs", None),
        postselect_mask=postsel_mask,
        rescale_factors=factors,
    )
    res_ps = np.array(res_ps)
    evs.append(res_ps[:, 0][0])

experiments = ["PNA", "PNA+TREX", "PNA+PS", "PNA+PS+TREX"]
colors = ["#d9d9d9", "#b0b0b0", "#7f7f7f", "#4c4c4c"]
plt.bar(experiments, evs[1:], color=colors)
plt.axhline(y=1, color="green", linestyle="--", linewidth=2, label="Ideal")
plt.axhline(
    y=evs[0], color="red", linestyle="--", linewidth=2, label="Unmitigated"
)
plt.ylabel("Expectation value", fontsize=14)

plt.title(
    r"30q Mirrored Ising, 10 Trotter steps, $\theta_{rx}=\frac{\pi}{8}$",
    fontsize=14,
)
plt.legend(loc="upper left", bbox_to_anchor=(1.05, 1), borderaxespad=0.0)
plt.xticks(rotation=45)
plt.tight_layout()
plt.show()
```

Wyniki pokazują skumulowane korzyści z łączenia różnych technik łagodzenia błędów. Sama metoda PNA już przywraca wartość oczekiwaną blisko idealnego benchmarku, co wskazuje, że propagacja odwrotnych kanałów szumu do obserwabli skutecznie kompensuje błędy bramek dwukubitowych.

- Dodanie ważenia TREX (PNA+TREX) nieznacznie poprawia oszacowanie poprzez korektę niezbalansowania próbkowania w zrandomizowanych obwodach.

- Post-selekcja (PNA+PS) zapewnia bardziej zauważalną poprawę, odfiltrowując niespójne wyniki pomiarowe, które prawdopodobnie wynikają z pozostałych błędów.

Ogólnie porównanie podkreśla, że PNA stanowi solidną podstawę dla estymacji wartości oczekiwanej uwzględniającej szum, podczas gdy TREX i post-selekcja oferują uzupełniające udoskonalenia dla dalszej poprawy dokładności.
